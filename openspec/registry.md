说明：

- **编号列**：`1`、`2`… 为长期维护的规范文档；`—` 表示整类文档不逐篇编号（笔记会持续增长到几十上百篇，逐篇编号会淹没体系且引用重映射成本高）。
- **类目行**（slug 以 `*` 结尾）：代表一整类文档，不对应磁盘上的单个文件，豁免「表与仓库实际一致」的存在性核对。
- `notes/*` 为**前向声明**：目前尚无笔记落地，`management/docs/notes/` 由 `article-note` skill 产出第一篇时创建（后端文档列表递归扫描 `management/docs/`，slug 形如 `notes/<slug>`）。
- 阅读顺序由 frontmatter 的 `order` 字段维护（工具见 `documentation` skill §2.6），与本体编号解耦。

## 登记规则

1. **新增一篇 wiki** → 先在本表登记编号与职责边界，再开单篇 Change `docs-<slug>`，design 审核通过后才动笔。
2. **废弃一篇 wiki** → 先在本表标注/移除该行，再开单篇 Change 处理正文与引用闭合。
3. **职责边界有争议** → 按本表「职责边界」列裁定；**边界本身要改** → 先改本表（体系级动作），再动正文。
4. **改编号 = 全仓事件** → 所有跨文档引用必须级联重映射，改完跑 `python3 scripts/checks/check_doc_refs.py` 做「引用 → 标题闭合」核对（悬空引用必须为 0）。
5. **登记表自身的位置与规则**属体系级约定 → 变更时须走一个体系级 OpenSpec change（日常的增删行不需要）。

## 跨文档引用规范

- 格式：`[《标题》 §X.Y](./<slug>.md)`（本库不使用「N 号」指代，见 §2 编号列仅作登记序号）
- 引用必须闭合：指向的标题必须真实存在；编号重映射后全仓核对（`check_doc_refs.py` 悬空 = 0）
- 正文中引用决策用「名字（Cxx）」，不裸用编号

## 与 OpenSpec 的关系

| 动作 | 是否走 change |
|---|---|
| 在本表增/删/改一行（登记、废弃、调整职责边界） | 否 —— 直接编辑本表 |
| 改本表的位置、结构或登记规则本身 | 是 —— 体系级 change |
| 新增/重写某篇文档正文 | 是 —— 单篇 `docs-<slug>` change，design 先行 |
| 内容级小修（错字 / 数字 / 单段论证 / 链接） | 否 —— 直接改，commit message 说明 |
