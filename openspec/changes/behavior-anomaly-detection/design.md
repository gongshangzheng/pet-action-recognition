# Design: behavior-anomaly-detection

> 继承总管 D3（隐空间/token 架构）、D5/D6；前置 `video-feature-latent`（L1-L3）。

## Decisions

### AN1: token 来源优先零训练

主选 = HDBSCAN 簇 ID 序列（video-feature-latent 已产出，零成本）；VQ token 仅当学习版被触发时可用。**先跑通零训练路线的异常检测，再评估是否需要 VQ。**

### AN2: 异常的形式化定义（调研重点）

待调研后定，候选机制各答一问：
- **低频簇**：「这个行为出现的频率有多罕见？」
- **转移突变**：「行为切换的模式是否反常？」（正常猫 吃→舔→睡 循环；异常可能是长时间静止+频繁饮水之类）
- **分布偏离**：「最近 N 小时的行为构成和长期基线差多少？」（慢性的，如活动量骤降）
- 每种机制对应不同异常类型（急性怪异动作 vs 慢性习惯改变），可能需要组合

### AN3: 人的位置

异常判定 = 系统出候选 + 人工确认。人工标注的簇语义进命名表，反哺 `video-feature-latent` 1.5 的命名表机制——**同一个簇命名体系，两个消费方（动作报告 / 异常报告）**。

## Open Questions

- 异常基线期需要多长？（猫个体差异大，基线按个体建还是按种群建？）
- 医学级异常（疼痛识别）是否超出无监督能力边界、需要引入 VBS 类标注数据？
