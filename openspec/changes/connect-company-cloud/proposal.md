# 自研 RV1126B 摄像头接入公司云

日期：2026-11-07。状态：Apply（用户 2026-11-07 批准，同意本计划提交到公开仓库；
设备端代码另建独立仓库）。

## Why

`项目要求.txt` 中期验收第 2 条要求“完成开发板阶段端侧和云端系统集成”，包括宠物行为
上报、统计、视频流直播、跟拍、设备控制、视频回放和亮点抓取。公司已有 App、Service、
Backend、GB28181 网关和 ZLMediaKit，并于 2026-11-05 发来《摄像头厂商对接材料 V0.2》
（以下称“对接材料”），规定摄像头侧必须实现的身份、配网、直播、实时控制、对讲、
事件上传和 OTA 协议，共 61 项验收。

芯片由我方决定，使用 RV1126B；硬件同学目前已能在板上采集图像。用户 2026-11-07
确认“接入公司云这块”由用户负责。因此，对接材料中“厂商”的固件职责（不含纯硬件）
落在本项目。仓库目前没有任何设备端协议代码。

## What Changes

按对接材料建议的“先身份→配网→GB28181→直播→心跳→Token，再控制/事件/隐私/画质/OTA”，
分六个阶段：

1. **离线算法对齐**：设备签名、配网二维码编解码与校验、对讲音频帧头。先写一份
   Python 参考实现，用对接材料的公开测试向量逐字节比对；它同时作为后续正式实现的
   测试基准。不联网、不需要板子。
2. **PC 设备模拟器接入测试环境**：在 PC 上跑完整设备流程：配网完成 → 取国标配置 →
   SIP 注册 → 用本地 H.264 文件推 PS/RTP 流 → 心跳进入 READY → 连接控制通道 →
   上传事件视频。验收标准：公司 App 能看到直播、能收到事件视频。硬件动作（云台、
   对讲、屏蔽）在 PC 上用桩实现，只记日志。
3. **移植到 RV1126B**：视频源换成板上采集 + 硬件编码；设备身份持久化、开机对时、
   Wi-Fi、摄像头扫码配网。
4. **硬件相关控制**：云台移动/停止/坐标/归位、对讲、物理屏蔽、画质切换。
   依赖硬件同学的驱动。
5. **OTA**：签名包校验、暂存、切换、健康检查、回滚。依赖公司服务端先支持 RV1126B。
6. **接入端侧算法**：宠物事件触发、事件视频上传；结构化结果（行为时间轴、亮点指标，
   见 `extract-highlight-features`）的上报通道等公司定义。

本 change 只是总计划。各阶段开工前按需要拆子 change 或补 design，逐阶段批准。

## 中期最小目标

直播（App 看到板子画面）、心跳在线、App 控制云台转动和停止、设备上传事件视频并在
App 回放。扫码配网可先用手工写入身份替代；对讲、OTA、画质、隐私放到中期之后。

## Non-goals

- 不改公司的 App、Service、Backend、网关（属公司职责）；发现接口问题只记录并反馈。
- 不做纯硬件：板级驱动、电机、红外、麦克风/喇叭电路由硬件同学负责，本 change 只定义
  对硬件层的接口需求。
- 不做量产产线工具与工厂放行流程，除非公司要求（测试阶段用公司发放的测试身份）。
- 不在对接材料“产品待定”范围内的功能（SD 卡检索、远程抓图、灯控、蜂鸣、离线告警）。
- 阶段 2 所需的测试身份（R2、R3）到位前，不连接公司任何环境。

## 需用户或硬件同学确认

- 板上系统：RV1126B SDK 的 Buildroot 还是 Debian，是否有 Python 3，工具链版本。
- 云台机构：步进电机步数、零位、限位、是否带物理屏蔽（对接材料 B02、P07、P08）。
- 是否有麦克风和喇叭（对讲、直播音频）。

## 验收

- 阶段 1：参考实现对全部公开测试向量（签名、二维码、对讲帧头）逐字节一致，
  且覆盖中文/特殊字符 SSID、CRC 错误等负例。
- 阶段 2：在公司测试环境，PC 模拟器完成 READY，公司 App 首帧可见、控制指令到达并
  正确回包、事件视频入库可回放；对应 T009–T014、T017、T019–T026、T028、T031–T033、
  T049–T051 的 PC 侧部分有记录。
- 阶段 3 及以后：按 `tasks.md` 中的 T 编号逐项记录真机证据，不以“接口返回成功”代替
  画面首帧、机械到位或真实声音。
