# Design：自研 RV1126B 摄像头接入公司云

协议细节以本地保存的对接材料为准，这里只记录我方的实现决策。章节号 §x 指
《01-摄像头厂商适配文档》，T0xx 指《02-对接与验收清单》，B/P 编号指《03-联调参数与待确认项》。

## D1 代码与凭据的存放

- 设备端实现代码放私有仓库（R7 未定前只在本地，不推送）。本公开仓库最多保留本计划。
- 真实凭据（设备密钥、Token、SIP 密码、Wi-Fi 密码、工厂凭据）只存在：
  PC 上 gitignore 的本地配置文件、板上受保护分区。不写进代码、日志、截图和计划文档。
- 对接材料的公开测试向量是合成值，可用于单元测试，但仍放私有仓库（材料整体受保密约定）。
- 日志结构化并脱敏（§14）：记录阶段、请求/事件/任务 ID、错误码、耗时、重试次数；
  不记录认证头、密钥、Wi-Fi 密码、视频私密 URL。

## D2 进程与模块划分

设备端一个主进程（同一 deviceId 只允许一个实例，避免 §11.1 的连接互相替换），模块：

| 模块 | 职责 | PC 实现 | 板上实现 |
|---|---|---|---|
| 身份与凭据存储 | deviceId/密钥/Token 的原子读写，复位与 OTA 不擦出厂身份（§5.1） | 本地文件 | 受保护分区 |
| 签名与编码 | HMAC 派生与签名、W4 二维码解码与 CRC8、对讲帧头（§6、§7.2、§12.1） | 共用 | 共用 |
| 设备状态机 | 配网 BOUND → READY、Token 刷新、心跳、错误分类与退避（§7–§9、§14） | 共用 | 共用 |
| GB28181 | SIP 注册/保活/目录/设备信息、INVITE/SDP、PS 封装、RTP（UDP/TCP 按 SDP）（§10） | 共用 | 共用 |
| 媒体源 | 提供 H.264（及可选音频）帧 | 本地文件循环读取 | 板上采集 + 硬件编码 |
| 实时控制 | 设备控制通道：握手、能力上报、云台/跟踪/隐私/画质/对讲消息（§11、§12） | 共用 | 共用 |
| 硬件抽象 | 云台、屏蔽、喇叭/麦克风、灯/语音提示 | 桩：只记日志、返回模拟坐标 | 调用硬件同学的驱动 |
| 事件上传 | 事件片段生成、本地有界队列、去重重试（§9.3） | 本地文件 | 板上存储 |
| OTA | 拉任务、验签、暂存、切换、回滚（§13） | 只做验签与清单校验 | 完整 |
| 算法接口 | 接收端侧算法的宠物事件与结构化结果 | 读离线结果 | 板上推理 |

模块之间通过清晰的接口隔离，使 PC 模拟器和板上程序共用除“媒体源”和“硬件抽象”
以外的全部代码。

## D3 实现语言：C++17 自研（2026-11-07 定）

- 公司不提供现有固件源码（R1 预期拿不到，用户 2026-11-07 决定），设备端自研。
- 语言选 C++17：直接调用瑞芯微 C 接口（采集、硬件编码、音频），交叉编译 aarch64，
  不引入额外运行时。
- 分层：
  - 核心库只用标准库、不做网络 I/O、不依赖操作系统，包含签名、配网二维码、对讲帧、
    H.264 访问单元切分、MPEG-2 PS 封装、RTP 打包、SIP 消息与 Digest、SDP、MANSCDP。
    在 PC 上单元测试，交叉编译后可在板上直接跑同一套测试。
  - 网络层（HTTPS/TLS、WSS、SIP 传输、状态机）和硬件层在核心库之上，引入第三方库前
    先核查许可证（GPL 类库不直接链接进产品固件）。
- 开发与测试环境：PC 上用 WSL2（Linux，内存上限 4GB）开发网络层与设备模拟器；
  最终在 RV1126B 板上用板厂 SDK 工具链验证（2026-11-07 定）。
- 阶段 1 的 Python 参考实现保留，作为 C++ 的差分测试基准：随机与损坏输入下两边
  输出和错误码必须一致。

## D4 测试环境与联调顺序

- 只连公司指定的测试环境与测试设备身份；不使用正式环境，不借用生产用户设备。
- 设备侧必须校验 TLS 证书和主机名，不为联调关闭校验（§4.2）。
- 冷启动先对时，再发第一个签名请求（§6.3、B06）。
- 先 PC 后板子：PC 模拟器打通整条链路后，板上只替换媒体源与硬件抽象，
  出问题时可回到 PC 区分是协议问题还是板级问题。

## D5 媒体基线

- 按对接材料建议，先用 PS/RTP + H.264 建立兼容基线，H.265 之后评估（§10.2）。
- RTP 用 UDP 还是 TCP、主动还是被动，一律按网关 SDP 协商结果，不写死；
  TCP 分帧方式以抓包验收（T027）。
- 码率、帧率、GOP、分辨率、音频编码按 B05 冻结后的值配置；冻结前 PC 模拟器用
  测试视频的原参数，并在报告中注明。

## D6 能力上报

控制通道握手时的能力列表只对“已实现且通过验收”的项报 `true`（§11.1）。
PC 模拟器阶段云台为桩实现，可在测试环境上报云台能力用于联调消息格式，但验收记录中
必须注明“桩实现，未验证机械到位”。

## D7 事件视频与算法结果

- 事件视频走现有上传接口：片段时长与大小按 §9.3 上限切分，事件 ID 在重试中保持
  不变，同 ID 不覆写不同内容；本地队列有上限、失败退避、过期清理（T051）。
- 触发条件、预录/后录、冷却时间按 P05 与产品冻结；端侧宠物检测/行为识别可作为
  “宠物事件”的触发来源。冻结前的默认值参考公司现有服务端检测脚本的做法
  （帧差运动初筛 → 检测模型确认宠物 → 触发冷却 → 单段时长上限），具体参数记录在
  私有设备仓库，不写入本公开计划；最终以 P05 冻结值为准。
- 结构化结果（`pet.highlight.v1` 等）的上报通道待公司定义（R6）；定义前只写本地
  outbox，不自行扩展公司接口字段。
- 云端如何使用端侧结构化结果**不预设**。向公司提 R6 时只列可选方式供公司决定，例如：
  作为云端分析（含可能的大模型分析）的输入、作为云端分析前的预筛选、或仅随事件入库
  供统计与 App 展示。端侧载荷保持与具体云端分析方式无关。
- 隐私录制策略（P09）：见 D13（用户 2026-11-07 批准提前做）。

## D8 解绑、换绑与安全

- 收到解绑/撤权类错误时停止旧授权的上传、控制和 SIP 会话，清空旧归属队列（§14、T052、T053）。
- 云台动作按“会话 + 操作 ID”维护所有权；断连或本地看门狗超时安全停机，
  不依赖网络一定送达停止指令（§11.3）。

## D9 OTA

公司服务端目前只接受 RV1106/RV1103B 平台标识，RV1126B 不能冒充旧平台（§13.1）。
阶段 5 等 R5；在此之前只实现验签与清单校验，作为离线单元测试。

## D10 验收记录

每项验收按 `02-对接与验收清单` 格式记录：固件/模拟器版本、环境、步骤、预期、实际、
脱敏证据（日志、抓包、App 截图）。记录存私有仓库；公开仓库只记阶段完成情况。

## D12 网络层与本地设备模拟器（用户 2026-11-07 批准）

公司测试环境参数（R2–R4）到位前，先在本地把网络层和整条设备流程写完，
对着我方按对接材料写的本地模拟服务跑通；拿到参数后只改配置去连公司测试环境。

**依赖（均非 GPL）**

| 库 | 用途 | 许可证 | 板上来源 |
|---|---|---|---|
| OpenSSL 3 | TLS、证书与主机名校验 | Apache-2.0 | 板厂 SDK 自带；没有则静态编入 |
| libcurl | HTTPS 请求、multipart 上传；控制通道的 TLS 连接 | curl（MIT 类） | 同上 |
| nlohmann/json 3.11.3 | JSON 解析与生成 | MIT | 单头文件入私有仓库 `third_party/` |

- Ubuntu 与常见发行版的 libcurl 没有开启 WebSocket 支持，所以 WebSocket 帧协议
  （握手、掩码、分片、ping/pong、关闭）自己写在核心库里，作为纯函数单元测试；
  TLS 连接借 libcurl 的“只连接”模式建立，证书校验配置与 HTTPS 共用一套。
- 不引入 Boost/asio 等大型框架。

**结构**

- 网络层只面向 Linux（POSIX socket），Windows 上只编核心库，CMake 选项控制。
- 线程：状态机一个线程，控制通道、SIP、每路媒体会话各一个线程（`poll` 驱动），
  模块之间用线程安全队列传事件。HTTPS 请求在调用方线程同步执行，带超时。
- 基础设施：配置与凭据从 gitignore 的本地文件读取；Token 等运行状态写临时文件后
  原子替换；日志统一经脱敏函数输出；文件锁保证同一设备只跑一个实例。
- 设备模拟器 `petcam_sim`：媒体源为本地 H.264 文件按帧率循环；云台为虚拟坐标
  （带会话归属与本地安全停止）；对讲音频写成 WAV 文件代替喇叭；配网二维码以文本输入。
  能力上报只报模拟器真实实现的部分，并在日志中标明“模拟”。

**本地模拟服务（只用于测试，不进产品）**

- Python 标准库实现，按对接材料逐条写：HTTPS 接口（自签 CA，设备端照常校验证书）、
  控制通道 WSS、SIP（UDP/TCP，含 Digest 挑战、目录/设备信息查询、点播 INVITE/BYE）、
  RTP 接收落盘后交给 ffprobe 检查。
- 校验签名、时间戳窗口与 nonce 去重、Token 阶段（配网 Token / 正式 Token）、
  READY 转换、事件上传的 eventId 幂等与 SHA 冲突，并能注入常见错误码。
- 本地跑通只说明“设备实现与我方对材料的理解一致”；验收仍以公司测试环境按
  阶段 2 各项（T0xx）为准，两者在报告中分开写。

## D13 人形隐私录制策略（用户 2026-11-07 批准）

产品语义：App 打开“画面有人时不录制”开关后，画面里有人的事件视频不上传到云端。
按对接材料，这个开关只管录制与上传，**不管直播**（App 实时观看照常）。

**策略同步**

- 设备在 READY 后、控制通道每次重连后、收到 `privacy_recording_policy_refresh` 时拉取
  录制隐私偏好接口；拉到后先在本地生效，再回 `privacy_recording_policy_status`
  （applied，带 blockHumanRecording 与 serverTime）；拉取失败回 failed 和错误码，不假报 applied。
- 策略缓存到运行状态目录（带拉取时间），重启后沿用。解绑时清除。
- 拉取失败：以前拉到过就沿用缓存；从未拉到过按“拦截”处理（保守）。
- 能力 `privacyRecordingPolicy` 只有在上述同步与拦截都实现并测试通过后才报 true。

**人形检测**

- 检测接口与具体实现分开：输入事件视频，输出逐帧“是否有人”及最高置信度。
- 板上：复用认猫用的 YOLO（同一次推理含“人”类别），在 NPU 上运行；随板级移植
  （1.9，需 SDK）接入，届时用真实视频测漏检率。
- PC 模拟器：没有 NPU，用与视频同名的检测结果文件代替（测试片段手工标注）；
  找不到检测结果时按“有人”处理（保守）。

**拦截规则（我方暂定，待公司/产品冻结 P09）**

- 开关打开时：事件视频（含预录部分）的任意一帧以较低阈值检出人，整段不上传。
  宁可多拦有猫的片段，不漏传有人的片段；阈值可配置。
- 拦截点有两处：入上传队列前检查一次；每次发送前按当前策略再检查一次
  （开关在排队期间被打开，排队中的有人片段也不再发送）。
- 被拦的片段在本地删除，只记一条不含画面的日志（eventId、原因）。
- 只覆盖云端上传；本地 SD 卡录像暂未实现，是否覆盖待 P09 确认。
- 检测不可能 100% 准确（夜间红外、只露手脚、远处人形），交付前须用真实视频评估并在
  报告中写明漏检率，不宣称“绝不上传有人画面”。

**事件上传队列（2L.9，与本项一起做）**

- 本地有界队列（条数与总字节数上限，超限丢最旧并记日志），队列记录持久化，重启续传。
- 每段视频一个 eventId，所有重试不变；上传前算整文件 SHA256；失败退避后整文件重试；
  服务端回 duplicate 视为成功；SHA 冲突不重试并记日志。
- 每条记录带入队时的 bindingId；解绑/撤权后丢弃旧 bindingId 的全部记录，不上传到新账号。

## D14 样机身份与待配网状态（2026-11-12，先做 PC 模拟器）

公司为两台样机（真板、PC 模拟器各一台，同一型号）按硬件指纹手动登记并发放了身份，
不走设备端的工厂领取流程。公司对厂商的要求（原文与具体路径、地址只记在私有设备仓库）：

1. 身份写入公司指定路径的身份文件，字段为设备 ID、密钥、密钥版本、型号，权限 0600，
   两台设备不能互换。
2. 固件读到的 CPU 序列号能生成登记时的硬件指纹（`cpu-<序列号>`），重启、恢复出厂后不变。
3. 样机准备为待配网：本地工厂放行标志为已放行，Wi-Fi 进入配网模式，清理工厂 Wi-Fi 凭据
   和调试代理，保留身份文件。公司没有要求清理 ssh/adb，开发阶段保留（用户 2026-11-12 定）。
4. 只连公司测试环境（test2），不连正式环境。

本批只改设备代码并在 PC 模拟器上落实 1、2、4 和 3 中的“放行标志 / 待配网”；
板上的 Wi-Fi 配网模式、清理工厂凭据由硬件组做，随新交接包说明（任务 3.0）。

**联调前提：测试版 App**

配网的配网码由 App 向服务端创建会话后得到，设备端无法自己生成，所以 2S.9 需要公司提供
连 test2 的测试版 App（安卓安装包或 iOS 测试分发）和测试账号（用户本人手机号）。
App 到位前只能做到“启动后等待扫码”；可选地在征得公司同意后做一次签名冒烟：用假配网码
调用配网完成接口，返回“配网码无效”而不是“签名错误”，即可确认地址、证书、签名路径和身份都对。

**身份文件**

- 配置新增 `identityFile`（板上指向公司指定路径）。读取四个字段；字段缺失、密钥不是
  32 字节、文件对组或其他用户有任何权限位时拒绝启动，并报明确错误。
- 原来在配置里直接写 `deviceId`/`deviceSecret` 的方式只留给本地模拟服务的测试；
  两种方式同时出现时拒绝启动。连公司环境的配置只用身份文件。
- 型号取自身份文件，用于国标设备信息查询的回复，替换现在写死的模拟值。
- 身份文件不在运行状态目录里：解绑、重新配网、清除授权都只清运行状态目录，不动身份文件。

**硬件指纹**

- 核心库加纯函数：从 cpuinfo 文本取 `Serial` 行，生成 `cpu-<小写序列号>`；没有该行或格式不对时报错。
- 读取路径可配置（`cpuinfoPath`，默认系统路径）。PC 模拟器指向一个只含 Serial 行的
  本地文件，序列号是我方为模拟器生成并已在公司登记的值。
- 指纹不是秘密：启动时写入日志；另加自检命令，打印设备 ID、型号、指纹、身份文件权限、
  放行标志状态（不打印密钥），给硬件组在板上核对“重启、恢复出厂后不变”。
- 目前设备端不向服务端上报指纹（只在工厂领取接口里用），本批不加运行时比对。

**放行标志**

- 配置新增 `factoryReleasedFlag`（文件路径，存在即已放行），同样放在运行状态目录之外，
  解绑与恢复出厂不清除。
- 未放行：不连云、不进配网，记日志 `FACTORY_NOT_RELEASED` 后以单独的退出码退出。
  设备端工厂命令轮询与放行回执（领取 identify / factory_release）本批不做，
  等公司走正常产线流程时再做。
- 已放行且没有授权：进入待配网（模拟器即等待 `--qr-file` 里的配网二维码文本）。

**连测试环境与扫码辅助**

- 测试环境配置放 gitignore 的本地文件，用系统 CA 校验证书（不配 `caFile`）；
  仓库里不出现正式环境地址。
- PC 上身份文件、指纹文件、放行标志放在 WSL 自己的文件系统里（Windows 盘挂载在 WSL 里
  不能可靠设置 0600）。
- 机身码：二维码内容即设备 ID（公司说明）；用 `qrencode` 生成图片给 App 扫。
- 联网二维码：App 显示后截图，用 `zbarimg` 解出 W4 文本（全为 ASCII）写入 `--qr-file`
  的文件，去掉末尾换行。两个工具都是 WSL 里的 apt 包，只用于测试，不进产品。
