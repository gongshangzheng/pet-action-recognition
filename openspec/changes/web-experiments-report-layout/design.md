## Context

动机见 [proposal.md](proposal.md)。现状要点：

- `ExperimentsPage.vue` 用两张上下堆叠的 `n-card`：第一张的 header 放标题与三个 `n-select` + 复选框，卡体放列表；第二张 `detail-card` 内是自定义 `detail-header` 与正文。
- 正文 `.detail-article { max-width: 76ch }`，指标表与案例图被压在窄栏内，宽表格挤压明显。
- `DocPage.vue` 已有成熟模式：`aside.doc-sidebar`（可折叠）+ 主区域正文，窄屏转抽屉。
- 全局 `.page-container` 只有 `padding: 20px`，没有整体宽度上限，所以限制来自 `detail-article` 自身。

约束：不改后端与报告生成器；沿用 Naive UI 组件；`design-principles` 要求列表分页/懒加载与 keep-alive 规则继续满足。

## Goals / Non-Goals

**Goals**

- 与文档页一致的阅读结构：左栏选报告，右栏读报告。
- 数据密度与可读性兼顾：段落窄、表格宽。
- 章节导航可见，长报告可直接跳转。

**Non-Goals**

- 不重做整站视觉主题，不改颜色与字体变量。
- 不改报告内容结构（生成器的章节顺序不变）。
- 不引入新的图表库。

## Decisions

### 4.1 直接复用文档页的侧栏模式

> **方案：** 抽取 `DocPage` 的侧栏尺寸、折叠按钮、active 态样式，作为报告页侧栏；不在报告页另造一套。

**理由：** 两个页面职责同构（列表选一项、右侧读内容），复用能保证间距、折叠行为和键盘可达性一致。

**替代：** 保留卡片式列表并只修宽度。被否决：用户明确认为「内容该放边栏」。

### 4.2 宽度策略：段落窄、数据宽

> **方案：** 正文容器不设整体上限；仅在视口 ≥1200px 时把 `p`、`li`、`blockquote` 限制在约 78ch，其余宽度段落铺满；`table`、`pre`、案例图始终占满正文区。

**理由：** 76ch 直接作用在整篇文章上，等于让表格与图也跟着窄；只对段落限宽能同时满足阅读与数据密度。

**替代：** 完全取消限制。被否决：超宽屏上一行文字会过长，阅读体验下降。

### 4.3 标题层级与页面结构

> **方案：** 全页只保留一个 `h1`（报告标题）；侧栏标题用 `h2` 或 `role="heading"`；正文内章节保持 `h2/h3`，与 TOC 对应。

**理由：** 当前 `h1` 是视觉隐藏的「实验报告」，真正的报告标题是 `h2`，标题层级与语义不符。

### 4.4 章节导航

> **方案：** 从报告的固定章节生成目录，桌面端常驻在正文左侧或右侧（与侧栏区分），当前章节高亮；<900px 折叠为正文顶部的下拉或折叠块。

**理由：** 报告较长，章节固定，跳转比滚动高效。

**替代：** 不做 TOC，只靠标题。被否决：用户已指出长报告难读。

### 4.5 响应式断点沿用 900px

> **方案：** ≥900px 侧栏常驻；<900px 侧栏与 TOC 都折叠为抽屉/折叠块，正文单列占满。

**理由：** 与 `design-principles` 的既有断点一致，避免第三套响应式规则。

## Risks / Trade-offs

- [侧栏在窄屏挤压正文] → 断点以下转抽屉，正文单列。
- [复用 DocPage 样式导致耦合] → 只复用已存在的 class 与变量，不改 DocPage 结构；若后续拆分样式，另开 change。
- [表格放宽后出现横向溢出] → 表格容器加 `overflow-x: auto`，不在正文层面横向滚动。
- [TOC 与固定章节名强耦合] → TOC 由解析出的章节列表生成，章节缺失时不显示空项。

## Migration Plan

1. 先改布局与宽度，保留现有数据与交互（筛选、选中、URL query 同步）。
2. 浏览器核对：1440px 桌面、1024px、768px 三档；确认表格不溢出、TOC 可跳转、侧栏折叠正常。
3. 回退：单文件改动，`git revert` 即可。

## Open Questions

- 章节导航放正文左侧还是右侧？左侧与报告列表并列会形成两列导航，右侧更接近阅读工具的常见做法，需在浏览器里对比后定。
- 窄屏下 TOC 用折叠块还是抽屉，取决于实际滚动长度。
