# 设计与取值依据

## 文字颜色阶梯

对比度按 WCAG 2.1 计算，验收底色取三档实际出现过的背景：`#ffffff`（card）/ `#f3f4f6`（elevated）/ `#f5f5f7`（page bg）；深色取 `#1f1f23` / `#27272a` / `#18181b`。

| 令牌 | 浅色 | 白底 | elevated | 深色 | card | elevated |
|---|---|---|---|---|---|---|
| `--color-text` | #1f2937 | 12.6 | 11.4 | #e4e4e7 | 12.9 | 11.7 |
| `--color-text-secondary` | #4b5563（原 #6b7280） | 7.56 | 6.87 | #b4b4bd（原 #a1a1aa） | 7.98 | 7.24 |
| `--color-text-dim` | #5f6672（原 #9ca3af） | 5.78 | 5.26 | #94949e（原 #71717a） | 5.47 | 4.96 |

结论：dim 在两档底色、两种模式下都 ≥4.5，且三级阶梯（12.6 / 7.56 / 5.78）仍可分辨，不会塌成同一级。

## Naive 组件覆盖

`themeOverrides.common` 增加 `textColor3`（空态描述、次要标签）与 `placeholderColor`（输入/选择占位符），取 dim 值；不覆盖 `textColor2`（Naive 用于常规正文，当前值达标）。深色走 `darkTheme` 时同一 override 会与 Naive 深色默认值合并，因此两档都显式给值。

## 键盘可达

新指令 `v-clickable`：`mounted` 里设 `role="button"`、补 `tabindex="0"`，监听 `keydown` 的 Enter / Space 触发 `el.click()`，`unmounted` 解绑。选择指令而非包装组件，是因为 5 处卡片的 DOM 结构与样式各异，包一层会破坏既有布局。

文档侧栏的 `<a @click.prevent>` 改为 `href` + `@click.prevent`，让它天然进入 tab 序列并带上浏览器默认的「链接」语义；不再加 role。

## 页面标题结构

- 内容区是 `<main id="main">`，MainLayout 顶部有 `跳到主内容` 链接（`position: fixed` 的 `:focus-visible` 才显形）。
- 每页一个 `h1`：默认渲染 `<h1 class="visually-hidden">{{ route.meta.title }}</h1>`。DocPage / ReportPage / MeetingList 正文已有可见 `h1`，这三条路由标 `meta.ownHeading = true`，不再渲染隐藏 h1，避免一页两个 h1。
- 页内当作「页面标题」用的 `h3`/`h4`（论文列表、评测结果、团队成员名、模型名）降为 `h2`，保证 h1 → h2 不跳级；`n-card title` 生成的 div 不动（无标题语义）。

## 响应式断点

沿用 Naive `responsive="screen"` 的写法，阈值取 640 / 900 / 1200：

- Home 模块卡：`1 640:2 900:3`；下半区两卡：`1 900:2`。
- TaskBoard 三列看板：`1 900:3`（看板本身就是三列语义，单列纵向堆叠即可）。
- TeamList / ModelManage：`1 640:2 900:3`。
- SpeedRun：`1 480:2 900:3 1200:4`（原 `3 600:2 900:3 1200:4` 在 <600 是 3 列，顺序反了）。

顶栏：`≤720px` 隐藏 `.header-date`；`.header-left` 允许收缩（`min-width: 0`）并给面包屑 `ellipsis`；`.header-right` 固定不收缩；`≤720px` 内边距 24 → 12。

## 优先级标签

原 10px + `#d97706 on #f3eada = 2.67`。改为 11px，并拆明暗两档：

- 浅色：高 `#b91c1c`(5.07) / 中 `#92400e`(5.94) / 低 `#475569`(6.12)
- 深色：高 `#f87171`(4.80) / 中 `#fbbf24`(7.17) / 低 `#cbd5e1`(9.02)

底色维持现有的 12%/10% 透明叠加，靠 CSS 变量在 `[data-theme='dark']` 下切换文字色。

## 风险与回滚

- 所有改动集中在展示层，无数据/接口变更；回滚粒度是文件级。
- 文字色变深会让部分页面的次要信息更抢眼，属于可接受的可读性代价，不做额外的层级补偿。

## 验证结果（修复后实测）

工具：impeccable detector（ego lite 渲染扫描，18 条路由 × 1280×800 / 390×844）+ 自建对比度脚本（逐文本节点取计算色与有效底色）+ 几何/结构脚本（1440 / 768 / 390 / 320 四档）。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| detector 阻塞项（18 路由 × 2 视口） | 118 | 0 |
| detector 建议项（低对比度） | 48 | 0 |
| 自建脚本对比度失败（15 路由 × 明暗两档） | 127 | 0 |
| 九种强调色 × 明暗两档对比度失败 | 未测 | 0 |
| 页面 `h1` 数量 ≠ 1 的路由 | 16/19 | 0/19 |
| 390/320 下横向溢出或控件被裁切 | 5 类页面 | 0（训练结果表格内部横滚属预期） |
| 键盘不可达的可点卡片/链接 | 6 处 | 0 处（Tab + Enter 实测可激活） |
| `transition: all` | 16 | 0 |
| 缺 alt 的 `<img>` | 6 | 0 |

键盘实测：首页首次 Tab 命中「跳到主内容」，Enter 后焦点进入 `<main>`；数据集卡片 Tab 可达、Enter 进入目录；文档侧栏链接带真实 `href`。

遗留（不在本次范围）：
- 训练结果 / 评测输出页的宽表在 390px 下需要表内横向滚动（表格本身可滚，不裁切内容）。
- 纸质模块 `PaperList` / `PaperDetail` 仍是独立的 slate 调色板，深色模式下呈浅色岛屿（视觉方向问题，单独立项）。
