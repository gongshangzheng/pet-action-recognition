# Design: 动作分割与闭集行为识别

> 总管：`pet-system-integration`。动机与范围见 [`proposal.md`](./proposal.md)，本文只写怎么做。
> 领域背景（各模型族的输入输出契约、采样器语义）见 [`papers/docs/action-recognition-models.md`](../../../papers/docs/action-recognition-models.md)；组件全景见 [《系统架构》](../../../management/docs/architecture.md)「行为识别与动作分割」一节。

## Context

**已有的东西（可复用）**

- 七类闭集区间协议已定并进主 spec（`openspec/specs/cat-action-training`）：`activity`、`eating`、`drinking`、`prolonged_stationary`、`grooming`、`toileting`、`abnormal`（异常四小类合并）。计划期审计数字：2,710 条候选区间，`activity` 1,629 / `eating` 341 / `prolonged_stationary` 335 / `drinking` 164 / `grooming` 85 / `abnormal` 125 / `toileting` 31；按拍摄日隔离的自然分布 train 1,664 / val 604 / test 442，其中 `toileting` 为 20/4/7。**最终数字以服务器审计产物为准。**
- 模型选择规则已定：验证集 macro-F1 为主、分类别召回为辅；测试集只做最终报告。
- vendored mmaction2 与 `configs/pet_*.py`：`SampleFrames(16, interval=4)` ⇒ 单窗口跨度 64 帧 ≈ 4.3 s @15fps；`results/training/`、`results/speedrun/` 有推理与标注设施。

**缺口（本 change 要补的三件）**

1. 窗口怎么铺满长视频（长度、步长、重叠、多尺度）；
2. 逐窗结果怎么变成段（合并、最小段长、低置信、无猫）；
3. 边界与端到端怎么验收（本项目**没有边界标注、没有逐帧标注**，只有区间级标注）。

**硬约束**

- 不得消费 `λ` 序列或行为簇表征（对应 change 已搁置）；
- GPU 为共享资源，训练/推理在远程执行且前先 `nvidia-smi`；
- 存在性检测的 FPR 目前只是宽区间估计（负样本仅 283，见 `presence-gate-model/evidence.md`），不能假定门控已可靠。

## Goals / Non-Goals

**Goals:**

- 把未裁剪长视频转成段列表（闭集类别 + 起止时间 + 置信信息），时间轴无重叠无缺口。
- 每段的边界**可追溯到支撑它的窗口结果**，聚合规则可审计、可复现。
- 在只有区间级标注的条件下，给出边界质量的度量方式并承认其上限。
- 把 TAD / TAS 的候选位置留出登记处，注明其标注缺口，不预设结论。

**Non-Goals:**

- 不训练新编码器，不做无监督行为发现或聚类，不恢复 `λ` 路线。
- 不做有监督 TAD / TAS 训练（缺边界与逐帧标注）。
- 不在本 change 判定「有没有猫」——那是存在性检测的职责。
- 不做多猫身份关联、不做实时因果硬约束。
- 不定观测指标（亮度、面积占比等），也不定端云上报字段的最终形态。

## Decisions

### D1: 主线是「分类后聚合」

```
视频或跟随画面 → 连续窗口 → 闭集窗口分类 → 逐窗类别与置信 → 时间聚合 → 段（类别 + 起止时间）
```

**理由**：① 现有分类模型、config、已训权重可直接复用，无需新标注；② 业界主流就是这条链路（门控 → 定长窗口分类 → 时序聚合，Google `LabelDetectionMode`、AWS `SegmentType`、Frigate 的 review item 属同一形态，2026-09-17 联网核实）；③ 与架构文档当前写法一致。

**替代方案及不采用的当下的原因**：先分割后分类、TAD、有监督 TAS、无监督 TAS——前两者缺边界标注，后者属已搁置研究。这些**不删除**，登记在 D7 的候选表里，由用户在调研结论出来后裁定。

### D2: 段边界由聚合规则产生，且其精度必须被测量

**决策**：每段 MUST 能追溯到支撑它的窗口集合；边界 MUST 由聚合规则产生，不得人工指定成段。边界质量作为独立指标报告。

**理由**：窗口步长决定了边界的系统误差下界（例如步长 2 s 就不可能比 ±1 s 更好），把它写成"精度待验收"而不是"假设够用"，才能避免把分类成绩误当分段成绩。

**边界度量口径是候选，不是结论**：可选 ±容差命中率、段级 IoU 阈值命中、段序列编辑距离。三者对"过分割"和"欠分割"的惩罚方式不同，具体用哪个、容差多少**待与用户审定**。

### D3: 窗口口径是**待实测参数**，不在计划里冻结

**候选**：单窗口 16 帧（≈1.1 s）、32 帧（≈2.1 s）、64 帧跨度（≈4.3 s，现 config）；步长取窗口的 1/2 或 1/4；重叠窗口的归属按"置信加权"或"中心帧归属"。

**理由**：类别时长跨三个数量级（`eating` 数十秒 ↔ `prolonged_stationary` 数十分钟 ↔ 短促动作数秒），单一时窗无法同时满足时间分辨率与长动作覆盖（`papers/docs/action-recognition-models.md` §2.2 的采样器论证）。因此窗口长度与步长由任务 3.3 实测对照确定，**不在此处写死数值**。

**多尺度分层**（短窗 + 长窗）是候选而非决定：它能缓解尺度矛盾，代价是推理成本与融合规则复杂度，须先证明单尺度不足。

### D4: 无猫区间由外部给定，静止行为用已有类别承担

- **无猫区间**：聚合 MUST 接受外部「无猫」标记（来自存在性检测），在该区间内 MUST NOT 输出宠物行为段，也 MUST NOT 自行判定在场。
- **静止**：旧方案的 `T_pause` 二义参数（同一静止信号既是停顿又是行为）**取消**。长时间静止归已有类别 `prolonged_stationary`；短于窗口的静止自然并入相邻段。是否需要「累计时长阈值」把长静止从多次短窗口预测中聚合出来，由任务 5.3 定。

### D5: 不强制因果，允许有限后视

离线与实时共用同一判别内核；允许等待少量后续窗口再定段，也允许对已出段做修订。EOF 附近的段处理（末尾不足一窗）、修订窗口大小、出段延迟都是待定项，由任务 5.4 的离线 / 有限后视对照确定。**不采用**严格因果约束（会牺牲边界质量而当前无相应收益）。

### D6: 三口径分开报告，口径审定前不记达标

| 口径 | 统计单位（候选） | 现状 |
|---|---|---|
| 片段分类 | 已裁剪区间 / 窗口 | 有协议，指标须复现核对 |
| 段边界 | 段与真值段的匹配 | 无协议 |
| 端到端 | 一次完整时段运行 | 无协议 |

MUST NOT 用片段分类成绩代表端到端结果，也 MUST NOT 用门控召回补充端到端召回。统计单位与汇总方式、分母（含不含无猫时段、含不含不可判区间）、时间匹配规则与容差，**由用户审定后冻结**（任务 6.2）。

### D7: 候选方案登记（只登记，不实施）

| 候选 | 输入 → 输出 | 缺什么 | 状态 |
|---|---|---|---|
| 分类后聚合（本 change 主线） | 窗口 → 段 | 无需新标注；边界精度受步长限制 | 采用 |
| TAD（ActionFormer / TriDet / TadTR） | 长视频 → 变长 proposal | **边界标注** | 调研 |
| 有监督 TAS（MS-TCN / ASFormer / DiffAct） | 长视频 → 逐帧标签 | **逐帧标注** | 调研 |
| 本仓 vendored TAL config（`configs/localization/{bmn,bsn,drn,tcanet}`） | 提案/定位 | 属另一任务族，需边界标注 | 调研 |
| 先分割后分类 | 边界 → 分类 | 边界来源未解 | 调研 |

表中「调研」项的输入输出、权重可得性、代码许可、动作顺序与重复实例假设，由任务 2.1–2.4 记录，选型由用户裁定。

### D8: 显式禁令（防回退）

实现 MUST NOT 引入以下前置：`λ` 序列、无监督聚类/行为簇词表、行为素离散化。缺少这些时系统 MUST 仍能产出段列表。此条写进 spec，因为它是本次修订的核心，且旧方案文本仍在仓库中（`identity-action-tokenizer`、`video-feature-latent`）。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 边界精度受窗口步长上限约束，可能达不到预期 | 步长/重叠/多尺度作为可调项；验收先测出该上限再谈目标，不承诺无法达到的精度 |
| 短动作（数秒）被长窗口稀释甚至消失 | 短窗分支或最小窗口保证；短类别的召回单独报告 |
| 类别极不平衡（`toileting` test 仅 7 条） | 分类别报告 + macro 汇总；单类别结论标注样本量，不据 7 条下强结论 |
| 长静止（数十分钟）与 4.3 s 窗口尺度错配，被切成大量同类窗口 | 合并规则 + 累计时长判定（任务 5.3）；不靠分类模型反复"确认睡觉" |
| 无猫区间误标污染端到端指标 | 消费门控标记并在报告中单列无猫时段；门控 FPR 的宽区间估计如实登记 |
| 数据泄漏（同拍摄日多段） | 沿用按拍摄日隔离的划分，不重新随机划分 |
| 用片段分类成绩冒充端到端 | spec 层禁止 + 报告模板强制三口径并列 |

## Open Questions

- 是否需要引入 TAD/TAS 作为对照实验（取决于任务 2 的调研结论与用户裁定）。
- 是否采用多尺度分层融合；若采用，融合规则如何定义。
- 段列表是否需要额外字段（支撑窗口数、聚合依据、可修订标记），以支撑审计。
- 长静止的累计时长阈值取值（影响段形态，但不影响 spec 的三口径要求）。
