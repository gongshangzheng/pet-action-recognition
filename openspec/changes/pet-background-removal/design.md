## Context

见 `proposal.md - Why`。现状与约束：

- **已有**：GroundingDINO 五类检测（`multi-object-detect-gate`，已归档，可提供猫的 bbox）、跟随裁剪（`crop-first`，猫居中但**框内仍含背景**）、黑边标注约定（speedrun 模块）
- **缺口**：从"裁剪"到"抠像"——需要把 bbox 内的背景像素真正移除
- **下游约束**：`identity-action-tokenizer` 的 TivTok 式双 token 架构假设背景稳定；followcam 场景背景随相机移动，必须消除
- **执行机**：pet（RTX 4090）；GPU 任务前查占用
- **数据规模**：followcam 34 段 + mammal_v0 2234 + cats v1 717
- **⚠️ 2026-09-17 选型变更（用户裁定）**：抠像改用**实时小模型**（`rembg` 承载的轻量背景移除模型）；**SAM 不再承担猫本体抠像**，改用于背景对象层（独立 change）

## Goals / Non-Goals

**Goals:**

- 猫本体抠像：输出仅含猫像素、其余填充为**固定纯色背景**（默认**白**）的视频，逐帧与原视频对齐
- **模型轻量、实时可用级**：单帧推理在实时量级（GPU 几十毫秒/帧），全语料批处理分钟级
- **许可合规**：所用模型权重 MUST 为允许本项目使用的许可（禁用非商用权重）
- 全语料批处理，可续跑，产出可核对清单
- 掩码质量可检测、异常可兜底（不静默输出脏数据）
- 速度满足"又快又好"：批处理全语料在可接受时间内完成（小时级）

**Non-Goals:**

- 不追求影视级 alpha matting（下游是特征提取，非合成）
- **本 change 交付仍为离线批处理**（不做在线/流式抠像服务）——但**选型 MUST 为实时可用级小模型**，为 L6 实时监控模式预留（2026-09-17 补充）
- 不重新实现检测（复用现有 GroundingDINO）
- 不处理空间上下文语义（`multi-object-detect-gate` 的空间关系状态层负责；**SAM 的背景对象层另立 change**）
- **不做 SAM 的关键帧背景对象推理**（那是背景对象层的职责，不在本 change）
- 不改动原视频与既有 followcam 产物

## Decisions

### D1: 二值掩码而非 alpha 抠像

**决策**：输出二值掩码（猫 / 非猫），背景填充**固定纯色**（默认**白**）。

> ⚠️ **2026-09-17 修正**：原写"背景置黑（沿用项目黑 margin 约定）"——**查证为错类比**。那个黑 margin 是 **speedrun 标注视频的上下黑边条**（目的是文字不遮画面，给整帧加 letterbox），与抠像填背景**毫无关系**。所以填充色是**全新决策**，据下方 D1b 重定。

**理由**：下游 tokenizer 的 TivTok 式架构只关心"背景运动是否被消除"与"猫本体是否完整"，对边缘羽化无要求；二值掩码实现简单、速度快、无 alpha 估计误差累积。

**备选**：alpha matting（RVM）——毛发边缘更自然，但复杂度更高，且我们的用途不需要。列为对照。

### D2: `rembg` 类**实时小模型**为主，做小规模选型实测（2026-09-17 修订）

**决策**：以 **`rembg`（danielgatis/rembg，库 MIT）承载的轻量背景移除小模型**为主方案。候选：

| 候选 | 许可 | 体积 | 备注 |
|---|---|---|---|
| `u2net` | Apache-2.0 ✅ | 176 MB | 显著物体分割（U-2-Net），通用基线 |
| `u2netp` / `silueta` | Apache-2.0 ✅ | **4.7 / 43 MB** | 轻量版，速度最优 |
| `isnet-general-use` | Apache-2.0 ✅ | ~176 MB | DIS，边缘优于 u2net |
| `birefnet-general-lite` / `-general` | MIT ✅ | 小 / 大 | 边缘最好（soft alpha）；heavy 版更慢 |

先在少量样本上跑对比，按 **许可 + 掩码质量 + 时序稳定性 + 速度** 四项裁决。

**理由**：
- **轻量、实时可用级**：U²-Net 系 GPU 推理几十毫秒/帧 → 全语料（≈2.6 万帧 @512×512）**分钟级**完成；相比视频分割模型的逐帧记忆传播便宜一两个数量级
- **显著物体分割正好对症**：followcam 已把猫居中且占画面主体 → 猫天然是"最显著物体"，正是 U²-Net/ISNet 这类模型的训练目标
- **工程成本最低**：`rembg` 提供 CLI / Python 库 / **视频帧管道**（`ffmpeg -f rawvideo pipe | rembg b W H -o out/%06u.png`），ONNX Runtime，依赖轻

**⚠️ 许可陷阱（选型硬门槛）**：
- `rembg` 库本身 MIT，但 **README 明确警告：权重许可独立于库许可**
- **`bria-rmbg` 是 rembg 的默认模型，采用 BRIA 许可（商用需付费）→ 必须显式换掉**（`-m u2net` 等）
- 上表许可已核（Apache-2.0 / MIT），均可用

**本 change 已移除的方案**：
- **SAM2 退出猫本体抠像**（用户裁定 2026-09-17）——SAM 改用于**背景对象层**：维护"有哪些背景物件"、纠正/补全 GroundingDINO，**仅关键帧触发**，属独立 change（暂名 `background-object-memory`）
- **RVM 否决**：人物域训练 + **GPL-3.0 传染**
- **RMBG-1.4 / RMBG-2.0**：BRIA 非商用许可，**红线**

**保留对照（仅当小模型普遍失败时重测）**：SAM2（质量上限对照）。

### D2b: 显著物体分割的"选错对象"风险与检测框约束

**风险**：显著物体分割输出"最显眼的东西"。followcam 下猫通常最显著，但背景若有更大/更亮的物体（大石碗、亮靠垫），**可能分割错对象**。

**决策**：用现有 GroundingDINO 猫框做**零成本约束与校验**：
- 校验：掩码质心 MUST 落在猫框内；框内掩码面积占比低于阈值 → 判定为"选错对象"
- 兜底：标记告警 + 人工复核；不静默输出

**备选**（若问题普遍）：改用可接受检测框 prompt 的模型（如 SAM2/SAM）作为兜底；但那会推翻 D2 的轻量化收益，故仅在实测失败时启用。

### D1b: 背景填**白**而非黑（2026-09-17 用户裁定 + 技术论证）

**决策**：背景填充**白色**（纯色常量）。

**理由**：训练影响黑/白**几乎中性**（常数区域零信息，且真实目标与重建目标**同一 fill**，首层卷积即可吸收该偏置）→ 决策权交给「给人看」，而可读性有实际收益：

| 考虑项 | 黑 | 白 |
|---|---|---|
| 训练影响 | 近中性 | 近中性 |
| **人工目检可读性** | ⚠️ **深色猫边缘错误看不见** | 浅色猫不可见（题可由 D1c 解决）|
| 审美 | 一般 | 更干净（用户偏好）|
| 预训练权重兼容 | 大块纯色对 natural-video 预训练均 **OOD** | 同左 |

**配套修正（更重要）**：
1. **损失改为掩码内计算**（masked loss）——重建/感知/对抗损失只在猫掩码内算 → **背景色对训练彻底无关**，颜色选择降为纯「给人看」的问题（同时避免大块常数区域浪费判别器容量、稀释感知损失）
2. **目检不依赖 fill 对比度**——改用**掩码轮廓叠加图**（对任意猫色有效）；复用现有「告警段接触表 `contact.jpg`」设施
3. **一致性**：训练 / 推理 / speedrun 评测消费的抠像视频 MUST 为**同一 fill**
4. **消融**：选型实测（任务 1.3）顺带跑一组黑/白对照，留数据

### D3: 掩码质量闸门与兜底

| 检查 | 触发 | 兜底 |
|---|---|---|
| 掩码面积突变 | 相邻帧掩码面积比值超阈值 | 回退最近有效掩码；连续超限则标记告警 |
| 时序漂移（帧间闪烁）| 相邻帧掩码 IoU 显著低于阈值 | 对掩码做时序平滑（中值/滑动平均）；连续超限标记告警 |
| **掩码与检测框不一致** | 掩码质心落在猫框外 / 框内掩码占比过低（**显著物体分割选错对象**，见 D2b）| 标记告警 + 人工复核；不静默输出 |
| 检测丢失帧 | GroundingDINO 无猫框 | 沿用上一有效掩码 / 标记该帧为"无猫" |
| 全段无有效掩码 | 整段失败 | 记录失败，产物跳过（不产脏数据）|

> 注：小模型逐帧独立推理，**无跨帧时序一致性**（这是与 SAM2 的关键差异）；因此"帧间闪烁"从风险升为**闸门项**，需实测并量化。

### D4: 白色背景 + 逐帧对齐输出

**决策**：背景填**白**（见 D1b）；输出视频保留原帧率、分辨率、帧数（逐帧对齐）；编码用 H.264 mp4。

**理由**：帧数/帧率一致是下游窗口切片正确对齐的前提（16 帧窗口 stride 8）。

### D5: 批处理与清单

**决策**：批处理脚本遍历语料根目录，产物写独立路径，清单（JSON/CSV）记录每段状态（成功/失败/告警）+ 失败原因；支持续跑（跳过已完成）。

## Risks / Trade-offs

- **猫毛边缘分割误差** → 特征提取对边缘容忍度高；必要时掩码膨胀 2-3 px
- **逐帧无时序一致性 → 帧间闪烁**（小模型的主要代价）→ 掩码时序平滑；下游是特征级任务容忍度高；退化时升到 `birefnet-general`（soft alpha）
- **显著物体选错对象**（背景有更显眼物体）→ D2b 检测框一致性校验 + 告警
- **输入分辨率损失**：`u2net` 内部把输入缩到 320×320 再上采样 → 512 下边缘精度有限；若不足则升 `isnet-general-use` / `birefnet-general-lite`（内部 1024）
- **许可风险** → D2 硬门槛：禁用 `bria-rmbg`（rembg 默认值）与 RMBG 系权重
- **多猫场景**（数据中存在多猫）→ 默认保留所有检测到的猫（掩码取并集）；身份训练只用单猫片段（在 tokenizer change 中处理）
- **遮挡/快速运动导致漏分割** → D3 质量闸门 + 告警
- **存储增长**（新增一套抠像视频）→ 可接受；可选用更高压缩率编码
- **模型权重下载** → 与既有 checkpoint 同流程管理（HuggingFace / GitHub releases）

## Open Questions

- 最终选型（`u2net` / `isnet-general-use` / `birefnet-general-lite`）由 D2 实测决定，不影响 spec 与任务拆解
- 是否需要保留少量 alpha 信息（若未来做合成/生成任务）——当前不影响
- 实时可用级模型是否为 L6 实时模式直接复用（吞吐实测在任务 2.5）
