# 设计与只读依据

## 已知事实

依据 `check-company-training-in-memory/design.md` 的前次只读检查：

- 视频目录有 2,737 个正常 `.mp4`，另有 2,737 个 `._` AppleDouble 文件。
- CSV 有 2,626 行：1,574 条上传引用、1,052 条 local-files 引用。
- JSON 有 2,737 个 task；按两种 URL 分别解析后，全部引用均可一一匹配。
- 无有效标注的任务或 `behavior` 为空的 CSV 行也有可匹配视频。
  本次仍保留这些记录，不因其标注状态筛除。

本次只读查阅了原训练检查与正式训练入口。现有
`scripts/check_company_training.py` 只支持上传路径；
`scripts/train_model.py` 使用 MMAction2 VideoDataset 列表格式。
本 change 不改上述训练脚本、不转换动作区间或整段视频标签。
规范化的是视频地址，并不将 Label Studio CSV/JSON 宣称为 VideoDataset 清单。

旧交互 SSH 会话已断开，没有新建远程连接或修改服务器文件。
上述数量是历史基线；实施时重新只读核对，以实际输入为准。

## 地址解析

1. 建立实际视频文件名索引，排除 `._` 文件；处理 UTF-8/BOM 标注。
2. 已存在的本地绝对路径直接验证，确保再次执行不会再次剥离前缀。
3. 上传引用读取并解码 URL path 的最后一段。优先使用原文件名精确匹配；
   仅当原名不存在且去掉单个八位十六进制上传前缀后能精确匹配时，使用去前缀版本。
4. local-files 引用用标准 URL 查询解析读取唯一的 `d` 值，再取文件名。
   查询解析负责一次 URL 解码，不重复解码以改变文件名。
5. 输出解析后的实际绝对路径，验证文件存在、可读，且解析后的路径位于视频根目录。
   不做时间戳、编辑距离或其他模糊匹配；未知格式、缺失、歧义均报告失败。

## 标注保护

CSV 保持列名、列顺序、行顺序及每个非 `video` 字段的原始字符串值，
尤其不重新解析/序列化 `behavior`。JSON 保持任务顺序与结构，
只修改 `data.video`；`annotations`、`predictions`、时间范围、标签和元信息原样保留。
副本可能采用新的 CSV 引号或 JSON 缩进格式；允许格式变化，不允许其他字段值变化。
原 CSV/JSON 不覆盖，处理前后计算 SHA256 进行核对。

无标注、空列表、取消标注和多标签记录均保留，不作清理、合并或标签选择。
跨 CSV/JSON 相同 task ID 的视频地址如出现冲突，报错，不静默修正标注。

## 写入与核验

标注副本写入项目 `datasets/company_video_paths/`，映射表及摘要写入
`results/datasets/company_video_paths_<执行时间>/`。源目录始终只读。
先在内存完成全部映射与非地址字段比较，再写入项目目录并回读验证。
已有不同内容的目标文件不覆盖；相同内容允许复用，避免重复执行破坏结果。
处理失败不留下声称完成的最终副本；专属项目目录中的临时产物明确标识并清理。

核验应包括所有地址的存在性、唯一对应和读取权限，不需要解码视频或执行模型。
以源 JSON 副本移除 `data.video` 后进行深度比较；CSV 比较全部非地址字段字符串。
输出任务/行计数、映射成功数、解析方式计数、失败原因及原标注哈希。
正常情况下历史 CSV 2,626/2,626 与 JSON 2,737/2,737 均可匹配；
如当前数量不同，先报告变化，不能将历史计数当作本次通过结果。

脚本在本地只做语法检查；进仓库提交后同步服务器，在现有环境执行地址修复及核验。
不安装依赖，不读取私钥，不保存动态口令，不更改网络权限，不跑训练或前向。
