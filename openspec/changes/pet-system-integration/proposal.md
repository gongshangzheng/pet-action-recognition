# Proposal: pet-system-integration

> 职责协调：数据准备、教师检测与去重、跟踪、YOLO 学生及动作离线训练以 [`pet-pipeline`](../pet-pipeline/design.md) 为主；本 change 保留空间状态、观测指标、端云与联合验收的系统统筹。旧任务已按职责迁移，旧号及状态见 task-map；跟踪算法尚未最终选定。

## Why

当前交付需要把监控视频转成可验收的闭集行为结果，并在开发板和云端完成产品功能。旧计划以自研隐空间和行为发现为主线，不能继续代表当前优先级。本 change 负责跨组件目标与验收协议、空间状态、观测和端云联合验收；数据及训练由 pet-pipeline 承担，存在性与动作分割由各自 change 负责。

## What Changes

- 闭集行为验收：测试子集条件准确率 ≥75% 已按用户裁定达成；区间漏检率 ≤10% 尚未达成，事件匹配与分母待审定。
- 存在性检测：像素变化调度与轻量模型确认；GroundingDINO 用于教师标注，独立人工核验用于验收。
- 检测器路线：GroundingDINO 离线教师及 YOLO 学生由 `pet-pipeline` 负责，人工框真值用于独立质量验收；小批教师核对与两路训练方案见其 design。
- 宠物定位与跟随视角：复用现有抽样检测、插值和平滑；如实标记漏检、遮挡和多猫关联限制。
- 动作分割：核验现成模型，比较离线与有限后视处理；不强制因果，不依赖自研身份/动作向量。
- 空间状态与观测指标：明确猫与物体关系，以及亮度、对比度、活动幅度、身体面积占比与时长、面部暴露面积占比与时长的定义、提取和上报。
- 开发板与云端集成：行为上报、统计、直播、跟拍、设备控制、回放和亮点抓取；建立每项功能的数据链与验收用例。
- 架构文档重写：按组件全名组织章节与 Mermaid 图，写明已实现、未验证和待设计，取消组件层号。
- 整体跑通后再研究 optional 背景移除及额外关联器；离线与在线跟踪方案仍待调研和用户选择，OC-SORT 仅为已有基线。

身份向量/动作向量研究、行为发现与聚类均搁置，不安排实施，不作为当前链路前置。

## Capabilities

### Modified Capabilities

- `motion-pipeline`: 新增系统集成边界的未来要求；数据及训练的具体合同由 `pet-pipeline-data` 管理。该 delta 不修改或同步已有主 spec。

## Impact

涉及现有存在性检测、动作分割、空间状态、训练评测和 Live 模块及开发板/云端接口；具体代码、硬件能力和部署分工须完成只读盘点并落入子计划后再实施。此次仅修订规划与项目记忆，不表示已批准实验、训练、服务器操作或产品部署。
