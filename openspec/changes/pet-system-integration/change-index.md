### 顺序与解除循环

现状：tracker 2.5 需要 pet 逐帧框/裁剪，pet 4.19-4.21 若等 tracker 3.5 的最终选择，而 3.5 又排在依赖 2.5 的 3.1-3.4 后，就形成环。建议把**接口确认、固定可调用阶段版本、最终选型**分开：tracker 1.4 经用户确认候选及规则，2.2/2.3 按获批范围提供有版本的真实可调用接口；pet 使用该版本完成逐帧框数据适配与裁剪供 2.5/3.1 验证；随后 3.2-3.5 比较及最终裁定。阶段版本不等于最终选择，也不是未经批准的临时 fallback。若用户不授权在 3.5 前固定阶段版本，则目前无法无环执行，须先决定接口和执行次序；不能虚构现成产物或新增任务。严格串行的 tracker 不自动与 pet 并行；pet 的原有共享前置和两路线串行/并行约束仍有效，实际跨 change 执行标注与顺序需一并由用户确认。尤其 4.19 晚于 4.6，若 4.6 被解释为等待最终选择也会再成环，须明确它只调用上述获批阶段版本，最终接入须等 3.5。逐帧框规则在 1.4 是否足以批准、2.2/2.3 哪项容纳正式逐帧接口，均为待决定的设计落点，不能直接当现行合同。
