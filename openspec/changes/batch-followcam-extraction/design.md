# Design: batch-followcam-extraction

> 继承总管 D1（验收的抽样+插值方案）、D1b（GatedTracker 否决记录）、D2（crop-first 口径）、D6（petlib 接口）；子 change `multi-object-detect-gate` 的 MD1-MD3（多 prompt + 空间状态）。

## Decisions

### B1: 预处理主链（已验收方案规模化）

GroundingDINO 多 prompt 抽样检测（每 10 帧）→ 线性插值 → 滑动平均 → follow_adaptive 裁剪 → H.264 跟随视频。沿用 gate0a_v3 全部参数（尺寸离群过滤 1.8× 中位内置）。

### B2: 逐帧运动校正（用户提出 2026-09-14，帧差方案的背景建模改进版）

**问题**：10 帧抽样 + 插值 → 抽样间隙猫移动时框不全（gate0a 验收中观察到的已知瑕疵）。

**方案**：用户提出「每帧与 10/20 帧前做帧差辅助定位」；工程上采用**背景建模**（时序中值背景，慢更新）替代长程帧差——长程帧差标记猫的旧+新位置（重影，可能把框错误扩向旧位置），背景前景 mask 标记的是猫的**当前完整位置**。

**融合规则**（每帧 CPU，不增 GPU）：
1. 背景模型输出前景 mask → 连通域
2. 与插值框相交的最大连通域 → 框向外扩展/平移以覆盖之（单帧校正幅度设上限，防漂移）
3. 无有效前景（猫静止被吸收 / 无猫）→ 信任插值框，不校正
4. 校正量落盘（供质量报告：校正率 = 被校正帧占比）

**验证**：074451 段跑「仅插值 vs 插值+运动校正」两版跟随视频对比，人工看框覆盖差异 + 校正率统计。

### B3: 产物契约

- 轨迹 JSON：猫框（含 interpolated / motion_corrected 标记）+ 家具框 + 空间状态序列
- 跟随视频：H.264（petlib H264VideoWriter）
- 关键点 NPZ：(T,V,3) float16 + frame_inds（辅助信号）
- 批处理报告：逐段检出率/插值率/校正率/离群剔除数；插值率 >30% 告警
