# 裁剪训练实验设计

## 1. Context

本设计供实验执行者实现和用户验收。用户已批准三臂实验；批准记录与运行证据见 [evidence.md](evidence.md)。小批裁剪质量已由用户确认，全量 B/C 资产与三臂共同索引已生成；训练在 A 臂部分轮次后暂停，原因与重启条件见 evidence.md 的 2026-11-06 条目。

### 1.1 已核对的入口

- `scripts/pet_detect_track.py`：GroundingDINO-tiny 抽样检测，最高置信猫框、插值和平滑，输出 `track.json`。`--motion-correct` 默认关闭；像素辅助使用 MOG2 前景与检测框交集外扩，不是存在性判定。
- 该检测脚本把全部解码帧保存在列表中；无猫检测时没有合法的空轨迹分支，插值也未限制长缺失区间。当前最高置信框方案没有多猫身份保证。
- 该脚本只在启用运动校正、非抽样帧且达到预热帧号后调用背景模型，需修正连续更新与预热过程后验证。静止宠物不能因前景消失被判无猫。
- `scripts/make_followcam.py`：按 `camera_box` 裁剪，外扩系数 1.2，默认输出 512×512；会把 `state` 文字画进 `followcam.mp4`。空裁剪写黑帧，短轨迹复用末项，均不能静默用于本实验。
- `scripts/pet_batch_run.py`：旧批次驱动未传入 `--motion-correct`，因此不能把旧批次一概视为启用了像素辅助。
- `configs/cat_action_videomaev2_b_v1.py`、`configs/cat_action_v1_base.py` 与 `petlib/datasets/cat_intervals.py`：七类分类配置，直接读取原始视频并在人工标注区间内采样。
- `scripts/run_cat_action_batch.py`：固定了旧索引和旧结果目录，需要独立实验入口，避免写回旧排名和模型结果。

### 1.2 历史参照与证据边界

`docs/cat_action_training_v1.md` 记录训练目录为 `pet-final-v1`，数据和产物链接到 `pet-final`。它记录七类 train/val/test 为 1664/604/442，VideoMAEv2-B 验证 top-1 85.93%、macro-F1 70.97%，测试 top-1 81.90%、macro-F1 67.66%。

这些数字是历史报告，不是本次复测。报告还提示本地曾有不同 seed 的索引副本，实施时必须核对远程索引 SHA-256，不能按本地行数猜测一致性。旧测试结果已公开，本轮重复使用该测试集只能作为既有基准复验，不能称全新独立留出验证。

## 2. Goals / Non-Goals

产出可追溯的空间裁剪语料和配对分类结果，分别回答裁剪是否有帮助、像素辅助是否带来额外收益。接受负结果，实验完成不以提高到某一分数为条件。

此次沿用七类人工时间标签，目标宠物未明确、多猫歧义和漏检均须可见。不引入新身份关联器，也不把分类准确率解释为事件检测效果。

## 3. Decisions

### 3.1 固定数据与单一训练臂

> **方案：** 本轮只训练 B（GroundingDINO 裁剪）。A（原视频）与 C（裁剪加像素辅助）的资产已生成，记录在 evidence 中备查，但不训练、不参与本轮评测结论。
>
> **理由：** 用户判断当前目标是让裁剪输入的分类链路端到端跑通并得到可用模型，而不是归因裁剪相对原视频的收益。少训两个臂可省去两次 20 epoch 训练及其调参、选择、测试成本，也让本轮结论的适用范围更清楚。
>
> **替代：** 原设计为 A/B/C 三臂配对，可分别回答“裁剪有没有收益”和“像素辅助有没有额外收益”。被本轮否决，代价是本轮不能声称裁剪带来提升，该限制必须写进报告；如后续需要归因，再按同一冻结索引补训 A 与 C。

先冻结原七类清单，再生成裁剪。样本筛选只能依据可解码性、检测和裁剪有效性及身份歧义，不能依据分类预测或测试类别调整规则。

训练样本只含猫。狗区间在可用集合中仅 7 个（train 6、val 1、test 0），数量不足以支撑一个类别目标，且会让验证集的物种构成不稳定，因此狗区间不进入本轮训练与评测。剔除后可用区间为 207：train 131、val 32、test 44。可用清单在训练前冻结，B 使用它；另列原清单总数、每类每 split 的损失和失败原因。

只训练 B 后，三臂对照才需要的核验不再进行：B/C 锚点像素一致性与源视频时间轴漂移都属于比较或按秒解释的范畴，单臂训练按帧号采样，不受其影响。帧号与区间边界的对应仍需保持，由索引与媒体审计覆盖。

在原始评测清单上同时报告成功分类数除以全部区间数，裁剪失败计为未成功分类；并单独报告成功裁剪子集的分类指标。前者是“含预处理失败的区间成功率”，不能称事件级准确率，避免用丢失难例换取高分。

### 3.2 复用检测缓存与干净裁剪

> **方案：** 对冻结清单引用的源视频生成检测缓存，B/C 共享完全相同的检测结果，随后分别计算相机路径并编码派生视频。逐个源视频处理，使用顺序解码和有界窗口，避免保留全片像素。
>
> **理由：** 源视频全长空间裁剪可保持原标注帧号，避免片段重编号错误，也避免重复检测。
>
> **替代：** 只编码标注时间段可节省磁盘，但需要额外帧号重映射，本轮不采用。

提议首轮复用现有起点：抽样间隔 10、检测阈值 0.3、外扩 1.2、输出 512×512，训练输入再取 224×224。这些数值不是已验证的最优值，须经训练集小批质检并冻结。任何后续参数改动先记录原因，并重新生成受影响缓存及清单。

训练有效帧只含裁剪画面，不新增文字、框、置信度或标签；源视频已有水印仍可能保留。展示叠加写入独立诊断视频。保留原帧数、顺序、FPS 与时间戳映射，核验编码无掉帧、重复帧或截断；若源视频为可变帧率且无法保持映射，明确拒绝，不能猜测帧号。当前媒体审计尚未覆盖逐帧时间戳，此项仍待完成。

每个源视频记录源路径及哈希、尺寸和帧数、检测权重哈希、代码提交、参数、裁剪视频哈希、轨迹、逐帧来源及有效性。重复运行验证缓存元数据后才能复用；参数或源哈希不符时拒绝混用，已有产物不得覆盖。

### 3.3 缺失检测与多宠物处理

> **方案：** 检测 prompt 同时包含猫和狗，并保留每个抽样帧的全部去重候选。只在有合法锚点的短缺口内插值；提议首轮最大锚点间隔为两个检测步长。端部、长缺失、空检测和目标歧义标记为无效；人工标注区间内任一帧无效，该区间进入失败清单，确保随机采样不会改变入选集合。
>
> **理由：** 长插值或复用最后框会制造没有观测依据的目标轨迹。
>
> **替代：** 退回整帧能提高可用率，但会混淆裁剪实验，本轮不自动回退。新增跟踪器另行讨论。

缓存保留全部猫和狗候选。资格按猫判定，且只在整帧宠物总数为 1 时有效：帧内恰好一只猫时记录 `target_class=cat` 并按该猫框裁剪；帧内出现狗或多只宠物时记录 `multi_pet_unsupported` 并排除，狗不参与训练。曾考虑“多宠物帧只要恰好一只猫就用猫框”，实测 1,551 个 `multi_pet_unsupported` 区间中单猫帧只占 13.3%、八成帧猫狗均未检出，放宽后新增可训练区间为 0，因此不采用。SORT 目标编号和多目标子视频导出属于后续独立实验。

实测说明：1,551 个 `multi_pet_unsupported` 区间的 408,301 帧中，80.6% 的帧猫狗都没有检出，13.3% 恰好一只猫，1.4% 有两只及以上猫。这些区间的主要障碍是漏检而非多宠物策略；放宽多宠物策略在现行“每帧有效”规则下新增区间为 0，因此维持严格排除。

无宠物帧不能由像素低运动直接判定。检测为空只记为 `no_reliable_pet_detection`，可能是宠物确实不在画面，也可能是小目标、遮挡、红外或探测器失败；当前缺少人工确认时不得声称“已确认无宠物”。像素变化继续只用于扩展已有检测框。

审阅显示与训练资格分开：无效帧有宠物框时使用最高置信度宠物框；检测缺口用最近同物种框插值或端部保持显示，并标记长缺口。只有整个视频没有任何宠物框时才显示完整原画。显示回退不改变 `valid` 或共同索引，也不保证目标身份连续；不能将可见画面视为训练合格证据。

### 3.3.1 复用 follow_cam 修复（2026-11-04 用户批准）

以 `scripts/pet_detect_track.py` 的检测框线性插值、5 帧滑动平均及运动偏移阻尼为基线，提取共享函数供当前裁剪链路使用。滑动平均在边缘复制端点，避免旧实现零填充造成首尾缩框。删除临时 smoothstep/EMA 0.2 审阅专用路径，有效帧与无效帧使用连续相机轨迹；训练资格仍由原检测规则独立判断。

漏检区间延续相机轨迹，不切换为全画面。首尾保持最近检测位置，长缺口和物种变化保留诊断标记，不因此放宽训练资格。整个视频无检测时明确标记无法定位，仅以原画供审阅。多宠物仍不进入训练，显示轨迹不保证身份连续。

像素运动校正复用旧实现的半余弦权重、旧版 xyxy 两组边坐标分别阻尼与限速（并非真正的中心/尺度分解）；B/C 使用相同基础轨迹。裁剪保留正方形比例，超出源画面的区域补边而不截断目标，不叠加文字。索引生成前核验源哈希、检测与渲染指纹、两路媒体存在性及哈希，拒绝旧缓存混用。新批复用 sample20-v3 检测缓存，保持 20 段、检测参数和源视频不变，只重建轨迹和媒体，便于归因。

验收包括缺口连续性、首尾无缩框、运动校正回归、资格不变及渲染缓存失效测试；远程先单段烟测，再生成全部 20 段 B/C、独立资格索引和新审阅集。视频全部保留远程，经现有后端播放。媒体核验后交用户逐段检查抖动、变焦呼吸、身体切断与错目标，未获确认前不扩量、不训练。

### 3.4 像素辅助变体的当前定位

C 已按同一检测缓存生成，用于记录像素辅助的实现与产物，本轮不参与训练与评测。它保留两项既有约束：只在非锚点帧使用像素前景外扩，不因低运动删除样本，也不改变检测缓存与空间标签；锚点帧的相机偏移为零。

C 不进入训练意味着其质量不再阻塞本轮，但也不能据此宣称像素辅助无效或有效。若后续要用它，需另行确认参数与人工质检。

### 3.5 训练与测试冻结

提议沿用现有 VideoMAEv2-B 配方：16 帧、间隔 4、224 输入，AdamW lr=5e-5、weight decay=0.05，20 epoch，warmup 2 epoch 后 cosine，AMP，micro-batch 4、累积 4，原七类权重。B 从 K710 蒸馏预训练骨干开始，不从旧七类 best checkpoint 续训。

本轮使用训练 seed 0，数据划分 seed 与训练 seed 分别记录。显存不足时调整 micro-batch 与累积并记录，不改配方其他项；多个 seed 的确认实验另行申请，本轮不宣称统计显著。

按 val macro-F1 保存最佳 epoch，使用 macro-F1 为主，top-1 与分类别召回作诊断。先写入冻结记录，再测试一次，不按测试集重新选参或挑模型。

训练须保存优化器与学习率调度器状态。基础配置的 `save_optimizer=False`、`save_param_scheduler=False` 必须覆盖；只含 `state_dict` 的检查点只能算诊断产物，不得作为对照实验的断点、最佳轮次候选或续训来源。中断后须在独立结果目录从预训练骨干重新开始，不得在被污染的目录上续写。

保存 top-1、macro-F1、balanced accuracy、混淆矩阵、各类 precision/recall/F1/support，以及逐 sample_id 概率和配对正确/错误变化。置信区间按源视频分组重采样，注明仅反映评测样本波动，不覆盖训练随机性。历史测试已使用的限制必须出现在报告中。

## 4. Risks / Trade-offs

裁剪可能丢失食碗、饮水机和如厕环境，导致类别性能下降。按类别检查失败，不能只报整体平均。

像素变化可能来自阴影、红外噪声或相机移动；固定机位适用性在训练小批审查中核实。未验证场景不能推广。

全长视频双变体编码会增加磁盘、CPU 和 GPU 成本。先估算源时长和存储，容量不足则停止并向用户报告，不能未经审核缩小样本后仍与旧全量成绩比较。

共享 GPU 有进程实际占显存或主机资源紧张时不得开跑；长任务通过 `remote-ops` 预检、静态审计、降规模冒烟及资源守卫。训练吞吐受共享资源干扰的结果不能用作性能结论。

只训练 B 意味着本轮无法把成绩差异归给裁剪。报告必须写成“裁剪输入下的分类水平”，不得与历史 A（原视频）成绩直接比较后声称提升，除非同时说明样本、配方和测试集复用差异。

可用区间只有 207 个（train 131），每个类别在验证集的样本极少，toileting 只有 2 个训练样本。任何类别级指标都可能由数个样本决定，报告必须逐类别给出 support，不得只报 macro-F1。

资源守卫自身的可靠性是训练前提，不是附带风险。已发现派生 worker 逃逸导致孤儿进程、进程退出时累计 jiffies 回落导致 CPU 百分比为负；这两项在真实 worker 生命周期下尚未验证。未通过“CPU 非负、elapsed 合理、超限时整组无残留”的 CPU-only 测试前，不得启动或恢复任何训练。

## 5. Migration Plan

实现使用独立 `exp/gdino-crop-videomaev2-evaluation` 分支，先提交可复用脚本、配置和测试，再通过 Git 同步远程并校验 HEAD。不得覆盖现有脏工作树或旧训练结果。

派生视频放 `results/cat_crop_classification/assets/<dataset-id>/`，索引放 `datasets/cat_crop_classification/<dataset-id>/`，运行记录放 `results/cat_crop_classification/<run-id>/{raw,gdino,gdino_motion}/`。各臂保存解析后的完整配置、环境、日志、状态、指标和权重哈希，禁止写回旧 model-zoo 排名。

代码以独立提交回退，原始数据和权重始终只读。失败产物保留状态，不自动清理用户数据；结论与失败原因写入本 change 的 `evidence.md`。

## 6. Open Questions

资产核验已确认：远程不存在 `pet-final-1`；`pet-final-v1` 是独立 worktree，`pet-final` 是主工作树，二者共享的数据、索引、权重和结果可读。原七类索引哈希与历史记录一致。后续仍须在任何训练前重新做资源预检与 Git HEAD 校验。

用户在 Review 时审核本设计提出的三臂成本、小批裁剪规则和训练预算。任何改变样本定义、实验臂或评测协议的后续决定必须先回写计划。
