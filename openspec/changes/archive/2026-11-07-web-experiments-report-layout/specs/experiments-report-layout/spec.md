## Purpose

规定实验报告页的导航结构、正文宽度策略、标题层级与响应式行为，使阅读长报告与查阅数据在同一页面内都不必牺牲可读性。

## ADDED Requirements

### Requirement: 列表与筛选位于侧栏

页面 SHALL 采用侧栏加正文的布局：侧栏承载筛选条件与报告列表，正文承载选中报告。列表项 MUST 显示标题、执行状态与结论，并标明当前选中项。

#### Scenario: 选中一篇报告

- **WHEN** 用户在侧栏点击一条报告
- **THEN** 正文切换到该报告，侧栏该项显示为当前选中
- **AND** 地址栏 query 同步为 `topic` 与 `slug`

#### Scenario: 筛选结果为空

- **WHEN** 当前筛选条件没有任何报告
- **THEN** 侧栏显示空状态说明，正文保持上一次选中内容或显示未选中提示
- **AND** 页面不出现空白区域或布局跳动

### Requirement: 正文宽度按内容类型区分

正文容器 MUST NOT 对整篇文章施加统一宽度上限。段落类文本 SHALL 限制在可读行宽，表格、代码块与案例图 SHALL 占满正文区。

#### Scenario: 宽表格

- **WHEN** 报告包含列数较多的指标表
- **THEN** 表格占满正文区宽度
- **AND** 宽度仍不足时仅在表格容器内横向滚动，正文不整体横向滚动

#### Scenario: 超宽屏阅读

- **WHEN** 视口宽度超过 1600px
- **THEN** 段落行宽保持在可读范围
- **AND** 数据区域随正文区一起变宽

### Requirement: 标题层级与页面结构

全页 MUST 只有一个一级标题，即当前报告标题。侧栏标题与正文内章节 MUST 使用二级或更低层级，且层级顺序不跳级。

#### Scenario: 打开一篇报告

- **WHEN** 报告加载完成
- **THEN** 页面存在且仅存在一个 `h1`
- **AND** 正文各章节为 `h2`，其子节为 `h3`

### Requirement: 章节导航

长报告 SHALL 提供章节导航，列出实际存在的章节。导航项 MUST 能跳转到对应章节，并在滚动时标示当前章节。

#### Scenario: 跳转到结论

- **WHEN** 用户点击导航中的「结论与下一步」
- **THEN** 页面滚动到该章节
- **AND** 该项显示为当前章节

#### Scenario: 报告缺少某章节

- **WHEN** 报告没有「附录」章节
- **THEN** 导航中不出现该项
- **AND** 不显示指向空锚点的链接

### Requirement: 响应式行为

视口宽度不小于 900px 时，侧栏 SHALL 常驻；小于 900px 时，侧栏 MUST 折叠为抽屉，正文 MUST 单列占满宽度。

#### Scenario: 窄屏阅读

- **WHEN** 视口宽度小于 900px
- **THEN** 正文单列显示且无横向溢出
- **AND** 侧栏通过明确的按钮打开与关闭

### Requirement: 既有交互不回归

改造 MUST 保留现有筛选、选中、URL query 同步与列表 keep-alive 行为。

#### Scenario: 从其他页面返回

- **WHEN** 用户离开报告页后再返回
- **THEN** 筛选条件与选中报告保持不变
- **AND** 不重复请求未变化的列表数据
