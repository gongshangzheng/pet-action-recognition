## Context

厂商材料 `docs/摄像头厂商对接材料-外发版-V0.2-20261105/` 的 README 标明其为 V0.2 外发版联调基线。`03-联调参数与待确认项.md` 列出尚待双方冻结的事项，`02-对接与验收清单.csv` 记录未执行验收。现有 `.agents/skills/live/SKILL.md` 面向本仓 Live 源管理和推理，不是厂商设备协议指南。

## Goals / Non-Goals

**Goals:** 让执行者找到对接材料、按链路区分证据、识别待确认项，并避免将视频上传误作行为或画面指标上报。

**Non-Goals:** 不核实实际服务部署，不制定新的接口或指标口径，不启动联调，不修改厂商资料或 `AGENTS.md`。

## Decisions

### 单独设立项目 skill

新建 `.agents/skills/camera-vendor-integration/SKILL.md`，以厂商对接、配网、设备协议和验收为触发词。现有 `live` skill 保持原样，继续负责本仓 Live 功能。备选方案是扩充 `live`，优点是摄像头入口集中，但会混淆两个系统的责任边界。

### 保留来源作为协议参考

skill 描述身份与配网、直播、控制、事件上传及 OTA 的排查和验收顺序，链接接口清单、适配文档、待确认表、验收表与公开向量，而非复制完整字段。它说明 BOUND 不等于 READY，心跳、SIP、WS 和媒体需分别核验；行为、画面指标的计算与上报不由现有材料证明。协议细节随版本核对，不能将文档表述当成部署现状。

### 明确授权和安全边界

skill 仅给出准备、核对和证据记录方法，实施性动作遵循项目 OpenSpec 审批。真实凭据不进入文档或日志，测试向量只用于离线比对。既有材料是否可入库或分发不由本 change 决定。

## Risks / Trade-offs

- 引用的厂商材料当前未被 Git 跟踪，其他工作区可能缺失。skill 应提示缺失时向用户索取授权材料，不假设文档可用。
- 摘要可能落后于接口版本。以经授权取得的最新材料和实际部署核对结果为准，V0.2 仅标注为来源基线。
- 单独 skill 增加一个入口，但职责区分可降低与本仓 Live 操作混淆的风险。

## Open Questions

- 材料的入库和分发方式由资料负责人另行决定，不作为创建 skill 或实施联调的隐含授权。
