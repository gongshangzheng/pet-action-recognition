# Design: video-feature-latent

> **三阶段总览（导读，2026-09-16 补）**——本 change 用"渐进入场"的方式把动作语义做出来，每阶段有独立闸门，不达标不进下一阶段：
>
> **阶段一：零训练选型**（任务 1.1，对应 L1 表格）
> 做什么：同一批跟随视频片段，用四个现成编码器各提一遍窗口特征（每窗口 16 帧 ≈1 秒 → 一个 768 维向量 = 一个"行为素"），各画一张 UMAP 二维散点图 + 算时序连续性 + 导出代表帧拼图。
> 为什么：不训练任何东西，几十分钟就能看出"哪只眼睛最会看猫动作"。
> 交付：你亲眼看四张对比图，挑行为团块最清晰、最能命名的那只眼睛当主力。
>
> **阶段二：全量发现 + 四闸门验收**（任务 1.2-1.6，对应 L2 判定、L6 闸门①③、L6b 闸门④）
> 做什么：用阶段一选出的编码器，给 34 段跟随视频全量提特征 → UMAP 降维 → HDBSCAN 聚出行为簇 → 导出每簇代表帧 → 你人工命名 → 冻结特征训线性探针。
> 交付：行为命名表 + 动作时间轴 + 探针 top1 报告。
> 闸门：①探针达标 ②可命名率 ≥60% ③码本不塌缩 ④身份泄漏接近随机——**全过则路线成立，阶段三不用做**。
>
> **阶段三：判别式自监督升级**（任务 1.7/1.9/1.10/1.11，对应 L3+L5+L6+L7+L8，条件启动）
> 仅当阶段二闸门失败才做：在我们 3k 段无标注语料上，用 CatHuBERT 迭代伪标签 + TiTok 式双 token 流（身份 register tokens × 动作 tokens）+ Wav2vec2 式对比目标，训练"懂猫"的编码器，然后回到阶段二重新验收。
>
> **读者指引**：想懂"为什么这么做"→ 读下方 L1-L8 各决策节；想知道"现在执行到哪一步"→ 读 tasks.md；想知道"最终产品长什么样"→ 读 proposal.md 和 specs/。

> 继承总管（pet-motion-latent-pipeline）D5（环境隔离）、D6（petlib 接口）；关键点降级裁定见 `batch-followcam-extraction` D2。**总管 D2b/D3/D8/A5/A6 已物理迁入本文件（ID 不变）**。
>
> **⚠️ 路线实施注记（2026-09-16）**：阶段三的自监督训练路线（L3 v2 架构 + L5 目标 + L6 CatHuBERT + L7 跨域 + L8 双 token 流）已**拆为独立研究 change `identity-action-tokenizer`**（含更详细设计 + UCF101→猫语料两阶段策略）。本文件的 L 系列保留为研究笔记与谱系出处；任务 1.7/1.10/1.11 已改指该 change。

## Decisions

### L1: 窗口特征口径（v2 修订 2026-09-15：用户质疑"K400 人类先验不适用"，候选重构）

**原设计缺陷（用户指出）**：VideoMAEv2 主力 checkpoint 的语义空间是人类动作（K400/K710），零样本迁移到猫域错位，不宜作主力候选。修订后三候选：

| 候选 | 动物域适配 | 时序 | 成本 |
|---|---|---|---|
| A. VideoMAE **v1 宠物微调版**（pet_action_mammal_v0 七类，训练产物） | ✅ 自家数据 | ✅ 原生视频模型 | 零 |
| B. **DINOv2 + 帧间差分**（timm 已装）：逐帧 embedding，窗口池化时拼接 Δfeature 作运动代理 | 中性 | ⚠️ 差分补偿 | 零 |
| C. **MammalNet VideoMAE**（CVPR 2023，18 类哺乳动物行为基准，动物版 VideoMAE） | ✅ 哺乳动物 | ✅ 原生 | 需下载权重（先探可行性；不可得则降级为后续增强） |

~~VideoMAEv2 K710 零样本~~ 降为参照（人类动作先验错位，用户裁定不作主力）。

| **D. V-JEPA 2**(Meta FAIR 2025-06,MIT 协议)--**新主力候选(2026-09-15 联网调研后升级)**:JEPA = latent 空间预测(非像素重建),官方定位即"视频→特征编码器";transformers 原生(`AutoModel` + `get_vision_features`);fpc16 变体与 16 帧行为素窗口精确对齐;SSv2 微调变体主打时序判别;MIT 无授权风险;hf-mirror 直连可下载(已核实,30 个变体)。**集成风险**:需 transformers ≥4.55(plf 现为 4.49),升级须先验证 GroundingDINO 兼容或开独立最小 venv。 | 

**调研溯源**:V-JEPA 2 官方模型卡 + HF 官方 API(hf-mirror 直连,2026-09-15);MammalNet 权重不在 HF(仅 GitHub,可达性存疑→维持降级);"220cat" 社区模型卡为空模板不采信。网络备注:本机路由层全局代理可用,直连国际站可达(本机 7890 端口代理未开不影响)。

**口径**：窗口 16 帧 stride 8（同前）。判定标准不变：UMAP 结构 + 相邻窗口时序连续性 + 人工可命名率为最终裁决；另增加"与 5 类人工标注的对齐度（NMI）"作辅助指标——注意微调版 v1 可能有"7 类判别偏置"（特征向标注类别收敛，抑制新行为发现），NMI 高不等于发现能力强，需结合簇数与可命名率综合判断。

### L2: 探针对照

主对照 = 同一编码器在**原始整帧**（未跟随处理）视频上的特征——检验跟随预处理增益；参考 = VideoMAEv2 全量微调基线（现有评测体系）。

### L3: 自训版触发条件与架构（2026-09-16 修订：显式合流 FLOAT 双分解与 CatHuBERT）

零训练基线「人工可命名率 <60%」或探针低于原始帧对照时，启动自训版。**架构 = FLOAT 式双分解（总管 D3）与 CatHuBERT（L6）的合流**：

**v2 架构（2026-09-16 用户定义，FLOAT 近似；取代此前"重建特征序列"口径）**：
```
身份 tokens（K_id≈32，TiTok 式可学习，跨时间共享）←─ 整段视频编码
逐帧动作 latent z_t（每帧一个，低维 ≈32d）      ←─ 编码器逐帧输出
            ↓
解码器 G(identity_tokens, z_1..z_T) ──► 重建原始视频帧
损失 = 重建(L1+LPIPS) + CatHuBERT 伪标签 CE(z_t 动作可分性)
     + InfoNCE(track 级 ID, E_id 身份监督) + GRL/正交(双分支互斥)
     + 速度匹配 + 平滑
解耦三机制：① 身份 token 随机 dropout（防 z_t 混入身份）
           ② 跨猫交换重建（A 的 z_t × B 的身份 tokens → 应重建出"B 做 A 动作"）
           ③ 瓶颈结构（身份 tokens 少而共享、z_t 低维而逐帧）
骨干初始化：V-JEPA 2 fpc16 / VideoMAE；解码器轻量（ViT-S 级）；3k 段语料，4090 可训
附赠能力：任意身份 × 任意动作序列 → 可控猫视频生成（FLOAT 同款应用）
```

**这个合流回应"FLOAT 内容是否丢失"**：没有——D3 的双分解全程保留，0B 后仅输入由关键点换为视频特征；与 L6 合流后，身份处理从"仅 GRL 推开"升级为"E_id 正向子空间 + GRL 辅助"，身份信息被分流复用而非丢弃。

## 自总管迁入的决策（ID 不变，交叉引用保持有效）

### D2b: HQSAM 的定位——它是什么、能干什么、为什么不在主链

**HQSAM 是什么**：Segment Anything（SAM）的高质量变体——可提示分割基础模型。输入一个框（来自 GroundingDINO），输出**像素级动物轮廓 mask**（精确到毛发边缘，SAM 在细边界上会糊，HQ-SAM 用高质量输出 token + 早晚特征融合修正）。与检测器的区别：检测给"框"（含 60–80% 背景），HQSAM 给"轮廓"（只含动物像素）。

**它在管线里的三个潜在用途**：
1. **mask 清洗 crop（消融实验 3.5）**：把裁剪帧中背景像素抹掉/模糊，只留猫——对抗白天背景捷径学习（模型靠猫砂盆/家具位置猜动作）。是否有效未知，故为消融实验而非主链
2. **体型/毛色分析（二期）**：轮廓面积/脊柱曲率可服务健康监测（消瘦检测），毛色区域可辅助个体识别
3. **关键点质量辅助（弱）**：理论上 mask 可限制关键点搜索区域，但 SuperAnimal 全图推理已够用，收益不明确

**为什么不在主链**：主链表示为视频特征（D8 修订后），mask 是像素级资产，主链没有消费者；且 HQSAM 每帧 ~150-250ms，挂主链白白拖慢管线。结论：主链 = 检测→跟踪→裁剪；HQSAM 独立成可选阶段（按需开启），消融实验决定 mask-cleaned crop 是否成为训练数据的默认形态。

### D3: 隐空间架构（修订版：视频特征主链；VQ 自训降级为可选增强）

**关卡 0B 裁定后的主链（零训练，无新模型训练）**：
```
followcam 视频 ─滑窗(16帧,stride8)─► 预训练编码器(VideoMAEv2/DINOv2) ─► 窗口特征(768d) ─时序平滑─► UMAP+HDBSCAN ─► 行为簇
```
- 窗口特征 = 编码器 CLS token（VideoMAEv2）或逐帧 patch 均值池化+时序池化（DINOv2）
- 主表示选型实验（D8）在两个编码器上同台对比后定主用
- 关键点序列仅作辅助：在场率/运动强度统计、簇代表帧叠加参考

**可选学习版（仅当零训练基线不达标时启动，架构沿用 FLOAT/Keypoint-MoSeq 杂交）**：
```
x = 视频特征窗口 (48,768) ─E_mot(1D CNN+Transformer)─► h(12,256) ─VQ(K=512,d=32)─► z(12,32) ─G─► x̂
L = L1(x,x̂) + 1.0·L1(Δx,Δx̂) + L_vq + 0.1·InfoNCE(s) + 0.01·‖Δz‖²
```
- 输入由原关键点 (48,34) 修订为视频特征序列（48,768），其余不变
- VQ 码本 K=512；码本利用率 <50% 触发重置（防塌缩）
- 身份码对比学习：监督信号 = track 级 ID；参数量目标 <10M；单卡 4090 训练 ≤4h
- 与 Keypoint-MoSeq 的差异：HMM → VQ-VAE/Transformer；关键点 → 视频特征；产出离散 token 便于 L2 切分与统计

**实施次序（修订）**：零训练编码器特征基线 = **主链**，不再是「基线」——若其「人工可命名率 ≥60% 且簇不碎」且线性探针达标，学习版整个不启动

### D8: 主表示选型——预训练视频编码器对比实验（关卡 0B 裁定后新增）

**背景**：关键点降级辅助后，主表示 = 跟随视角视频的预训练编码器零训练特征。两个候选：

| 候选 | 机制 | 优势 | 风险 |
|---|---|---|---|
| **VideoMAEv2** | 视频掩码自编码器，时序建模原生 | 动作语义最强（Kinetics 系训练），16 帧窗口直接出 CLS token | 对遮挡/小物体敏感；我们的跟随视频恰好规避这点 |
| **DINOv2** | 图像自监督 ViT，逐帧+时序池化 | 外观/姿态表征稳，逐帧可用（粒度细） | 无时序建模，运动信息靠池化窗口间接获得 |

**实验设计**：两段验收跟随视频 + 抽 3 段其他白天段，两编码器各出窗口特征（16帧窗口 stride8）→ 各做 UMAP 可视化 + 时序平滑度（相邻窗口特征余弦距离分布）→ 人工看簇内代表帧可命名性。**判定：可命名簇比例为主，时序连续性为辅；打平取 VideoMAEv2**（时序原生）。两实现均走 petlib 接口（`petlib/features/`），契约测试复用。

**与评测的关系**：§7 线性探针的「基线」相应改为**同一编码器在原始整帧（未跟随）视频上的特征**——对比的是「跟随预处理是否带来增益」，而非「我们 vs VideoMAEv2」。

## 附录：算法原理（自总管附录 A 迁入）

### A5 运动隐空间

**VideoMAE / VideoMAEv2（下游 L1 的骨干来源）**
- 是什么：视频掩码自监督预训练——把视频切块后**遮住 90%**，让模型从稀疏可见块重建被遮内容
- 为什么有效：极高掩码率迫使模型学运动语义而非外观纹理；且**几千段视频即可预训练**（数据效率），V2 的双掩码+蒸馏把规模推到十亿参数级
- 与本项目：训练/评测模块现用的骨干谱系；隐空间线性探针的对照基线

**FLOAT（隐空间架构来源，D3）**
- 是什么：运动隐自编码器——参考帧编码为静态身份码，序列编码为运动隐码，解码重建；流匹配生成
- 借鉴点：identity-motion 分解结构（见 D3）

**VQ 层（离散动作 token）**
- 是什么：VQ-VAE 的离散码本——编码器输出连续向量后，用最近的码本条目替换（直通估计器训练）；码本 = "动作字典"
- 为什么：离散 token 让 L3 聚类/直方图统计天然可做

### A6 无监督行为发现（零训练基线，D3 实施次序）

**UMAP**
- 是什么：流形学习降维——基于模糊单纯集假设，保持数据局部邻接结构，把高维特征投到 2D/低维
- 用途：把运动学特征（速度/关节角/距离）从高维压到低维供聚类

**HDBSCAN**
- 是什么：密度层次聚类——不需要指定簇数 K，自动发现任意形状的簇，并把低密度点标为噪声
- 为什么：行为簇数量未知（不能定 K）、且有噪声帧；HDBSCAN 的"噪声标签"机制天然对应"无法归类的动作"


### L4: 决策树蒸馏与无监督树（2026-09-14 讨论，可选增强）

**接力关系**：发现靠聚类（无监督，找未知），落地靠决策树（有监督，快而可解释）。聚类 + 人工命名后，用 (特征 → 簇名) 训浅决策树：
1. 可解释规则（"位移>50px 且 高度下降 → 跳下"）人可校对
2. 新视频免重新聚类，spot-check CLI 直接前向出动作
3. 特征可换成可读运动学量（速度/体态/空间状态），规则白盒化

**无监督树备选**（不需要标签的树）：① 预测聚类树（按簇内分散度分叉）= HDBSCAN 的可解释替代，适合可读运动学特征；② 隔离森林 = 异常检测（见 behavior-anomaly-detection AN2）；③ 层次聚类树状图 = 多粒度行为层级（粗 3 类/细 10 类按剪枝定），可给可命名率报告加"哪层粒度最易命名"维度。均为可选项，主链不依赖。

### L5: 路线 W——Wav2vec 式域内自监督预训练（2026-09-15 用户提出，参照 Wav2vec2/HuBERT）

**动机（用户指出）**：微调版 v1 的特征被 7 类判别目标拉偏，不是为"编码"而生的 embedding。Wav2vec 2.0 / HuBERT 的启示：好表征来自**自监督目标在无标注数据上的预训练**（contrastive / masked prediction），不来自人工标签。

**路线 W：域内继续预训练（domain-adaptive SSL）**
```
VideoMAE v1/v2 预训练权重（通用起点，即视频界的 Wav2vec）
  → 在我们 ~3k 段无标注视频（79 原始 + 717 cats clips + mammal_v0 2234 段）上
    继续 masked 预训练（VideoMAE 数据高效口径：3.5k 视频 ≈ ViT-B 可训）
  → "懂猫"的自监督编码器（零标签污染）→ 行为素 → 聚类
```
- **目标函数修正（用户定调：重点 = 区分动作，判别式优先）**：masked 重建（VideoMAE 式）偏向外观纹理、不保证动作可分 → 路线 W 首选**判别式自监督目标**：
  - **W1 首选（HuBERT 式）**：窗口聚类造伪行为标签 → 遮窗预测伪标签 → 表征精炼 → 再聚类（迭代）——"行为素"在此自发涌现（原始 VQ 码本设想的自监督回归）
  - **W2 备选（Wav2vec2 式）**：量化潜在码 + InfoNCE 时序对比（正=时间邻域窗，负=跨视频/远时窗）
  - **旁证（LatentSync/SyncNet）**：latent 空间的判别性值得单独建目标——可加判别头，"区分动作"写进损失
  - 验收加一条：**线性可分性**（冻结特征线性探针）必须作为路线 W 的第一道闸门
- 定位：**第二阶段升级路线**——第一阶段货架编码器选型（L1 三候选）先建零成本基线并量化域差；可命名率不达标或需要更强表征时启动 W
- 成本：4090 数小时~1 天（masked 预训练 ViT-B，数据高效口径）；无标注依赖
- 语音类比映射：Wav2vec2 对比目标 ≈ 视频对比系（VideoMoCo 等）；HuBERT masked prediction ≈ VideoMAE/BEiT 系；Wav2Lip 为任务驱动编码器的旁证（非范式）

### L6: 行为素迭代预训练（CatHuBERT 式，2026-09-15 设计定稿——路线 W 的具体实现）

**选型依据**：Wav2vec2（InfoNCE 对比）/ HuBERT（迭代伪标签 masked prediction）/ LatentSync（判别潜空间）三工作的机制映射后，**首选 HuBERT 式**——伪标签 CE 无负样本采样陷阱（行为段相邻窗口同类，对比式易误伤）、更好实现、原论文证明 2 轮迭代即收敛。

**流水线**：
```
第 0 步  全语料窗口特征（一次性 ~1h）：3k 段 × 滑窗(16帧,stride 8) → 宠物微调 v1 骨干（冻结）
         → ~3-5 万窗口特征 (768d)          ※骨干冻结不动
第 1 步  伪行为素：k-means(F, K=256) → 伪标签 z_i（第一代行为素，粗糙无偏）
第 2 步  小 Transformer（4层/384d/<10M 参数）：随机遮连续 4-8 窗（≈2-4s 行为段，mask 率 ~40%）
         → 预测被遮位置的行为素 ID（CE）——"从上下文推断行为"= 判别性写进目标
第 3 步  迭代：Transformer 输出重新聚类 → 第二代行为素 → 回第 2 步（2 轮足够，HuBERT 结论）
```
**产出**：① 行为素序列（离散码 = 行为时间轴雏形）② 连续 embedding（供 UMAP/HDBSCAN/探针）

**为什么恰好对上需求**：判别动作=CE 目标直接产物；未知行为=伪标签由数据聚类决定；行为素/VQ 设想=k-means 量化码的零标注回归；成本低=骨干冻结+小 Transformer（半天内完成两轮迭代）。

**验收闸门**：① 线性可分性（新表征 5 类探针 ≥ 货架编码器基线）② 可命名率 ≥60% ③ 码本健康（前 10% 素占比 <80% 防塌缩）④ **身份泄漏 <1.5× 随机水平**（见 L6b）。

### L6b: 身份-动作解耦（2026-09-15 用户提出：动作不得与具体个体绑定）

**原则：解耦 ≠ 消灭身份**。终局报告需要"哪只猫在干嘛"——正确架构是**分流**：动作通道（行为素 embedding）个体不变；身份走独立支线（spot-check 8.2 登记照检索 / D9），报告层汇合。

**各候选纠缠风险**：DINOv2 最高（Re-ID 王者，花色/体型信息强）；宠物微调 v1 中（可能学到个体捷径）；帧间差分低（运动模式天然无外观）。

**机制（按成本递进，审计驱动）**：
- **第 0 步 审计（必做）**：DINOv2 crop embedding 聚类 → 伪身份标签（个体 A/B/C，无需真名）；审计 伪身份 × 伪行为素 的 NMI——高相关 = 簇按个体而非行为划分 → 触发机制
- **第 1 档 逐个体归一化**：按个体归属（track/视频来源）减去各自特征均值——一阶身份信息（体型/基色）白盒消除
- **第 2 档 对抗去身份（GRL）**：行为素 embedding 挂个体分类器小头 + 梯度反转，拉锯至"猜不出个体"（DANN 标准操作，代价极小）
- **第 3 档 跨个体平衡采样**：迭代重聚类时强制每个伪行为素从所有个体均匀采样——簇定义无法被个体劫持

**验收第 4 闸门**：伪身份小分类器在动作 embedding 上的准确率 < 1.5× 随机水平（多猫审计段上测）。

**参数初值**：K=256 / 遮 4-8 窗 / mask 率 40% / Transformer 4层384d6头 / 2 轮迭代。Wav2vec2 式 InfoNCE 对比留作对照实验。

### L7: 跨域迁移实验（2026-09-15 用户提议）——V-JEPA 2 微调 vs VideoMAE v1 基线

**目的**：量化「人类视频预训练 → 四足动作」的跨域迁移性——V-JEPA 2 到底行不行，用数据说话而非猜测。

**设置**：V-JEPA 2 fpc16（ViT-L，16 帧窗口与行为素窗口对齐）在 pet_action_mammal_v0（2234 clips，7 类）上微调；对照 = VideoMAE v1 基线（同数据同切分的既有 top1）。val top1 对比：V-JEPA 2 ≥ 基线 → 迁移性成立，确立其 CatHuBERT 骨干首选地位；差距显著 → 域差坐实，骨干转向宠物微调 v1。同时兼作路线 4（有监督微调对照）。

**工程**：独立 conda 环境 `pet_vjepa`（clone plf 后仅升级 transformers ≥4.55，不动 plf 本体以保护 GroundingDINO/mmpose）；bf16 + 梯度检查点 + 低学习率（ViT-L 全微调，4090 约 2-4h）；视频解码走 cv2/decord，绕开 torchcodec 依赖。

**顺带产出**：微调后的 V-JEPA 2 即「路线 4 对照分类器」，其冻结特征也加入 L1 选型对比（= 第四个特征候选）。
### L8: TiTok 式双 token 流——身份 register tokens × 动作 tokens（2026-09-15/16 用户提议+联网调研）

**用户提议**：参考 TiTok（32 tokens 承载全图）与后续视频工作，用**外接 extra tokens 提取身份**，另用某种机制提取**逐帧动作**——身份与动作在 token 层面物理分离。

**联网调研谱系（2026-09-16）**：
| 工作 | 出处 | 对我们的启发 |
|---|---|---|
| TiTok "An Image is Worth 32 Tokens" | arXiv 2406.07550（DeepMind） | 1D 极简 token 承载全图信息；masked token 重建 + 量化 |
| 1d-tokenizer | github.com/bytedance/1d-tokenizer（字节） | 1D tokenizer 工程实现 |
| **AdapTok** | arXiv 2505.17011，**CVPR'26**，VisionXLab（README 全文已抓取） | **视频 1D 潜空间 + 时序因果** + 内容自适应 token 预算分配（块级 mask + ILP 评分）；UCF-101/K600 验证；HF 有预训练模型 |
| Register Tokens | arXiv 2309.16588（ICLR'24，**知识库未联网复核**） | 额外低信息 token 吸附全局信息/伪影——"register"机制的出处 |
| V-JEPA 2 | hf-mirror 模型卡（已核实） | latent 预测式骨干，fpc16 与窗口对齐（候选 D） |

**映射到我们的架构（L3 合流自训版的 token 化实现）**：
```
跟随窗口(16帧) → 骨干（V-JEPA 2 fpc16 初始化）
  ├─ 身份 register tokens（K_id≈8-32 个可学习 token，register 风格）
  │    与 patch tokens 共同注意力 → 池化 = E_id → InfoNCE(track 级 ID)
  │    （TiTok/register 思想：紧凑潜码承载个体信息；分流进登记-检索支线）
  └─ 动作 tokens：patch tokens 池化 → VQ 量化 = 行为素 → CatHuBERT 伪标签 CE
       （区分动作；AdapTok 启发：token 预算可内容自适应——静止行为少分配，
        运动行为多分配；一期固定 K_act，自适应留二期）
解耦：E_id × E_mot 正交/GRL 互斥 + 各自监督（L3 合流）
防塌缩辅助（可选）：TiTok 式轻量解码器从双 tokens 重建窗口
  ——辅助损失保证 token 信息完整性；主目标仍为判别式（用户定调）
```

**与 L3 的关系**：L3 的"E_id = 池化+MLP"升级为 register tokens 聚合（注意力式、可控紧凑）；E_mot 不变。不是新路线，是 L3 架构的具体 token 化实现升级。

**验收增补**：E_id 支线可独立评测——用 E_id embedding 做猫个体检索（对应 spot-check 登记需求），检索精度与 DINOv2 crop embedding 基线对比（若接近，则一模型同时出动作+身份两用表征）。
