> ## 谱系溯源（2026-09-16 精读；**2026-09-17 重心转向 FLOAT**）
>

> | **MAR** | arXiv 2406.11838（NeurIPS 2024）| **反面印证：连续 token 无需 VQ**——"discrete-valued space … is not a necessity" |

> **⭐ 为什么 FLOAT 成为主源**（2026-09-17）：
> - 它是**唯一**同时提供"硬分离 + 完整性保障 + 无需对比损失"的方案
> - 身份来自独立输入 → 给定而非推断 → 单猫语料**零额外标注**
> - 正交基容量闸门使"身份装下所有身份信息"**由架构强制成立**
>
> **被否定的方案（记录理由）**：
> - **TivTok SIF 双 token**（暂不采用）：身份改由参考输入提供后，视频内 TIV 与身份通道职责重叠 → 冗余（备档：`papers/docs/tivtok-reference.md`）
> - **`track ID InfoNCE` 作身份主监督**：判别式目标只保证「分得开」不保证「装得下」；FLOAT 全文 `infonce/contrastive` **0 次命中**
> - **任何 VQ / 码本（含 SoftVQ）**：(a) 量化只服务 AR 生成，我们下游全需连续表征；(b) 序列级离散化已由行为聚类（HDBSCAN + 命名）承担；(c) 先例充分（TiTok 官方 VAE 模式重建反而更好 0.84 vs 1.49）
> - **逐图编码后平均（做身份）**：背包式聚合、图与图无交互 → 无法跨视角融合（弱于 register 联合融合，见 T-A5）
> - 双独立编码器：误读 FLOAT；且参数量翻倍
> - 冻结骨干当特征提取器：架构本质是端到端 tokenizer，冻结只是快速验证阶段的策略

## 架构总图

```
原始视频（followcam / mammal_v0 / cats v1）
   │
   ▼
① 背景移除（**`rembg` 类实时小模型**主选，见 pet-background-removal design D2；SAM 已移出抠像）
   ※ 许可分档（架构 §8.1）：交付路径用 🟢 权重；`bria-rmbg` = 🟡 CC BY-NC（科研可用，商用需协议，作对照）
   → 猫本体 + 白背景（纯色常量；损失只在掩码内计算 → 背景色对训练无关）
   │  ※ 理由：followcam 相机随猫移动 → 背景持续变化 →
   │    TivTok 原假设"背景稳定"不成立，若不抠像，
   │    动作通道会把相机运动/场景变化当成"动作"学进去（污染）
   │  ※ 空间上下文（在床上/地上）已由 2.1 multi-object-detect-gate 独立处理，此处不丢信息
   ▼
② 待分析视频（16 帧窗口）→ **视频编码器**：**3D patchify（tubelet t×p×p = 4×8×8）**
   │     ※ t 帧拼三维体再整体切块（借 AdapTok）——运动直接进 patch、token 数降 t 倍
   │     ※ 无量化层——编码器输出即连续潜变量（T-A4b）
   ▼
动作特征 z_j（每 t 帧一份）——「这段时间在动什么」
   │
   ▼
FLOAT/LIA 正交运动基分解（正交坐标系 + **容量闸门**）：
   z_t = Σ_{m=1}^{M} λ_m(t) · v_m
   V = {v_1..v_M} 由 torch.linalg.qr 每次前向强制正交
   λ_m(t) = <z_t, v_m>   ← 正交归一基下坐标 = 内积
   ※ 运动被压到 M 维 → 其余维度只能装外观 → 强制由身份承担（T-A4）
   ▼
λ_m(t) 基元强度序列（可解释，副产品）
   │
   │   ┌──── 参考输入（用户事先拍摄）────┐
   │   │  【形态待决策】A. 高质量多图 / B. 参考视频
   │   │   → 身份编码器 → w_identity（固定向量）   ← T-A5
   │   │  ※ 身份「给定」而非「推断」
   │   └────────────────────────┘
   ▼
解码器 decode(w_identity + Σλ_m(t)·v_m) → 重建第 t 帧
   ※ FLOAT 生成时即"add the source identity latent"到每帧（与 TivTok 的
     Invariant Broadcasting 数学等价 → 迁移平滑）
   训练：同片段内 S→D 重建（FLOAT A.3）——只需"片段→参考"配属，无需正负样本对
   损失：L1 + VGG 多尺度感知 + 对抗（FLOAT 口径；λ1=1, λ2=0.2）
   解耦验证：换参考输入 → 「B 做 A 的动作」（**免费**，见 T-A6）
```

> ⭐ **本文档重心 = FLOAT**（2026-09-17 用户裁定）。TivTok 的 SIF 双 token **暂不采用**——材料已整理到 [`papers/docs/tivtok-reference.md`](../../../papers/docs/tivtok-reference.md)。

### T-A5c: 参考输入架构的落地决定（2026-09-17 裁定）

| # | 问题 | 决定 | 依据 |
|---|---|---|---|
| Q1 | 视频内的 TIV 还需要吗？ | **去掉**（只保留动作通道）| 身份改由参考输入提供后 TIV 冗余；FLOAT 即如此 |
| Q2 | `λ_t` 如何获得多帧时序上下文？ | **由视频编码器整段提特征**（不是"只看本帧"）| FLOAT 的运动 latent 由时序模型在 L 帧上产生；让编码器看全片段即可，**不需 SIF 的局部 scope** |
| Q3 | 参考编码器与视频编码器是否共享权重？ | 待定（训练时试）| 共享省参数、域一致；分开职责分明。若共享则需**两组 register tokens**（身份组 / 运动组），且必须**两次独立前向** |
| Q4 | 多图/短视频参考如何聚合成 `w_identity`？ | **已定：register tokens 跨全部参考 token 联合融合 → 投影成单向量** | 平均是背包式聚合、无法跨视角融合（见 T-A5）|

> **Q1/Q2 的结论已并入 T-A3 改写**；TivTok SIF 正式退出主线。

#### T-A3c: 我们的 proxy 不是生成——重建只是中间任务（用户观察）

**背景**：LIA 的重建路径是「预测光流 → warp 源图及其 `feats`」。它服务的是**生成质量**（外观搬而非合成，重建更容易）与外观搬运；而我们的产出是**动作表征**，重建只是中间的 **proxy 任务**。

**这个观察的两个后果**：

1. **不需要以「重建得像」为目标**，也不需要 LIA 的 warp / `feats` 通道（那是生成导向的机制）——它降低重建难度，但不是我们的目的
2. **但要认清 warp 的另一半**：它是**结构性**屏障——λ 只产出流场，而流场在结构上**无法携带外观**。去掉它，λ 不含身份就只剩「**容量闸门 + 审计**」两层保证（较弱）

**真正的关键动作：换一个适合动作的 proxy**（而不是硬用生成导向那套）：

| proxy 候选 | 特点 | 对身份通道的影响 |
|---|---|---|
| ① 外观重建（现设计）| 需要身份通道当「垃圾桶」吸收外观 | 必须保留 `w_identity` 参与训练 |
| ② 未来帧 / 帧间预测（特征级）| 目标直接是「接下来会怎么动」 | 不再需合成外观 → 身份通道角色弱化 |
| ③ 光流 / 运动自监督 | 纯运动目标，外观结构上进不来 | 完全不需身份通道参与训练 |
| ④ 时序对比 | 学「哪段与哪段像」 | 同上 |

**与 T-A5d 的联动**：选 ②③④ 时，`w_identity` 从「必要零件」降为不必要 → 身份可彻底外挂，与**方案二**天然契合（且比 FLOAT 式重建**简单得多**）。

**代价**：③ 的「运动」定义变窄（像素动态仍含纹理/花纹运动）；少了重建这条「完整信息」保障（但那保障对检索式身份并非必需）。

**待裁定**：proxy 目标族（①②③④ 或组合）+ 身份通道是否参与训练——与 T-A5d 一并定。

#### T-A5d: 身份提取的两个方案——共享对称编码器 vs 外挂编码器（待裁定）

**背景**：FLOAT / LIA 用同一编码器处理参考与驱动，但这**不是**解耦的必要条件。真正保证「动作侧不含身份」的是三件事：① **容量闸门**（动作码只有 M 维正交方向）；② **外观有别的去处**（参考提供外观）；③ **训练压力 + 审计**（重建目标逼着分解成立 + 行为素上的身份泄漏审计）。同一编码器只是让 ①–③ 的循环更自然（且对称、参数共享），并非定理。

| | **方案一：共享对称编码器** | **方案二：外挂编码器** |
|---|---|---|
| 身份来源 | 参考输入走同一套编码器 → register 融合 → `w_identity` | **DINOv2 / DINOv3** 或 **OmniMate 式 VAE 多图编码** → `w_identity` |
| 动作侧目标 | 条件重建（外观必须有去处 → 逼运动进正交基）| 条件重建（外部身份特征当条件）或纯运动自监督 |
| 参数 | 一套参数、两个输入（对称）| 两套模型，各自可换 SOTA |
| 解耦保证 | 同一分解循环 + 闸门 + 审计 | 闸门 + 审计（**失去**「参考也走同一分解」的天然免疫）|
| 风险 | 训练耦合；换基座要重训整条 | 身份编码器可能吸收姿态/运动（需换姿态验证 `w_identity` 稳定性）；两侧特征空间不共享，解码器需 conditioning 适配 |
| 与 Q3 关系 | Q3（是否共享权重）是方案一内部的子问题 | 不涉及 |

**待定**：选哪个方案；若选方案二，身份编码器取 DINOv2/DINOv3 还是 VAE，动作侧目标取条件重建还是纯运动自监督。

**影响面**：动作通道（T-A4）、身份通道（T-A5）、训练流程（T-A7）、评测矩阵（T-A8）；以及《动作识别模型设计》的结构（§5 身份提取需分方案叙述）。

### T-A3: 身份-运动分解骨架（**FLOAT 式**，2026-09-17 重写）

```
身份：参考输入 → 身份编码器 E_id → w_identity ∈ R^d      （固定向量，跨片段不变）
运动：待分析视频（16 帧）→ 视频编码器 E_mot（**整段提特征**）
        → 逐 tubelet 特征 → 正交基投影 → λ_j ∈ R^M（每 t 帧一份，M 维坐标）
重建：decode(w_identity + Σ_m λ_m(t)·v_m) → 第 t 帧
```

**与 FLOAT 的逐项对应**（Eq. 8-9 + A.3）：

| FLOAT | 我们 |
|---|---|
| `w_S = w_{S→r} + w_{r→S}` | `w_identity + Σ λ_m·v_m` |
| `w_{S→r}` 来自源图像 S | `w_identity` 来自参考输入（单图 / 多视角图 / 短视频）|
| `w_{r→S} = Σ λ_m(S)·v_m` | 逐 tubelet `λ_j`（每 t 帧一份；视频编码器 + 正交基投影）|
| 生成时 "add the source identity latent" | 解码器输入 `w_identity + Σλ_m·v_m` |
| 训练：同片段内 S→D 重建（A.3）| 同左 |
| 损失：L1 + VGG 感知 + 部件感知 + 对抗 + FSM | L1 + 感知 + 对抗（**先照 FLOAT 口径**）|

**关键性质**：
- 运动被压在 M 维正交子空间（**容量闸门**）→ 外观无处可藏 → **身份必须完整**（T-A4）
- 身份是**固定常量** → 同一只猫的所有片段共享同一身份条件
- **无 SIF、无 TIV/TV、无 N_TIV/N_TV 超参**（随 TivTok 一并移除）
- 视频编码器**看整段**（Q2）→ `λ_j` 自带时序上下文；**粒度 = tubelet（每 t 帧一份）**，见 《动作识别模型设计》《身份-动作 Tokenizer》§4.2a

### T-A3b: 视频编码器用 **3D patchify（tubelet embedding）**（2026-09-17 新增，借鉴 AdapTok）

**决策**：把 **t 帧拼成三维张量再整体切块**（patch = `t×p×p`，照 AdapTok 口径 `t=4, p=8`），**不逐帧切二维块**。

**为什么明显更好**：
1. **运动直接进 patch**——一个 tubelet 覆盖 t 帧同一空间位置，时间变化被编码进 patch 本身（2D 逐帧切块靠 attention 事后建关系）
2. **降 token 数**——时间维下采样 t 倍 → attention 成本大幅下降
3. **顺带回答 Q2**——**patch 层面就有时序**，不需要“逐帧 local scope”这类特殊设计
4. **与视频 transformer 主流一致**——ViViT / TimeSformer / VideoMAE
5. **补 FLOAT/LIA 的缺口**——它们是**图像**自编码器（逐帧、无时序建模）

**从 AdapTok 可借鉴清单**：

| # | 可借鉴 | 用途 |
|---|---|---|
| 1 | **3D patchify（tubelet）** | 本节 |
| 2 | 12L / 768d / 12heads 规模 | 与主源口径对齐 |
| 3 | 训练配方（L1 + LPIPS + GAN + LeCAM 0.001）| 重建质量基线 |
| 4 | **block-causal attention** | ❌ 不再需要：推理形态已裁定（架构 §1.3）——判别非流式 |
| 5 | 可跑基座（代码+权重+脚本）| 降低工程风险 |
| ❌ | attention mask 框架（`tiv_tv` 等）| SIF 已移除；但 mask 通路本身若走流式仍可复用（见第 4 条）|

**AdapTok 与本设计的粒度差异（两层，均已定）**：

```
AdapTok 的 latent = 1D 全局 token（整段一组 L 个）
我们的 λ          = 逐 tubelet（每 t 帧一份）→ t=4 时 16 帧得 4 个 λ
```

**为什么 `λ` 不逐帧**：① tubelet 覆盖 t 帧 → 编码器输出天然只有 `T/t` 个时间位置；② **运动是过程量，单帧提不出来**（FLOAT 能单帧算 `α` 是因为它要的是「相对参考的姿态偏离」——状态量）。粒度够用：0.13 s/点远细于段边界要求。**λ 时间粒度已定（并入「patch 尺寸」推论）。**

**待定超参**：`M`（正交基元数，默认 32；FLOAT/LIA 用 20）、`d`、视频编码器层数/维度、**patch `t`（默认 4）与 `p`（默认 8）**、窗口长度（16 帧）、参考编码器是否与视频编码器共享权重（Q3）、λ 时间粒度（上述张力）

**⚠️ 阶段 A 的接口问题**：UCF101 没有"参考输入"这种标注形态——但**可以自动构造**（同一视频内取一帧当参考、另一段当驱动），**无需人工标注**（FLOAT 的 A.3 就是这么训练的）。

### T-A4: 动作通道——FLOAT/LIA 正交运动基（用户裁定 2026-09-16）

**机制（LIA 原文 Eq. 3 形式，FLOAT 继承；实现按两仓库源码）**：
```python
# 每个前向传播（LIA styledecoder.py / FLOAT styledecoder.py 实测写法）：
W = nn.Parameter(torch.randn(d, M))    # 可学习基矩阵（d=512, M=20）
Q, _ = torch.linalg.qr(W)              # 硬约束：<v_i, v_j> = δ_ij（列正交归一）
z_t = Q @ λ_t                          # 动作 latent = 正交基元的线性组合
λ_t = Q.T @ z_t                        # 正交归一基下坐标 = 内积（闭式可解）
```

- **论文写 Gram-Schmidt、代码用 QR —— 非矛盾**：Gram-Schmidt 正是计算 QR 分解的算法，是同一数学对象；代码用 LAPACK Householder QR（数值更稳）
- 默认 `M = 32`（正交基元数；LIA/FLOAT 均用 20，我们动作更复杂可调）
- **无正交损失**——QR 是前向硬约束（LIA 损失只有 L1+vgg+adv）
- **符号固定**：若把基冻结为固定组件，须显式固定 Q 的列符号，否则 λ 语义随训练漂移（λ 可学时符号差异被吸收，无需处理）
- M < d 保证可行（M 个方向要求维度足够）——**注意：正交只能约束 M 个方向，不能约束海量码字**（这正是 VQ 码本无法正交的原因，见 T-A4b）
- **关键收益**：`λ_m(t)` 曲线 = 动作基元强度时间序列 → **行为可解释性大幅提升**；聚类可对 λ 向量做；每个 `v_m` 可单独可视化

**身份/动作分离机制**（零构造、**按 FLOAT 源码逐条核对**，2026-09-17 重写）

FLOAT 的真实结构（`models/float/encoder.py` + `styledecoder.py:487`）：

```python
# ① 编码器：三条路径
h_source, feats = self.net_app(img_source)   # 身份 latent（512）+ 多尺度特征 —— 只从 source
h_target, _     = self.net_app(img_drive)
alpha = self.fc(h_target)                    # 运动系数 α（20 维）—— 只从 target

# ② 解码器：身份与运动相加，且源图特征逐层注入做 warp
latent = wa + Σ_m α_m·v_m                    # wa = h_source
for conv1, conv2, to_rgb, to_flow, feat in zip(..., feats):
    out_warp, out, skip_flow, _ = to_flow(out, latent[:, i+2], feat, skip_flow)
```

| 通道 | 内容 | 容量 | 来源 |
|---|---|---|---|
| ① 外观 transport | **`feats`（源图特征金字塔）** | **多层、高分辨率** | 只从 source |
| ② 身份 latent | `wa = h_source` | 512 | 只从 source |
| ③ 运动系数 | `alpha = fc(E(target))` | **20** | 只从 target |

**关键：外观/身份有一条结构上强得多的独立通道（`feats` 逐层注入并参与 warp）→ 运动通道没有动机携带外观。**

**对"身份为何不泄漏"的准确结论——不是架构硬保证**：

| 机制 | 强度 | 说明 |
|---|---|---|
| **身份/外观有独立且高容量通道**（`feats` + `wa`）| **强（结构性）** | 外观由源图特征逐层注入；`alpha` 只是 20 维调制 → 信息论上外观"装不进" alpha |
| **容量闸门** | 强 | 20 维 vs 多层高维特征 |
| **训练时 source 与 target 同个体** | **前提条件（最易漏）** | 只有同个体，源图外观才能替 target 提供外观 → alpha 才无动机带身份。**不同个体则模型被迫把身份塞进 alpha** |
| 正交基残差式分解 | 中 | `w = wa + Σ_m α_m·v_m`，学出的基对齐"共同项 / 偏离项" |
| 实证验证 | — | FLOAT 用可视化 + 消融验证（Fig 11），**不是证明** |

> ⚠️ **`alpha` 是 target 的函数，而 target 里有身份 → 架构上 `alpha` 可以编码身份。** 挡住它的是上述三条的组合，缺一不可，且只能靠**审计**确认（见 §6 评测矩阵）。

#### T-A4c: "同身份"保证的两层结构（2026-09-17 用户追问）

FLOAT A.3 原话：*"reconstructing a driving image D from a source image S, **both sampled from the same video clip**"*（arXiv 2412.01064）。

**第 1 层：配对同身份——训练数据构造要求（我们满足，且 MUST 满足）**

| 阶段 | 配对来源 | 同身份如何保证 |
|---|---|---|
| A（UCF101）| 参考与驱动取自**同一段视频** | 每段单人动作片段 → 天然同一人（**FLOAT 同款做法**）|
| B（猫语料）| 参考来自该猫材料，驱动是该猫视频 | 用户配属；单猫语料天然满足 |

⚠️ **这是前提不是可选项**：配对若不同身份 → 参考的外观不是驱动的外观 → 模型**被迫**把驱动身份塞进 λ → 泄漏是**数学必然**。

**第 2 层：参考与驱动之间的信息隔离——架构级硬保证（与 FLOAT 等价）**

```
w_identity = E_id(参考)          ← 计算图里【没有】驱动视频
λ          = E_mot(驱动视频)      ← 计算图里【没有】参考
```

→ w_identity **架构上不可能**编码驱动视频的运动；λ **架构上不可能**编码参考的身份。**因为是计算图里没有那条边**，不是靠训练压力。
FLOAT 也是同样两条路径（`net_app(source)` / `fc(net_app(target))`）→ **此层与 FLOAT 等价**。

**⚠️ 第 3 点（FLOAT 不需要、我们需要）：参考**自身**的运动可能泄漏**

```
FLOAT：source 与驱动都是单帧 → 参考自身不带运动 → 不存在此问题
我们若选 B（参考视频）：参考自带运动 → registers 可能把【参考自己的运动】吸进 w_identity
                      → w_identity 会加到每一帧 → 注入常量错误运动
```

| 参考形态 | 与 FLOAT 保证的关系 |
|---|---|
| **A 高质量多图** | **完全等价**（静态图无运动可吸）|
| **B 参考视频** | **多一个泄漏面**（参考自身运动），需额外处理：参考分支运动抑制（SIF 式约束 / 训练压力 / 审计）|

**对应审计（都能直接测）**：

| 测什么 | 做法 | 期望 |
|---|---|---|
| λ 不携带身份 | 在 λ 上训个体分类器（喂不同猫）| 接近随机 |
| **w_identity 不携带参考的运动**（**B 形态专属、决定性验收**）| **同一只猫两段运动不同的参考** → `w_identity` 应几乎相同 | 变化量≈0；差异大 = 参考运动泄漏 |

#### T-A4b: 一个源码暴露的分叉——运动系数的时序上下文

FLOAT 的 `alpha = fc(net_app(target))` 是**从单帧**算的：它编码的是"**相对参考的偏离**"，**不是时间导数**；时序动态由 flow-matching transformer 在序列上生成。

我们直接有视频，于是两条路：

| 选项 | λ 的来源 | 语义 | 代价 |
|---|---|---|---|
| ① FLOAT 忠实版（**已不采用**）| 逐帧 `λ = fc(E(x_t))`，帧间**无**上下文 | 「姿态 / 偏离」（状态量）| 抓不到速度方向（走 vs 跑 难分）——**且与 tubelet 矛盾**（见 T-A3b）|
| ② 加时序上下文 | 3D tubelet（t=4）/ 时序注意力 | "运动"（含速度方向）| 略偏离 FLOAT；实现稍复杂 |

**3D patchify（`t=4`）是自然折中**：tubelet 内自带 t 帧上下文，同时保住 per-position 系数的形状。**即：`λ` 的时序上下文是 patch 尺寸 `t` 的推论，不是独立决策。**

### T-A5: 身份通道——**参考输入（= 一段视频）**（用户裁定 2026-09-17）

> **对称架构**：参考与输入视频**共用同一套参数与结构**（FLOAT 即如此——其 `net_app`/`fc` 对 source 与 target 是同一套），差别只在取哪部分输出。
> **参考形态已定 = B（参考视频）**：对称分解使「参考运动污染」不再是问题；视频能覆盖猫前后左右全部方向。
> ⚠️ **隔离约束**：`register` 可 attend patch，但 **patch/tubelet 【不能】attend register**——否则身份信息会流入 λ。详见 《动作识别模型设计》《身份-动作 Tokenizer》§4.6b。

**决策**：身份**不从待分析视频里推断**，而由**独立的参考输入**提供：

```
身份输入（用户事先拍摄）→ 身份编码器 → w_identity（固定向量）
待分析视频       → 动作编码器 → λ 序列（每 t 帧一份，体现运动过程）
重建 = decode(w_identity, λ_t) → 该视频的帧
```

**参考输入三种形态（默认允许，推荐多视角）**：

| 形态 | 说明 | 适用 |
|---|---|---|
| 单张全身图 | 最省事 | 花纹清晰的正面/侧面 |
| **3–5 张多视角图** | **推荐默认** | 猫是**非刚体**，花纹分布在大形变表面，单视角信息不全 |
| 一段参考短视频 | 信息最全 | 用户愿意多拍时 |

**读出机制：register tokens（跨全部参考 token 联合融合）**（2026-09-17 定稿）

```
参考输入（单图 / 多图 / 视频）→ patchify
   ↓ 拼接可学习 register tokens
[register tokens ⊕ 全部输入 tokens] → 编码器 → **只保留 register tokens**
   ↓ 融合完成后投影
w_identity ∈ R^d（单向量）→ 加法分解照旧：decode(w_identity + Σ_m λ_m(t)·v_m)
```

**参考形态：初版只支持一种，二选一待决策（2026-09-17）**

| 选项 | 优势 | 代价 |
|---|---|---|
| **A. 高质量多图**（3–5 张，用户挑清晰多视角）| ① **原理最干净**：身份本质是**时间不变量**，静态图与「身份=常量」语义**完全对齐** → **架构上不存在参考运动污染** ② 质量用户可控 ③ 编码成本低 | ① 依赖用户配合挑图 ② 拍得不好则信息不全 ③ 视角变化不如视频丰富 |
| **B. 参考视频**（一段）| ① **用户成本最低**（随手录）② 视角/光照/姿态变化天然更丰富 ③ **与视频编码器天然同构** | ① ⚠️ **参考运动污染**（register 可能吸收参考运动，而 `w_identity` 会加到每帧）② 需挑窗口/切段 ③ 编码成本高 ④ 质量不可控 |

> **不阻塞架构**：两种形态**共用同一套 register 读出结构**，差异只在输入 token 是「多张静态图」还是「多帧视频」——可先实现结构、形态后定。
> **若选 B 需额外处理**：参考分支的运动抑制（SIF 式约束 / 训练压力 / 分离审计）。

**为什么不用"逐图编码后平均"**（2026-09-17 用户裁定，重要）：

```
平均：      w = (1/N) Σ E(x_i)      ← 各图独立编码再线性组合，图与图【无任何交互】
register：  reg attend 所有图的全部 token ← 可做跨视角关系推理
```

平均是"背包式"聚合（bag-of-frames），**无法**：
- 判断"视图1 的左耳斑块"与"视图2 的右耳斑块"是同一块花纹
- 用另一视角**补全被遮挡**的部位
- **忽略**某视角里的背景/姿态、只挑身份相关区域（池化把空间信息平均掉）

→ 要满足"**身份变量完整得出所有身份相关信息**"这一原始目标，**register 是正确工具，平均弱一档**。先例：TiTok latent tokens / TivTok（扩到视频）/ FlexTok register tokens。

**形状处理（两全）**：register 负责**融合**，融合完**投影成单个 d 维向量**，使加法分解保持 FLOAT 式简单（d=512 对猫外观是充足的——瓶颈在"能看多少视角"，不在"存多少"）。
> 备选：保留 K 个 token 到最后、解码器用 cross-attention（形状自由）。若单向量瓶颈限制明显，再升级。

**⚠️ 必须保留的正确性要求**：身份分支与运动分支**必须独立前向**（身份编码器只吃参考、运动编码器只吃视频）；若合并成一次共享注意力前向，"身份不接触视频"的硬保证会失效。

**⚠️ 参考为视频时的运动污染**：若参考是视频，registers 可能吸收**参考里的运动**，而 `w_identity` 会被加到每一帧 → 注入错误常量运动。
> **缓解**：① 训练时让**参考与驱动来自同一只猫的不同片段**（不是同一片段）——否则参考运动与驱动运动一致，会把泄漏**掩盖**掉（阶段 A 自构造时必须遵守）② 主要靠训练压力排除（参考运动与驱动运动对不上 → 重建变差）③ 若实测污染明显，再在参考分支加 SIF 式约束。

**为什么参考输入比"从视频推断"更好**：

| 维度 | 参考输入 | 从视频推断 |
|---|---|---|
| 身份 latent | **固定常量**（同一参考永远出同一向量）| 随片段浮动 |
| 完整性 | 容量不对称**强制成立** | ❌ 无保障（外观可藏进共享 token）|
| 监督需求 | 只需"片段→参考"的**配属（分区）**；单猫语料**零标注** | 需个体级正负样本对（**我们没有**，见 T-A5b）|
| 跨猫交换验证 | **免费**（直接换参考输入）| 需专门训练目标 |

**为什么身份监督不靠判别式目标**（2026-09-17 裁定，此处集中说明）：

- 判别式目标（如对比损失 / InfoNCE）只保证**分得开**，不保证**装得下**——极端反例：2 维嵌入即可完美区分 2 只猫，但那 2 维几乎不含身份信息；与我们要的"**完整**身份信息"直接冲突
- **只有重建能保证完整**：身份 latent 装不下外观 → 解码器重建失败 → 损失直接惩罚
- **参考事例**：FLOAT 的身份监督完全由重建承担（其损失只有 L1 + VGG 多尺度感知 + 面部部件感知 + 对抗 + FSM）；身份保真度用外部嵌入的余弦相似度（CSIM）**评测**而非训练
- 若日后身份嵌入要用于检索且度量质量不足，可在其上另加度量学习头——那是**下游适配**，不是本 change 的解耦机制

**训练监督**：`decode(参考_cat_i, 片段_j 的运动) → 重建片段 j`，其中片段 j 属于 cat_i。**只需分区，不需正负样本对。**

### T-A5b: 身份监督的数据依赖（决策记录）

**曾被考虑、但判为不可行的方案：用轨迹 id 做对比监督。** 三个致命问题（保留记录，避免重蹈）：
- 管线给的 track id 只有**一个隐式 id**（`argmax(置信度)`）→ 组内**零负样本**
- 语料里**没有个体身份标注**（`cui`/`jiang` 是**两个标注者的名字**，不是两只猫）
- 34 段 followcam 大概率**全是同一只猫** → 若退化到用“视频 id”当标签，会把**同一只猫拆成不同类** → **假负样本，反而有害**

**参考输入方案下这些问题全部消失**：
- 单猫语料：只需**一份参考**，零额外标注
- 多猫语料：只需“片段→参考”的**分区标注**（比正负样本对便宜得多）
- 参考由用户提供时，甚至可先于语料获取（登记照流程）

**降级路径（用户不愿提供参考时）**：从该猫任一清晰片段取一帧当参考——**同一机制，仅参考来源不同**（不引入第二套身份逻辑）。

### T-A6: 损失设计

| 通道 | 损失 |
|---|---|
| 重建 | L1 + perceptual（VGG）+ adversarial（λ₁=1, λ₂=0.2）。⚠️ **只在猫掩码内计算**（masked loss）——抠像后背景是**白色常量**（pet-background-removal D1b），大块常数区域会浪费判别器容量、稀释感知损失；掩码内计算使背景色对训练彻底无关 |
| 动作 | 伪行为素 CE（CatHuBERT K=256）+ 速度匹配 + 平滑正则 |
| 身份 | **无需独立损失**——参考输入（T-A5）+ 容量闸门（T-A4）+ 重建，三者合起来已将身份钉住 |
| 解耦验证 | **跨猫交换重建**：**换参考输入即得**（`decode(参考_B, A 的 λ)` → 应重建“B 做 A 的动作”）——**免费，不需训练目标** |
| 正交 | **无独立损失**（QR 前向硬约束）|
| 可选 | DeRA 式对齐（外观↔DINOv3 / 动作↔V-JEPA 2）；若身份嵌入要用于检索且度量不足，可在其上再加度量学习头——**仅在对问题出现时启用** |

### T-A7: 编码器初始化与训练策略

**V-JEPA 2 的定位修正（2026-09-16）**：V-JEPA 2 **不是编码器初始化**（其 latent 预测目标刻意丢弃像素细节，与重建目标方向相反）。它的位置是：
- **动作流的对齐教师候选**（DeRA 式，替代/并列 InternVideo2）
- **伪行为素标签的特征源**（CatHuBERT 迭代）
- 下游对照候选

**编码器初始化**：阶段 A 从零训 ViT（UCF-101 13320 段足够），或用 **AdapTok（MIT，12L/768d/patch 4×8×8 同形）** 开源权重初始化编码器/解码器块（其 VQ bottleneck 直接旁路）。SoftVQ-VAE 权重不再是首选（其卖点是连续量化器，而我们已去量化）。

| 阶段 | 策略 |
|---|---|
| A | UCF-101 训练（100K 迭代量级，256×256 或 128×128）；bf16 + 梯度检查点 |
| B | 继承 A 权重 → 猫语料微调 + 接入 track ID 监督 |

### T-A4b: 连续潜空间（无量化）——决策 + 先例（2026-09-17 联网核查）

**决策**：**移除全部 VQ / SoftVQ 量化层**；编码器输出连续潜变量，TV 通道经正交基得到连续 λ。

**先例充分（不是我们首创，风险已由他人探明）**：

| 先例 | 事实 | 对我们 |
|---|---|---|
| **TiTok 官方 VAE 模式** | 官方仓库 `quantize_mode: "vae"`（`token_size: 16`，对角高斯 + KL），**已发布预训练权重**（`titok_ll32/bl64/bl128_vae_c16`）| 同结构不用 VQ **是官方支持配置** |
| **TiTok 连续模式重建更好** | ImageNet rFID：BL-128 **VAE 0.84** vs VQ 1.49；BL-64 VAE 1.25 vs VQ 2.06 | 去 VQ **不掉重建质量，反而更好** |
| **TiTok 论文自述** | 结论部分把 "1D-VAE" 列为 tokenizer 的泛化方向 | 官方预留了这条路线 |
| **SoftVQ-VAE 本身** | 论文标题即 "1-Dimensional **Continuous** Tokenizer"；`z_q = Σ p_k·c_k` 是**连续加权和**，前向无 straight-through、无 argmax | **TivTok 的"量化"本就是软的**（TivTok 基于 SoftVQ-VAE 构建）→ 我们的 TivTok 分支去 VQ 是延续而非背离 |
| **MAR** | arXiv 2406.11838："discrete-valued space … is not a necessity for autoregressive modeling"，连续 token + 扩散损失 | 跨领域印证 |
| **AR Video w/o VQ** | arXiv 2412.14169：视频域非量化自回归 | **视频域先例** |
| **TA-TiTok** | 官方声明同时支持 discrete 与 continuous token | 双模式是常态 |

**术语提醒**：文献普遍把 SoftVQ 类输出称作 "quantized / discrete code space"（TivTok 原文亦如此），但**实现是连续的**。读论文时不要被这个词吓住。

**去 VQ 带来的问题（已知，均有对策）**：

| 问题 | 说明 | 对策 |
|---|---|---|
| 失去离散词表 | 不能直接喂 AR next-token 生成 | 我们不依赖它；未来若需生成走 flow matching（FLOAT 路线）|
| 潜空间可能不够结构化 | 无码本约束 → latent 可能各向异性 / 尺度失衡，影响聚类 | (a) KL 正则（TiTok VAE 模式做法）；(b) L2 归一化；(c) 聚类前 whitening/标准化（必须做）|
| 无码本利用率可观测指标 | 失去 perplexity 类诊断 | 用「λ 各维方差谱 + 重激活统计」替代监控 |
| 重建目标可能被低方差维主导 | 连续 latent 的欧氏距离受尺度影响 | 损失端做尺度归一（per-dim 标准化）|

**保留但不作架构主干**：SoftVQ 的软码本可作为**可选正则器**（把 latent 拉向词典流形，利于聚类）——仅在阶段 B 观察到潜空间散乱时启用；**不是 v1 组成部分**。

### T-A8: 评测矩阵

| 维度 | 指标 | 达标参考 |
|---|---|---|
| 重建 | LPIPS / PSNR / rFVD（held-out）| 与 TivTok 报告同量级 |
| 动作判别 | z_t 线性探针 top1（UCF101 101 类 / 猫 5 类）| ≥ 冻结 VideoMAE 基线 |
| **动作可解释** | λ_m(t) 基元强度曲线 + v_m 可视化 | 基元语义可控、可命名 |
| 身份检索 | 同一参考 + 同猫不同片段/视角 → 重建稳定；身份条件本身为固定常量 | 高 |
| **视角无关性** | 同猫不同视角 identity 余弦相似度 | **≥0.7** |
| **身份→动作泄漏** | 在 λ_t 上训个体分类器（喂不同猫的视频）| 接近随机 |
| **动作→身份泄漏** | **固定参考、喂不同动作** → `w_identity` 应**恒定不变** | 变化量≈0 |
| **分离有效性** | **固定动作、换参考** → λ 应**几乎不变** | 变化量≈0 |
| 双向审计合成 | 身份通道不随动作变 + 动作通道不随身份变 | 两者同时成立 |
| 解耦 | 跨猫交换重建质量 | 换身份后外观变、动作保持 |

### T-A9: 待定超参（训练时搜索）

- `N_TIV`（默认 16）、`N_TV`（默认 2）、`M`（默认 32）
- 潜维度 `d`、解码器规模、是否启用 DeRA 对齐
- 分辨率（128 vs 256）、窗口长度（16 帧）

## Risks

| 风险 | 缓解 |
|---|---|
| 抠像质量差（猫毛/遮挡）| 掩码膨胀 + 对误差鲁棒（特征级任务容忍度高）|
| 正交基在猫的大姿态变化下学不出有意义基元 | 备选：降低 M / 退化到软正交（余弦惩罚）|
| **动作分支混入身份**（λ 可被用来判个体）| 容量闸门（M 维）+ **双向泄漏审计**；不过再给 λ 加对抗约束（GRL）。见 T-A4a |
| UCF101（人类）动作基元迁移到猫 | 阶段 B 迁移实验先探；基元数可重训 |
| 训练成本（重建+对抗+双臂）| 阶段 A 先冻结部分模块跑通，再全量 |
| **去 VQ 后潜空间各向异性/尺度失衡** | 沿用 TiTok VAE 模式的 KL 正则；聚类前 whitening；监控 λ 方差谱 |
| **连续 latent 无码本约束 → 可能退化** | 保留 SoftVQ 作可选正则器（训练不稳时启用）；重建+对抗损失本身提供下界 |
| **参考输入与目标猫配属错** | 训练前人工核对配属；单猫语料天然无此问题 |
| **单张参考图信息不足**（猫非刚体、花纹分布在大形变表面）| 默认允许 3–5 张多视角图 / 参考短视频 |
| **用户不愿/忘记拍参考** | 降级：从该猫任一清晰片段取一帧当参考（同一机制）|
