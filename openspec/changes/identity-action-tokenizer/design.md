> **⭐ 为什么 FLOAT 成为主源**（2026-09-17）：
> - 它是**唯一**同时提供"硬分离 + 完整性保障 + 无需对比损失"的方案
> - 身份来自独立输入 → 给定而非推断 → 单猫语料**零额外标注**
> - 正交基容量闸门使"身份装下所有身份信息"**由架构强制成立**
>
> **被否定的方案（记录理由）**：
> - ~~参考帧机制~~ → ✅ **已翻转为默认设定**（2026-09-17 用户裁定）：身份由参考输入（单图 / 3–5 张多视角图 / 短视频）提供。原先引用 TivTok §4.5 的否定理由**不再成立**（我们不再依赖 SIF）
> - 纯 register tokens（Darcet 2024）：图像分割方法，无法"从整段视频整合信息"
> - 双独立编码器：误读 FLOAT；且参数量翻倍
> - **任何 VQ / 码本（含 SoftVQ）**：用户裁定 2026-09-17 全面移除——(a) 量化只服务 AR 生成，我们下游全需连续表征；(b) 序列级离散化已由行为聚类（HDBSCAN + 命名）承担；(c) 先例充分（TiTok 官方 VAE 模式重建反而更好 0.84 vs 1.49；SoftVQ-VAE 本就是 continuous tokenizer）
> - 模型内 VQ 码本做动作监督：由 HuBERT 式离线伪标签 CE 取代（无塌缩风险，**保留**）
> - **`track ID InfoNCE` 作身份主监督**（2026-09-17）：判别式目标只保证"分得开"不保证"装得下"；FLOAT 全文 `infonce/contrastive` **0 次命中**
> - **TivTok SIF 双 token**（2026-09-17，**暂不采用**）：身份改由参考输入提供后，视频内 TIV 与身份通道职责重叠 → 冗余；SIF 的"在同一段视频内分离身份与动作"这一存在意义消失

## 架构总图

```
原始视频（followcam / mammal_v0 / cats v1）
   │
   ▼
① 背景移除（**`rembg` 类实时小模型**主选，见 pet-background-removal design D2；SAM 已移出抠像）
   ※ 许可硬门槛：禁用 rembg 默认模型 `bria-rmbg`（BRIA 商用需付费）
   → 猫本体 + 白背景（纯色常量；损失只在掩码内计算 → 背景色对训练无关）
   │  ※ 理由：followcam 相机随猫移动 → 背景持续变化 →
   │    TivTok 原假设"背景稳定"不成立，若不抠像，
   │    动作通道会把相机运动/场景变化当成"动作"学进去（污染）
   │  ※ 空间上下文（在床上/地上）已由 2.1 multi-object-detect-gate 独立处理，此处不丢信息
   ▼
② 待分析视频（16 帧窗口）→ **视频编码器**：**3D patchify（tubelet t×p×p = 4×8×8）**
   │     ※ t 帧拼三维体再整体切块（借 AdapTok）——运动直接进 patch、token 数降 t 倍
   │     ※ 无量化层——编码器输出即连续潜变量（T-A4b）
   ▼
逐帧 latent z_t ——「这一帧在动什么」
   │
   ▼
FLOAT/LIA 正交运动基分解（正交坐标系 + **容量闸门**）：
   z_t = Σ_{m=1}^{M} λ_m(t) · v_m
   V = {v_1..v_M} 由 torch.linalg.qr 每次前向强制正交
   λ_m(t) = <z_t, v_m>   ← 正交归一基下坐标 = 内积
   ※ 运动被压到 M 维 → 其余维度只能装外观 → 强制由身份承担（T-A4）
   ▼
λ_m(t) 基元强度序列（可解释，副产品）
   │
   │   ┌──── 参考输入（用户事先拍摄）────┐
   │   │  单图 / 3–5 张多视角图 / 短视频
   │   │   → 身份编码器 → w_identity（固定向量）   ← T-A5
   │   │  ※ 身份「给定」而非「推断」
   │   └────────────────────────┘
   ▼
解码器 decode(w_identity + Σλ_m(t)·v_m) → 重建第 t 帧
   ※ FLOAT 生成时即"add the source identity latent"到每帧（与 TivTok 的
     Invariant Broadcasting 数学等价 → 迁移平滑）
   训练：同片段内 S→D 重建（FLOAT A.3）——只需"片段→参考"配属，无需正负样本对
   损失：L1 + VGG 多尺度感知 + 对抗（FLOAT 口径；λ1=1, λ2=0.2）
   解耦验证：换参考输入 → 「B 做 A 的动作」（**免费**，见 T-A6）
```

> ⭐ **本文档重心 = FLOAT**（2026-09-17 用户裁定）。TivTok 的 SIF 双 token **暂不采用**——材料已整理到 [`papers/docs/tivtok-reference.md`](../../../papers/docs/tivtok-reference.md)。

### T-A3: 身份-运动分解骨架（**FLOAT 式**，2026-09-17 重写）

```
身份：参考输入 → 身份编码器 E_id → w_identity ∈ R^d      （固定向量，跨片段不变）
运动：待分析视频（16 帧）→ 视频编码器 E_mot（**整段提特征**）
        → 逐帧 latent → 正交基投影 → λ_t ∈ R^M（M 维坐标）
重建：decode(w_identity + Σ_m λ_m(t)·v_m) → 第 t 帧
```

**与 FLOAT 的逐项对应**（Eq. 8-9 + A.3）：

| FLOAT | 我们 |
|---|---|
| `w_S = w_{S→r} + w_{r→S}` | `w_identity + Σ λ_m·v_m` |
| `w_{S→r}` 来自源图像 S | `w_identity` 来自参考输入（单图 / 多视角图 / 短视频）|
| `w_{r→S} = Σ λ_m(S)·v_m` | 逐帧 `λ_t`（视频编码器 + 正交基投影）|
| 生成时 "add the source identity latent" | 解码器输入 `w_identity + Σλ_m·v_m` |
| 训练：同片段内 S→D 重建（A.3）| 同左 |
| 损失：L1 + VGG 感知 + 部件感知 + 对抗 + FSM | L1 + 感知 + 对抗（**先照 FLOAT 口径**）|

**关键性质**：
- 运动被压在 M 维正交子空间（**容量闸门**）→ 外观无处可藏 → **身份必须完整**（T-A4）
- 身份是**固定常量** → 同一只猫的所有片段共享同一身份条件
- **无 SIF、无 TIV/TV、无 N_TIV/N_TV 超参**（随 TivTok 一并移除）
- 视频编码器**看整段**（Q2）→ `λ_t` 自带时序上下文

### T-A3b: 视频编码器用 **3D patchify（tubelet embedding）**（2026-09-17 新增，借鉴 AdapTok）

**决策**：把 **t 帧拼成三维张量再整体切块**（patch = `t×p×p`，照 AdapTok 口径 `t=4, p=8`），**不逐帧切二维块**。

**为什么明显更好**：
1. **运动直接进 patch**——一个 tubelet 覆盖 t 帧同一空间位置，时间变化被编码进 patch 本身（2D 逐帧切块靠 attention 事后建关系）
2. **降 token 数**——时间维下采样 t 倍 → attention 成本大幅下降
3. **顺带回答 Q2**——**patch 层面就有时序**，不需要“逐帧 local scope”这类特殊设计
4. **与视频 transformer 主流一致**——ViViT / TimeSformer / VideoMAE
5. **补 FLOAT/LIA 的缺口**——它们是**图像**自编码器（逐帧、无时序建模）

**从 AdapTok 可借鉴清单**：

| # | 可借鉴 | 用途 |
|---|---|---|
| 1 | **3D patchify（tubelet）** | 本节 |
| 2 | 12L / 768d / 12heads 规模 | 与主源口径对齐 |
| 3 | 训练配方（L1 + LPIPS + GAN + LeCAM 0.001）| 重建质量基线 |
| 4 | **block-causal attention** | 若走流式/因果推理（§4.5 C18 选项①）——现成 |
| 5 | 可跑基座（代码+权重+脚本）| 降低工程风险 |
| ❌ | attention mask 框架（`tiv_tv` 等）| SIF 已移除；但 mask 通路本身若走流式仍可复用（见第 4 条）|

**⚠️ 一个待解张力**：AdapTok 的 latent 是 **1D 全局 token**（整段一组 L 个），而我们要**逐帧 `λ_t`**：

```
t=4 → 16 帧片段只有 16/4 = 4 个时间位置 → λ 的时间粒度 = 4 帧（非逐帧）
```

候选解法（待定）：① 接受 4 帧粒度 ② tubelet 序列 → 逐帧头（读出后上采样）③ 动作分支用 `t=1` patch（损失部分效率）

**待定超参**：`M`（正交基元数，默认 32；FLOAT/LIA 用 20）、`d`、视频编码器层数/维度、**patch `t`（默认 4）与 `p`（默认 8）**、窗口长度（16 帧）、参考编码器是否与视频编码器共享权重（Q3）、λ 时间粒度（上述张力）

**⚠️ 阶段 A 的接口问题**：UCF101 没有"参考输入"这种标注形态——但**可以自动构造**（同一视频内取一帧当参考、另一段当驱动），**无需人工标注**（FLOAT 的 A.3 就是这么训练的）。

### T-A4: 动作通道——FLOAT/LIA 正交运动基（用户裁定 2026-09-16）

**机制（LIA 原文 Eq. 3 形式，FLOAT 继承；实现按两仓库源码）**：
```python
# 每个前向传播（LIA styledecoder.py / FLOAT styledecoder.py 实测写法）：
W = nn.Parameter(torch.randn(d, M))    # 可学习基矩阵（d=512, M=20）
Q, _ = torch.linalg.qr(W)              # 硬约束：<v_i, v_j> = δ_ij（列正交归一）
z_t = Q @ λ_t                          # 动作 latent = 正交基元的线性组合
λ_t = Q.T @ z_t                        # 正交归一基下坐标 = 内积（闭式可解）
```

- **论文写 Gram-Schmidt、代码用 QR —— 非矛盾**：Gram-Schmidt 正是计算 QR 分解的算法，是同一数学对象；代码用 LAPACK Householder QR（数值更稳）
- 默认 `M = 32`（正交基元数；LIA/FLOAT 均用 20，我们动作更复杂可调）
- **无正交损失**——QR 是前向硬约束（LIA 损失只有 L1+vgg+adv）
- **符号固定**：若把基冻结为固定组件，须显式固定 Q 的列符号，否则 λ 语义随训练漂移（λ 可学时符号差异被吸收，无需处理）
- M < d 保证可行（M 个方向要求维度足够）——**注意：正交只能约束 M 个方向，不能约束海量码字**（这正是 VQ 码本无法正交的原因，见 T-A4b）
- **关键收益**：`λ_m(t)` 曲线 = 动作基元强度时间序列 → **行为可解释性大幅提升**；聚类可对 λ 向量做；每个 `v_m` 可单独可视化

**身份/动作分离机制**（三层，必须分清，2026-09-17 重写）：

1. **SIF attention scope**（TIV 看全段 / TV 只看本帧）——把“时间不变”与“时间可变”分开
2. **正交基容量闸门**（`z_t = Q·λ`，运动 ≤ M 维）——**逼身份通道承担全部外观信息**
3. **参考输入**（T-A5）——身份“给定”而非“推断”，架构硬分离

> ⚠️ **正交基的首要作用是容量闸门，不是可解释性**（2026-09-17 修正）
>
> FLOAT 的身份**完整性**靠的是：运动被限制在 M=20 维正交子空间 → 其余 ~492 维**只能装外观** → 解码器要能重建这只人，身份 latent 就必须完整。
>
> 我们的 TV 若不受限（每帧 2×768 维），外观会藏进 TV → 重建**不再要求**身份完整。所以 `z_t = Σ λ_m·v_m` 是**机制必需**（不是可选项），λ 曲线可读只是副产品。
>
> 另：FLOAT 的分解是 `w_S = w_{S→r}(身份) + w_{r→S}(运动)`，身份 = **减掉运动子空间分量后的残差**；`w_{S→r}` 来自**源图像 S**（独立输入），不是从驱动视频推断。

### T-A5: 身份通道——**参考输入（默认设定）**（用户裁定 2026-09-17）

**决策**：身份**不从待分析视频里推断**，而由**独立的参考输入**提供：

```
身份输入（用户事先拍摄）→ 身份编码器 → w_identity（固定向量）
待分析视频       → 动作编码器 → λ_t（逐帧运动）
重建 = decode(w_identity, λ_t) → 该视频的帧
```

**参考输入三种形态（默认允许，推荐多视角）**：

| 形态 | 说明 | 适用 |
|---|---|---|
| 单张全身图 | 最省事 | 花纹清晰的正面/侧面 |
| **3–5 张多视角图** | **推荐默认** | 猫是**非刚体**，花纹分布在大形变表面，单视角信息不全 |
| 一段参考短视频 | 信息最全 | 用户愿意多拍时 |

**为什么参考输入比“从视频推断”更好**：

| 维度 | 参考输入 | 从视频推断 |
|---|---|---|
| 身份 latent | **固定常量**（同一参考永远出同一向量）| 随片段浮动 |
| 完整性 | 容量不对称**强制成立** | ❌ 无保障（外观可藏进 TV）|
| 监督需求 | 只需“片段→参考”的**配属（分区）**；单猫语料**零标注** | 需个体级正负样本对（**我们没有**，见 T-A5b）|
| 跨猫交换验证 | **免费**（直接换参考输入）| 需专门训练目标 |

**为什么身份监督不靠判别式目标**（2026-09-17 裁定，此处集中说明）：

- 判别式目标（如对比损失 / InfoNCE）只保证**分得开**，不保证**装得下**——极端反例：2 维嵌入即可完美区分 2 只猫，但那 2 维几乎不含身份信息；与我们要的"**完整**身份信息"直接冲突
- **只有重建能保证完整**：身份 latent 装不下外观 → 解码器重建失败 → 损失直接惩罚
- **参考事例**：FLOAT 的身份监督完全由重建承担（其损失只有 L1 + VGG 多尺度感知 + 面部部件感知 + 对抗 + FSM）；身份保真度用外部嵌入的余弦相似度（CSIM）**评测**而非训练
- 若日后身份嵌入要用于检索且度量质量不足，可在其上另加度量学习头——那是**下游适配**，不是本 change 的解耦机制

**训练监督**：`decode(参考_cat_i, 片段_j 的运动) → 重建片段 j`，其中片段 j 属于 cat_i。**只需分区，不需正负样本对。**

### T-A5b: 身份监督的数据依赖（决策记录）

**曾被考虑、但判为不可行的方案：用轨迹 id 做对比监督。** 三个致命问题（保留记录，避免重蹈）：
- 管线给的 track id 只有**一个隐式 id**（`argmax(置信度)`）→ 组内**零负样本**
- 语料里**没有个体身份标注**（`cui`/`jiang` 是**两个标注者的名字**，不是两只猫）
- 34 段 followcam 大概率**全是同一只猫** → 若退化到用“视频 id”当标签，会把**同一只猫拆成不同类** → **假负样本，反而有害**

**参考输入方案下这些问题全部消失**：
- 单猫语料：只需**一份参考**，零额外标注
- 多猫语料：只需“片段→参考”的**分区标注**（比正负样本对便宜得多）
- 参考由用户提供时，甚至可先于语料获取（登记照流程）

**降级路径（用户不愿提供参考时）**：从该猫任一清晰片段取一帧当参考——**同一机制，仅参考来源不同**（不引入第二套身份逻辑）。

### T-A6: 损失设计

| 通道 | 损失 |
|---|---|
| 重建 | L1 + perceptual（VGG）+ adversarial（λ₁=1, λ₂=0.2）。⚠️ **只在猫掩码内计算**（masked loss）——抠像后背景是**白色常量**（pet-background-removal D1b），大块常数区域会浪费判别器容量、稀释感知损失；掩码内计算使背景色对训练彻底无关 |
| 动作 | 伪行为素 CE（CatHuBERT K=256）+ 速度匹配 + 平滑正则 |
| 身份 | **无需独立损失**——参考输入（T-A5）+ 容量闸门（T-A4）+ 重建，三者合起来已将身份钉住 |
| 解耦验证 | **跨猫交换重建**：**换参考输入即得**（`decode(参考_B, A 的 λ)` → 应重建“B 做 A 的动作”）——**免费，不需训练目标** |
| 正交 | **无独立损失**（QR 前向硬约束）|
| 可选 | DeRA 式对齐（外观↔DINOv3 / 动作↔V-JEPA 2）；若身份嵌入要用于检索且度量不足，可在其上再加度量学习头——**仅在对问题出现时启用** |

### T-A7: 编码器初始化与训练策略

**V-JEPA 2 的定位修正（2026-09-16）**：V-JEPA 2 **不是编码器初始化**（其 latent 预测目标刻意丢弃像素细节，与重建目标方向相反）。它的位置是：
- **动作流的对齐教师候选**（DeRA 式，替代/并列 InternVideo2）
- **伪行为素标签的特征源**（CatHuBERT 迭代）
- 下游对照候选

**编码器初始化**：阶段 A 从零训 ViT（UCF-101 13320 段足够），或用 **AdapTok（MIT，12L/768d/patch 4×8×8 同形）** 开源权重初始化编码器/解码器块（其 VQ bottleneck 直接旁路）。SoftVQ-VAE 权重不再是首选（其卖点是连续量化器，而我们已去量化）。

| 阶段 | 策略 |
|---|---|
| A | UCF-101 训练（100K 迭代量级，256×256 或 128×128）；bf16 + 梯度检查点 |
| B | 继承 A 权重 → 猫语料微调 + 接入 track ID 监督 |

### T-A4b: 连续潜空间（无量化）——决策 + 先例（2026-09-17 联网核查）

**决策**：**移除全部 VQ / SoftVQ 量化层**；编码器输出连续潜变量，TV 通道经正交基得到连续 λ。

**先例充分（不是我们首创，风险已由他人探明）**：

| 先例 | 事实 | 对我们 |
|---|---|---|
| **TiTok 官方 VAE 模式** | 官方仓库 `quantize_mode: "vae"`（`token_size: 16`，对角高斯 + KL），**已发布预训练权重**（`titok_ll32/bl64/bl128_vae_c16`）| 同结构不用 VQ **是官方支持配置** |
| **TiTok 连续模式重建更好** | ImageNet rFID：BL-128 **VAE 0.84** vs VQ 1.49；BL-64 VAE 1.25 vs VQ 2.06 | 去 VQ **不掉重建质量，反而更好** |
| **TiTok 论文自述** | 结论部分把 "1D-VAE" 列为 tokenizer 的泛化方向 | 官方预留了这条路线 |
| **SoftVQ-VAE 本身** | 论文标题即 "1-Dimensional **Continuous** Tokenizer"；`z_q = Σ p_k·c_k` 是**连续加权和**，前向无 straight-through、无 argmax | **TivTok 的"量化"本就是软的**（TivTok 基于 SoftVQ-VAE 构建）→ 我们的 TivTok 分支去 VQ 是延续而非背离 |
| **MAR** | arXiv 2406.11838："discrete-valued space … is not a necessity for autoregressive modeling"，连续 token + 扩散损失 | 跨领域印证 |
| **AR Video w/o VQ** | arXiv 2412.14169：视频域非量化自回归 | **视频域先例** |
| **TA-TiTok** | 官方声明同时支持 discrete 与 continuous token | 双模式是常态 |

**术语提醒**：文献普遍把 SoftVQ 类输出称作 "quantized / discrete code space"（TivTok 原文亦如此），但**实现是连续的**。读论文时不要被这个词吓住。

**去 VQ 带来的问题（已知，均有对策）**：

| 问题 | 说明 | 对策 |
|---|---|---|
| 失去离散词表 | 不能直接喂 AR next-token 生成 | 我们不依赖它；未来若需生成走 flow matching（FLOAT 路线）|
| 潜空间可能不够结构化 | 无码本约束 → latent 可能各向异性 / 尺度失衡，影响聚类 | (a) KL 正则（TiTok VAE 模式做法）；(b) L2 归一化；(c) 聚类前 whitening/标准化（必须做）|
| 无码本利用率可观测指标 | 失去 perplexity 类诊断 | 用「λ 各维方差谱 + 重激活统计」替代监控 |
| 重建目标可能被低方差维主导 | 连续 latent 的欧氏距离受尺度影响 | 损失端做尺度归一（per-dim 标准化）|

**保留但不作架构主干**：SoftVQ 的软码本可作为**可选正则器**（把 latent 拉向词典流形，利于聚类）——仅在阶段 B 观察到潜空间散乱时启用；**不是 v1 组成部分**。

### T-A8: 评测矩阵

| 维度 | 指标 | 达标参考 |
|---|---|---|
| 重建 | LPIPS / PSNR / rFVD（held-out）| 与 TivTok 报告同量级 |
| 动作判别 | z_t 线性探针 top1（UCF101 101 类 / 猫 5 类）| ≥ 冻结 VideoMAE 基线 |
| **动作可解释** | λ_m(t) 基元强度曲线 + v_m 可视化 | 基元语义可控、可命名 |
| 身份检索 | 同一参考 + 同猫不同片段/视角 → 重建稳定；身份条件本身为固定常量 | 高 |
| **视角无关性** | 同猫不同视角 identity 余弦相似度 | **≥0.7** |
| 身份泄漏 | z_t / λ 上训个体分类器 | 接近随机 |
| 解耦 | 跨猫交换重建质量 | 换身份后外观变、动作保持 |

## Risks

| 风险 | 缓解 |
|---|---|
| 抠像质量差（猫毛/遮挡）| 掩码膨胀 + 对误差鲁棒（特征级任务容忍度高）|
| 正交基在猫的大姿态变化下学不出有意义基元 | 备选：降低 M / 退化到软正交（余弦惩罚）|
| TIV tokens 抓不到"个体身份"（只抓到"猫"这个类别）| 加 track ID 监督（本设计已含）；阶段 B 实测 |
| UCF101（人类）动作基元迁移到猫 | 阶段 B 迁移实验先探；基元数可重训 |
| 训练成本（重建+对抗+双臂）| 阶段 A 先冻结部分模块跑通，再全量 |
| **去 VQ 后潜空间各向异性/尺度失衡** | 沿用 TiTok VAE 模式的 KL 正则；聚类前 whitening；监控 λ 方差谱 |
| **连续 latent 无码本约束 → 可能退化** | 保留 SoftVQ 作可选正则器（训练不稳时启用）；重建+对抗损失本身提供下界 |
| **参考输入与目标猫配属错** | 训练前人工核对配属；单猫语料天然无此问题 |
| **单张参考图信息不足**（猫非刚体、花纹分布在大形变表面）| 默认允许 3–5 张多视角图 / 参考短视频 |
| **用户不愿/忘记拍参考** | 降级：从该猫任一清晰片段取一帧当参考（同一机制）|
