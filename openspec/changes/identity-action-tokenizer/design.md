# Design: identity-action-tokenizer

> 继承总管 D3（双分解）、D5/D6；谱系调研见 video-feature-latent design L5/L6/L8（Wav2vec2/HuBERT/LatentSync/TiTok/AdapTok/Register Tokens/1d-tokenizer，2026-09-15/16 联网调研）。
>
> **架构范式（2026-09-16 用户裁定）**：FLOAT 真正范式 = **"一个模型同时提取，在末尾拆成两个"**——
> 共享骨干产生统一表征，身份/动作用不同 head + 不同输入视角 + 不同损失在末端分叉。
> 视角无关性的核心是"身份只用参考帧"（FLOAT 关键机制）。

## 架构总图（FLOAT 真正范式 × TiTok 结构）

```
                        16 帧视频
                            │
                            ▼
              共享视觉编码器（V-JEPA 2 / VideoMAE，先冻结后解冻）
                输出时空 patch tokens（统一表征）
                            │
              ┌─────────────┴─────────────┐
              │ TiTok 式瓶颈交叉注意力       │
              │ （统一压缩通道，信息分拣）  │
              └─────────────┬─────────────┘
                            │
              ┌─────────────┴─────────────┐
              ↓                           ↓
        身份 head（专用）              动作 head（专用）
   ┌──────────────────────┐    ┌──────────────────────┐
   │ 输入：参考帧聚合      │    │ 输入：每帧查询        │
   │ （从 16 帧中选        │    │ （从 patch tokens 提   │
   │   1-2 帧最清晰帧）    │    │   每帧时序信息）       │
   │ + 多裁剪/随机擦除/   │    │ + 帧差分增强          │
   │   颜色抖动            │    │                      │
   ├──────────────────────┤    ├──────────────────────┤
   │ ArcFace 角度间隔损失  │    │ 伪行为素 CE           │
   │ InfoNCE(track ID)     │    │ 速度匹配 + 平滑       │
   │ 跨视频 ReID 扩展      │    │                      │
   └──────────────────────┘    └──────────────────────┘
              ↓                           ↓
        K_id (32-d,                 z_1..z_T
        视角无关)                    (32-d/帧, 无外观)
              │                           │
              └────────────┬──────────────┘
                           ▼
              轻量解码器 G(K_id, z_t)
                           │
                    重建 16 帧视频
                    L1 + LPIPS + 跨猫交换重建
```

**FLOAT 风格的关键（用户裁定）**：

| 原则 | 体现 |
|---|---|
| **同一个模型同时提取** | 共享视觉编码器（V-JEPA 2 / ViT）一次性出全部 patch tokens |
| **末尾分叉成两个** | 身份 head（参考帧+ArcFace） vs 动作 head（逐帧+CatHuBERT） |
| **输入视角不同** | 身份只看 1-2 帧（参考帧机制）vs 动作看整段时序 |
| **骨干参数共享，head 参数独立** | 参数量中骨干占大头，head 轻量分离 |
| **损失层面解耦** | 不同 head 各自独立损失 + 跨猫交换重建验证解耦 |

## Decisions

### T-A1: 两阶段数据策略（用户指定：先人类后动物）

| 阶段 | 数据 | 规模 | 目的 |
|---|---|---|---|
| A 人类 | **UCF101**（13320 段，9.5GB，**已在 NAS `/home/wyy/mnt/ucf101/UCF-101`**） | 大两个数量级 | 架构可行性、重建质量、z_t 判别性——**不受猫数据量制约** |
| B 猫 | mammal_v0 2234 + cats v1 717 + 34 followcam + 79 events | ~3k 段 | 域迁移 + 身份监督（我们的猫有登记/track ID） |

UCF101 上身份监督弱（无个体标注）→ 阶段 A 只验证**架构**（重建 + 动作判别 + token 瓶颈有效性）；身份解耦的完整验证在阶段 B（有真身份标签）。

### T-A2: 损失设计

**两条专用分支，各自独立损失；重建损失作为融合监督**

**身份分支损失**：
- **ArcFace 角度间隔损失**（主）：在归一化超球面上，类间加角度 margin（m=0.5，s=30）→ 角度空间判别天然视角鲁棒
- **InfoNCE（辅）**：track 级对比，τ=0.07；memory bank ≥4096；硬负样本挖掘
- **跨视频 ReID 扩展**：注册猫（猫 A 跨日所有视频）= 天然正样本
- 辅助：随机擦除（遮挡鲁棒）+ 颜色抖动（颜色不变性）+ 多裁剪增强（视角/尺度不变性）

**动作分支损失**：
- 迭代伪行为素 CE（CatHuBERT，K=256）——**取代总管 D3 原始的模型内 VQ 码本**（判别式更直接、无塌缩风险；VQ-VAE 量化留作备选）
- 速度匹配 + 平滑正则（总管 D3 遗产）
- 帧差/光流输入 → 动作分支**天然不带外观**（FLOAT 核心机制）

**融合/解码损失**：
- 重建：L1 + LPIPS（TiTok 口径；对抗损失二期可选）
- **跨猫交换重建**（关键解耦闸门）：猫 A 的 z_t × 猫 B 的 K_id → 重建出"B 做 A 的动作"——像素级强制 K_id 编码外观、z_t 编码动作
- 身份 token dropout（10-20%）：逼解码器不能依赖 K_id 存动作信息
- e_id × z_t 正交惩罚（辅助）：保子空间不互相渗透

**三损失分工**：
1. 身份分支损失 → 让 K_id 学会"是哪只猫"（特征空间）
2. 动作分支损失 → 让 z_t 学会"在做什么动作"（特征空间）
3. 融合/解码损失 → 验证 K_id + z_t 信息完备且解耦（像素空间，FLOAT 的核心）

### T-A3: 结构定位与训练策略（2026-09-16 用户澄清）

**结构本质 = TiTok 端到端 tokenizer**（瓶颈 token 注意力 + 轻量解码器 + 像素重建），
V-JEPA 2 **仅是编码器的初始化来源**，"冻结"是分阶段训练策略而非模型结构：

| 阶段 | 编码器状态 | 目的 |
|---|---|---|
| A1 快速验证 | **冻结**（缓存 patch features，只训瓶颈注意力+解码器） | 数小时内验证架构/损失/瓶颈有效性，低风险 |
| A2 端到端 | **全量解冻**（V-JEPA 2 权重初始化，联合微调，LR 小 10×） | 消除"冻结特征缺像素细节→重建模糊"的结构性上限 |
| B 猫语料 | 继承 A2 端到端权重继续训 | 域迁移 + 身份监督接入 |

- **消融要求**：A1 vs A2 重建质量对比（LPIPS/PSNR）必须实测，冻结若够用也可停在 A1
- bf16 + 梯度检查点；K_id=32、z_t=32d、解码器 ViT-S 级
- 重建目标 = **原始视频像素**（用户指定；区别于 D3 修订版的特征序列重建）
- 16 帧窗口训练、推理可滑窗
- **FLOAT 范式训练调度**：共享骨干 LR 10⁻⁵（小 10×，微调模式）、身份 head LR 10⁻⁴、动作 head LR 10⁻³、解码器 LR 5×10⁻⁴。骨干参数共享 → 节省一半存储；head 分离保证各自任务专注。
- **AdapTok 关系备注**：AdapTok = TiTok 家族的自适应 token 预算（按内容复杂度分配 token 数）；v1 固定 K_id=32，自适应预算列为 v2 增强候选，不进本 change 范围

### T-A4: 评测矩阵

| 维度 | 指标 | 达标参考 |
|---|---|---|
| 重建 | LPIPS/PSNR（held-out） | 定性可用 + 与 token 数的缩放曲线 |
| 动作判别 | z_t 线性探针 top1（UCF101 101 类 / 猫 5 类） | ≥ 冻结 VideoMAE 基线的可比水平 |
| **身份检索** | e_id 最近邻检索准确率（阶段 B，猫同身份跨帧/跨视频）| **高**（身份信息该在 e_id 里） |
| **视角无关性** | **e_id 在同猫不同视角/裁剪下的一致性**（cos sim ≥ 阈值）| **关键闸门**：必须跨视角鲁棒 |
| 身份泄漏 | z_t 上训个体分类器 | 接近随机（动作不含身份） |
| 解耦 | 跨身份交换重建质量 | 换身份后外观变、动作保持 |

**新增视角无关性测试方法**：取同猫不同视角/距离/光照的多段视频，提取 K_id，计算跨视角余弦相似度——若 <0.7 则视角无关性失败，需加强 ID 分支增强（更多裁剪 / 颜色抖动）或考虑用专用 ReID backbone（如 MegaDescriptor）替代 V-JEPA 2 的 ID 头输入。

### T-A5: 视角无关性策略（FLOAT 核心 = 参考帧机制）

**核心机制**：身份 head 只输入 1-2 帧（"参考帧"），不看整段视频——FLOAT 原文中由一张静态参考图提取身份 embedding，
**绕开视角问题的最直接方式就是不要让身份看完整视频**。

| 机制 | 做法 | 目的 |
|---|---|---|
| **参考帧机制（核心）** | 训练时随机选 1-2 帧作为身份 anchor；测试时也只对单帧提身份 | FLOAT 核心——选最清晰的一帧 → 视角问题天然绕开 |
| **多裁剪增强** | 同猫不同视角/裁剪/尺度 → 应有相同 K_id | 强化视角不变 |
| **ArcFace 角度间隔** | 角度空间而非欧氏空间，天然视角鲁棒 | 几何层面视角无关 |
| **随机擦除（Cutout）**| ReID 标准增强，ID 不应被遮挡破坏 | 鲁棒性 |
| **颜色抖动** | ID 不应依赖具体颜色（避免"橘猫 ID 绑定橘色"）| 不变性 |
| **ReID 骨干备选** | 若 V-JEPA 2 + ArcFace 头不够，可换 MegaDescriptor/OSNet 等专用 ReID 网络 | 退路 |

## Risks

- 冻结骨干特征缺像素细节 → 重建模糊 → 解冻末层/加大解码器（成本↑）
- z_t 塌缩吸收身份 → 身份 dropout + 交换重建 + GRL 三重防线 + **架构层面身份只取参考帧**（不接触全段），泄漏风险天然降低
- UCF101 阶段学到的"动作"以人类为中心 → 阶段 B 迁移损耗（先探针量化）
- **视角无关性不达标** → 加强 ID head 增强 / 换 ReID 骨干（OSNet/MegaDescriptor）
- **FLOAT 范式（共享骨干+分叉 head）计算成本适中**——骨干共享节省一半存储，head 轻量分离
