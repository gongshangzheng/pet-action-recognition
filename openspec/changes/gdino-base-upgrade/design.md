## Context

动机见 [proposal.md](proposal.md)。与本 change 直接相关的事实（2026-11-07 实测）：

- **tiny 教师的四类失败**（`multi-pet-sort-tracking` 2.4/3.7 与 `gdino-distill-yolo-detector` 3.3 实证）：
  1. 印刷动物误检：`charw1g_0713` 袋面金毛被判活狗，稳定 23 锚点、置信 0.54；真猫反而置信 0.331 低于三条误检。
  2. 嵌套重复：同一只猫紧框+松框（IoS≈1.0、IoU≈0.48，NMS 阈值以下），单目标画面锚点约 9% 出现。
  3. 物种抖动：真猫部分锚点被判 dog，硬分实例下造成身份断裂。
  4. 真猫漏检：`charw1g_0713` 那只猫覆盖率仅 54%。
- **这些失败已进入 YOLO 学生**：学生 mAP@0.5=0.809 是对教师的循环一致率；失效抽样显示学生既漏 1 也多检 4，方向无人工 GT 不可判。
- **覆盖缺口**：cat_raw 共 2,737 段，tiny 缓存只有 2,573 段（差 164 段）。
- **速度基准**：tiny 约 150 ms/锚点（stride=2 批次实测）；全量 stride=5 历史 4h17m。base 参数约 5×，推理估 3–4×（450–600 ms/锚点）。
- **环境**：pet 的死代理 `http_proxy=127.0.0.1:7890` 需清掉后直连下载；`plf` 环境的 transformers 已支持 GroundingDINO（tiny 即用此 API），base 只换 checkpoint，无需新依赖。
- **用户裁定**：检测范围为**全视频**（与现有口径一致；区间外帧是负样本与进出过渡来源）；额外类目首轮不加（只 cat/dog），类目扩展作为后续独立消融。

## Goals / Non-Goals

**Goals**

- 用量化闸门回答"base 是否比 tiny 好"，闸门未过则止损。
- 闸门通过后：全量重跑（含补齐 164 段）→ 新数据集 → 重训 YOLO → 三方对照。

**Non-Goals**

- 不加额外检测类目（家具/食盆等留作后续消融）。
- 不做人工框标注（仍是伪标签蒸馏；人工框是另一条线）。
- 不替换生产检测链路；tiny 缓存与其全部下游结论保留不动。
- 不改 stride（维持 5；`multi-pet-sort-tracking` 3.9 已证加密无收益）。

## Decisions

### 4.1 闸门判据事先写定（对照小批）

> **方案：** 在 3 段已人工核对视频（`charw1g_0713` / `event_20260807_033836` / `event_20260618_233630`，共约 160 锚点）上逐锚点跑 base 与 tiny，按下表判据裁决。**判据在跑之前写死，跑后不得调整。**

| # | 判据 | 达标线 | 权重 |
|---|---|---|---|
| G1 | 印刷金毛段：印刷物区域内的检出锚点数 | base < tiny（减少即算） | 核心 |
| G2 | `033836` 真猫：物种抖动锚点数（被判 dog 的锚点） | base ≤ tiny | 核心 |
| G3 | `033836` 真猫：嵌套重复对数（IoS≥0.8） | base ≤ tiny | 核心 |
| G4 | `0618` 双猫：两段轨迹的锚点覆盖 | base ≥ tiny | 参考 |
| G5 | 速度：ms/锚点 | 如实记录（不设线，供全量成本估算） | 参考 |

**裁决规则：三条核心判据（G1–G3）全部达标 → 启动全量；任一未达标 → 收口并记录数字。** 参考项不阻塞，但必须写入报告。

**理由：** tiny 的失败里，印刷动物与物种抖动是「错误」，嵌套重复是「噪声」，三者若 base 都不改善，说明失败源于开放词表检测器的原理而非模型容量——换大模型无意义，应转人工框或检测后处理路线。

**风险：** 3 段样本小，G1 只有约 43 个锚点里的印刷物检出可数——结论标注样本量，不外推到全量。

### 4.2 全量重跑口径冻结

> **方案：** 全视频、stride=5、box_threshold=0.3、text_threshold=0.3、prompt 与 tiny 完全一致；含补齐的 164 段，共 2,737 段。产物 `results/cat_crop_classification/gdino-crop-20261103a/assets/full_run_base/detections/`（新目录）。

**理由：** 与 tiny 缓存逐段可比；区间外帧保留（负样本 + 进出过渡）。

**执行约束：** 全量估 13–17 小时，远超单次守卫 3 小时上限 → 按视频清单分批（每批 ≤2.5 小时），批次间重新预检；用日志标志（BATCH DONE）防重复跑。

### 4.3 新数据集：指纹触发重建 + 提帧扩量

> **方案：** 复用 `export_pseudo_labels.py`（已内建指纹前置校验，不一致即拒绝）。`--max-frames-per-video` 从 8 提到 **20**（预期约 5 万帧 / 3.7–4.5 万框，含 164 段新视频）。其余过滤口径不变（IoS 0.8、面积比 0.15–3、不设置信度下限）。

**理由：** 上轮 1.5 万训练框偏少是已知短板；教师换代本身就是重建契机。

### 4.4 YOLO 重训参数（吸取上轮教训）

> **方案：** YOLO11s @1280、epochs **35**（30–40 区间中值）、batch 16、**workers=2**（上轮 workers=4 + batch16 在 epoch 20 时 rss 25.3GB 触发守卫 24GB 上限被杀）、patience=10、seed 不变。产物 project 用**绝对路径**（上轮 Ultralytics 把相对 project 解析到自家 settings 目录，权重散落在 `/home/wyy/pet-final/runs/...`）。

**理由：** workers 减半预计 rss 降约 6–8GB；若仍超限，回退 batch 8 + workers 2（epoch 时间约 2×，仍在守卫窗口内）。

### 4.5 三方对照的报告口径

> **方案：** 报告并列三方——YOLO(base, 35ep) / YOLO(tiny, 20ep) / tiny 本人——各自标注教师指纹与 epoch；一致率均在同一 test 帧集上算（以各自教师为 GT 的两方 + 互为对照的一方）；速度同批帧同硬件。

**限制（必须随报告声明）：** YOLO(base) 的"一致率"仍是对 base 的模仿度，不是真实准确率；三方可比的前提是闸门已确认 base 在已知失败上更优，否则"更高的模仿度"没有意义。

## Risks / Trade-offs

- [闸门样本太小误判] → 判据数字随样本量声明；G1 印刷物锚点约 43 个，±5 个锚点的波动就可能翻转结论，报告须给出绝对数而非百分比。
- [全量 13–17 小时挤占共享机] → 分批 + 批间预检 + 日志标志；若 GPU 长期被占，暂停并报告，不抢。
- [base 推理显存] → 估 8–10GB，GPU0 24GB 足够；若与 GPU1 训练任务冲突则等待。
- [新数据集更大导出更慢] → 5 万帧导出估约 2 小时（上轮 2 万帧 40 分钟）；分批不是必须，守卫窗口内可完成。
- [YOLO 重训仍触发内存守卫] → 4.4 的回退路径：batch 8 + workers 2。
- [教师换了但学生没变好] → 三方对照如实报告；这是伪标签蒸馏的固有上限，报告必须写明。

## Migration Plan

1. 闸门小批（1.x–2.x）→ 报告 → 用户看过报告后决定全量。
2. 全量重跑分批（3.1–3.3）→ 新数据集（4.1）→ YOLO 重训（4.2）→ 三方对照报告（5.1）。
3. 回退方式：所有产物均为新增目录，删除即回退；tiny 缓存与其下游零改动。

## Open Questions

- base 对夜视红外的表现未知（3 段闸门样本只有 1 段夜间）——全量后可在新缓存上分昼夜统计，属后续分析。
- 类目扩展（家具/食盆/水盆）的消融时机：base 验证通过后单独一轮，不在本 change。
- 若闸门未过，"印刷动物抑制"的下一站是人工框还是检测后处理（presence-gate-model 的框级判定），届时再议。
