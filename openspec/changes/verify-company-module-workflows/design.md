# 测试设计

## 1. 执行边界与输入

全部计算在公司服务器进行，使用既有 `.runtime/pet`；本地只编辑和读取报告。
先查看 GPU 占用，选择一张有余量的 A30，顺序执行 GPU 测试，不占满多卡。
不升级核心依赖，不修改 `models/mmaction2`，不访问公司数据目录。

基础素材由固定种子生成：12 秒、1920×1080、15 fps 的运动图形视频，包含
空场、进入、持续存在、短时消失、离开、画面变化和视频结束等受控事件。
按帧生成/读取，避免将所有 1080p 帧常驻内存；送入模型时使用适合各自的较小输入尺寸。
它只验证视频和接口处理，不代表真实猫、真实背景或真实动作。
另生成小型分类、检测框、掩码、时序标签，用于有监督损失的计算检查。

每次执行分配唯一 run_id，所有缓存、临时文件、输出和 checkpoint 均在项目目录内。
测试模式禁用自动下载与 Ultralytics 自动安装；清除模型配置中的预训练加载项。
随机初始化时须同时禁用 torchvision 主模型和 backbone 的默认预训练权重。

## 2. 独立模块检查

| 模块 | 代表路径 | 验收 |
|---|---|---|
| 视频输入输出 | FFmpeg/OpenCV 编码，Decord/OpenCV 解码 | 帧数、分辨率、15 fps 与时间映射正确；容许有损编码的像素差异；空输入/损坏输入有明确错误 |
| 猫存在性候选 | YOLO11n YAML 随机初始化；MobileNetV3-Small | 执行实际前向和后处理，检查维度、有限数值、坐标范围和分类维度；随机模型空检测合法，不要求检出“猫” |
| 在场门控 | 高低阈值、进入/退出保持、允许的前后缓存 | 用已知置信度序列验证启动、短暂漏检、退出、空结果、静止仍在场和结束刷出；跟踪预测框不作为新检测证据 |
| 背景移除候选 | LR-ASPP + MobileNetV3 随机初始化；OpenCV GrabCut | logits/掩码形状与原帧对齐，输出有限；已知几何掩码合成时前景保留/背景填色正确；随机预测不检查语义掩码 IoU |
| rembg | U2-NetP ONNX 会话与 remove API | 需要真实兼容 ONNX 文件；默认不下载，缺权重明确记为 pending_weights；ORT 通用检查不能替代此项 |
| 动作边界 | ruptures/PELT；小型因果 TCN | 已知分段特征的变化点定位；边界有序、非负、无非法重叠；TCN 前向维度及未来输入扰动检查 |
| 动作识别 | 代表性的 MMAction2 2D TSN 与 3D X3D 路径 | 解码→采样→数据预处理→模型→分类输出；有限数值、类别数、片段时间范围正确；不覆盖全部注册模型族 |
| ONNX | 小网络及可支持的轻量分类代表网络 | export、checker、简化、ORT CPU 执行；对照同一权重的 PyTorch 输出 |
| RKNN | 固定形状的小 Conv/ReLU/Pool 网络，target=rv1126b | load_onnx、build、export、模拟器初始化与 inference 分别记录；不以导入成功替代运行 |

猫存在性还需检查显式类别名称/ID 映射，避免把任意类别的框当成猫。
模型选型、阈值和输入尺寸只是测试配置，不在本 change 中锁定项目最终方案。

## 3. 最小训练闭环

对 YOLO11n、MobileNetV3-Small、LR-ASPP、TCN 和选定 MMAction2 代表路径，
使用少量合成输入及格式有效的标签，执行 1–3 个 optimizer step：

1. forward 得到有限 loss；backward 后至少一组应训练参数有有限非零梯度。
2. optimizer step 后至少一项应训练参数发生变化，不要求三步内 loss 单调下降。
3. 保存并重新加载权重，同一固定输入在 eval 模式下输出一致或在声明容差内。
4. 动作模型另保存 optimizer/scheduler/step 状态，恢复后计数连续，再走一次小型验证/评估循环。
5. 合成标签的 top1 或 loss 仅用于流程检查，不作为真实准确率或模型排名。

先验证底层 Runner，再验证项目训练、前向、评估包装入口，分别记录覆盖范围。
现有包装器会写公共 metrics/test_results/checkpoints，并触发额外可视化/benchmark；
实施时通过测试目录中的隔离工作副本运行未修改的包装器和配置，vendor 可只读链接复用。
合成数据和标签置于该副本专属路径，输出也必须落在测试 run 目录，禁止写原实验索引。
限制数据量、epoch、输入尺寸和额外生成规模；如果某包装器仍会超出预算，须记录未执行，
不能用底层 Runner 通过冒充包装器通过。随机测试 checkpoint 使用绝对路径。

## 4. 合并测试的两种覆盖

### 4.1 同一进程兼容性

在同一个 Python 进程先后导入并调用 Torch/MMCV、Ultralytics、torchvision 分割、
TCN、ONNX Runtime 与 RKNN；对输出和错误逐项核对。
该测试检出单独子进程导入难以暴露的本地动态库/线程池/内存资源问题。
先顺序运行；不以并行压测消耗共享 GPU。每个模块释放会话/模型后再进入下一项。
另保留需要同时常驻的 Torch 流水线模型，做小规模连续处理。

### 4.2 数据串联

建立仅用于验证的适配层：

视频/PTS → 检测或存在性评分 → 门控片段 → 掩码与去背景帧
→ 帧特征 → 动作边界 → MMAction2 片段分类 → JSON/视频产物。

统一约定原始 RGB/BGR、CHW/HWC、dtype、数值范围、resize/letterbox 逆映射、
frame_id、PTS、fps 和片段起止，检查 resize 后输出回到原图坐标。
窗口/片段短于模型需求时记录重复采样或 padding 规则，不伪造原视频时长。

分两组运行并分别标记：

- **实际模块输出串联**：各模块确实计算并传递结果。随机检测可能全为空，
  如未走到非空片段分支必须报告覆盖不足。
- **受控信号注入**：使用已知置信度、掩码和边界覆盖空场、非空片段、退出等分支。
  注入点和下游真实执行点必须记录；这验证控制逻辑，不能记为真实猫检测通过。

这些适配层不等于仓库已有生产管线，不改 Live 服务，也不把研究阶段新模块标为已经正式集成。

## 5. 针对原型“猫离开后还切片”的检查

离线 PELT 可使用整段信息；因果 TCN/在线门控必须分别声明可见时间范围。
允许缓存模式使用最多 W 秒前视，W 作为显式配置，不能悄悄读取整段视频。
对测试时间 t 之后或 t+W 之后的输入做扰动，检查不应受影响的输出是否保持一致。

用受控离开时刻分别记录：

- 最后有效检测的媒体时间、持续时间阈值、前后保留时长及输出片段结束时间；
- 采集时间/PTS、开始处理时间、处理完成时间、决定关闭片段的时间；
- 帧采样间隔、前视缓存、队列积压和计算时间，各自对延迟的贡献。

验收以预先声明的 exit_hold、post_roll、采样间隔和 W 为准，分别检查
“保存的视频多保留了多久”与“多久之后才确认保存结束”，两者不能混为一谈。
注入处理阻塞和输入快于消费的情况，验证队列有上限、丢帧有记录、EOF 能刷出
未结束片段，避免只在快速离线读取时看不出积压问题。
本阶段仅验证测试适配层，原型流式服务的真实延迟仍需后续接入其采集/缓存链路测量。

## 6. 数值与 RKNN 边界

FP32 小网络 PyTorch→ORT 对照初始采用 atol=1e-5、rtol=1e-4，报告最大/平均误差。
简化前后必须使用相同输入检查，不只验证生成了 ONNX 文件。
FP16 和 INT8 使用各自明确的容差/误差指标，不套用 FP32 标准。

RKNN 优先尝试目标支持的非量化路径；若 RV1126B 路径要求 INT8，使用明确标记的
合成校准样本验证工具链，另记量化步骤和误差，不能据此估算真实模型精度损失。
若模拟器、目标后端或算子不支持，保留错误并标为失败/受限，不静默回退其他平台。
单个小网络跑通只证明这个网络的路径，不能推导所有 YOLO/分割/动作模型均可转换。
服务器耗时可用于定位故障，不能当作 RV1126B 实机速度。

## 7. 报告与运行预算

每项记录 status、implementation、真实/注入输入、shape、dtype、设备、权重来源、
seed、版本、预处理配置、耗时、峰值显存（GPU 项）、数值误差或失败日志路径。
训练和实际推理次数明确计数；超时或资源不足标为失败/受限，不静默跳过。
GPU 小批量串行执行，常规模块设置分钟级超时，RKNN 编译单独设置较长上限。

结果状态区分 passed、failed、pending_weights、not_implemented、not_run、
unsupported，以及 contract_only 的覆盖说明。任何必测项缺失都不能给出完整通过结论。
Markdown 总表区分原子模块、同进程共存、数据串联、训练/包装器闭环、RKNN。
不生成正式精度对比榜；真实视频和权重验证另行扩展，记录来源与类别映射。
