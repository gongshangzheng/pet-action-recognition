# Proposal: 存在性检测

## Why

存在性检测需要判断整幅画面、指定区域或指定候选目标中是否有真实宠物，为下游调度及疑似目标复核提供依据。整帧初评及包装误检证据见 [evidence.md](evidence.md)；局部图片与视频能力需要经过人工审核的数据训练和独立评测，不能从整帧成绩推定。

## What Changes

- 统一管理整帧、指定区域及候选目标的存在性检测。区域内存在宠物与候选目标本身是真宠物分别定义标签及验收。
- 保留 MobileNetV3-Small 图片模型与已确认的 X3D-XS RGB 视频模型作为基线；整帧初评已完成，局部输入能力尚待验证，不把现有 checkpoint 直接视为适配局部任务。
- 复用 GroundingDINO 检测与现有 SORT 系列关联产物，利用同一候选轨迹的两个或三个检测锚点收集中间的原始连续视频。不同宠物不可拼接，跟踪结果不作为宠物真值。
- 候选视频先人工复核目标关联、可判读性和标签；只有复核通过且标签明确的样本才能进入本 change 的训练数据。包装、印刷动物等负例与静止、夜视、小目标等正例均需覆盖。
- 局部素材生成同时服务训练数据收集与推理输入准备。推理无需等待训练标注，但推理输出不能未经人工复核回流训练。
- 模型输入仅 RGB，不加入帧差、光流或其他运动通道。像素变化调度是独立实验，不进入模型输入。
- 先整理源视频及划分，再生成相互关联的单帧与片段清单；教师标签与独立人工真值分开保存，负样本必须核验。
- 后续按 tasks.md 顺序执行：数据审计与协议确认、局部输入生成验证、候选素材收集、人工复核、审核数据入库、图片与视频训练评测、用户选型及接口验收。每项验证通过后再进入下一项，不因本次规划修改启动执行。
- 用同硬件、同尺寸、同数据说明最快首选及完整成本；不把理论低算量写成已测最快。

## Capabilities

### New Capabilities

- `presence-gate`: 整帧与局部 RGB 图片／视频存在性检测、同轨迹素材收集、人工审核后入库、图片与视频公平对照及可追溯输出。

## Impact

影响局部素材准备、人工复核、训练数据准入、模型训练评测及下游验证接口。复用现有检测与关联，不改跟踪算法，不顺带重构背景建模或推进设备部署。保留现有 evidence、checkpoint 和原始轨迹；本次仅修改 change 规划，不启动抽取、训练、远程任务或部署。
