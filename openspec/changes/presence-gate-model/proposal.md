# Proposal: 存在性检测

## Why

存在性检测必须快速判断画面中是否有宠物，支持下游计算调度。现有单帧模型与 RGB 视频候选需要统一的数据、速度和质量对照，才能判断视频上下文是否值得额外成本。

## What Changes

- 将所有存在性检测规划统一到本 change，合并原 presence-gate-clip-model 的研究范围，不保留第二个活动 change。
- 两个候选：已有 MobileNetV3-Small 单帧二分类；独立选型的 RGB 视频模型（当前建议 X3D-XS，待用户确认）。速度优先，首轮不扩展复杂时序模型。
- 模型输入仅 RGB，不加入帧差、光流或其他运动通道。像素变化调度是独立实验，不进入模型输入。
- 先整理源视频及划分，再生成相互关联的单帧与片段清单；教师标签与独立人工真值分开保存，负样本必须核验。
- 固定实验顺序：数据审计与图片批次 → 图片标注 → 图片训练初评 → 视频批次与标注 → 确认视频架构后训练初评 → 调度与部署验证。首轮每阶段仅数百样本。
- 用同硬件、同尺寸、同数据说明最快首选及完整成本；不把理论低算量写成已测最快。

## Capabilities

### New Capabilities

- `presence-gate`: 单帧与 RGB 视频在场检测、数据追溯、公平对照、速度优先选型及时间轴输出。

## Impact

影响数据提取、标注、训练、评测和门控集成计划。保留 existing evidence 与 checkpoint，不覆盖历史实验。当前修改规划和架构文档，不启动抽取、训练、远程任务或部署。
