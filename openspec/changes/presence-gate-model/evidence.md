# Evidence: presence-gate-model

> 结论载体。每条实验：做了什么 + 数据 + 结论/下一步（≤120 字），附上「这个指标不测量什么」。

## 2026-10-29：运动能量能否替代模型？（motion-probe-20261029a）

- **skill 闸门**：已加载 `experiment` skill（移植自 CyberVerse）。
- **类型**：正确性 / 判别力（不是性能）。
- **baseline**：模型（GDINO native, tiles=3, 阈值 0.15）在 15,139 帧上的帧级标签：present 97.6% / absent 2.4%。
- **可辨识性**：运动能量在 present/absent 两组的中位数分别为 **2.85 / 1.91**（灰度平均绝对差，1 s 间隔）——
  两组分布几乎重叠，说明该判据对「有没有宠物」的可辨识性很弱；这本身就是结论的一半。
- **对照**：同一批帧、同一时间间隔（1 fps 抽样，帧差跨 1 s），唯一变量是「用运动能量还是用模型」。
- **结果表**（motion ≥ 阈值即判 present）：

| 阈值 | 召回 | 漏检帧 | 误检率（absent 被误触发） |
|---|---|---|---|
| 0.5 | 0.997 | 44 | **0.994** |
| 2.0 | 0.719 | 3,994 | 0.477 |
| 5.0 | 0.245 | 10,720 | 0.111 |
| 15.0 | 0.064 | 13,286 | 0.028 |

- **关键盲点**：**28.1%** 的「有宠物」帧运动能量 < 2.0（静止/趴卧的猫）。而 `prolonged_stationary`
  是本项目标注量第二大的类（538 条）——纯运动检测会系统性丢掉最常见的行为。
- **反向误触发**：11.1% 的「无宠物」帧运动能量 ≥ 5（红外切换 / 曝光变化 / 窗帘）。
- **这个指标不测量什么**：运动能量不区分「谁在动」（人 / 宠物 / 家电），也不测量「静止但在场」。
- **样本量**：14,544 帧（present 14,192 / absent 352），跨 124 天、8+ 户码，达标。
- **结论与其上界**：**纯运动能量不能替代模型**（要 99.7% 召回得把误检率推到 99.4%，等于永远触发）。
  但可作为**免费触发器**：运动低时降低模型调用频率、运动高时立即调用。
- **下一步**：门控改为二态（present = 有猫或有其他宠物）；三态仅留作语料污染审计；
  评估「运动触发 + 模型定期确认」的双层调用策略能省多少次模型前向。

## 标签口径（用户裁定 2026-10-29）

- **门控输出二态**：`present`（画面里有宠物，不论猫狗）/ `absent`（没有宠物）。
- **三态仅用于审计**：`cat_present` / `other_animal_only` / `absent` 继续记录，用于量化「语料里混了多少狗」，
  不再作为门控输出。

## 2026-10-29：运动统计 v2（时间窗口 + 背景建模）（motion-windowed-20261029b）

用户指出 v1 的算法太弱：「看像素变动不能只看单帧」。v1 实际算法是**相邻两个 1 fps 抽样帧的灰度平均绝对差**
（间隔 1 s，每段视频首帧无前帧被剔除）——单次成对差，既看不到 1 s 内的动作，也分不清「慢慢走」与「静止 + 噪声」。
因此重做 v2：按**原生帧率**解码 `[t-2s, t]` 窗口，每 2 帧取一帧，算五种统计量。

- **类型**：正确性 / 判别力。
- **baseline**：同一份三态标签；`present = cat_present ∪ other_animal_only`。
- **可辨识性**：AUC 上限（见下表）——若 AUC 接近 0.5，说明该判据对「有没有宠物」无区分力。
- **对照**：同采样点、同窗口长度，唯一变量是统计量（5 种）。
- **结果表**（379 个采样点：present 194 / absent 185；阈值取「漏检 ≤ 2%」时的最高阈值）：

| 统计量 | 定义 | AUC | 该阈值下误检率 |
|---|---|---|---|
| `diff_adj_max` | 窗口内相邻帧差的最大值 | 0.661 | **0.946** |
| `diff_adj_mean` | 相邻帧差均值 | 0.703 | 0.854 |
| `diff_adj_p90` | 相邻帧差 90 分位 | 0.694 | 0.935 |
| `diff_span` | 窗首 vs 窗尾 | 0.712 | 0.957 |
| `mog2_max` | MOG2 前景占比最大值 | **0.747** | **0.800** |

- **改进幅度**：窗口 + 背景建模把 AUC 从「接近随机」抬到 0.747（最强指标 `mog2_max`），**但仍远不足以判定**：
  保住 98.5% 召回时，无宠物帧有 **80%** 会被误触发。
- **这个指标不测量什么**：不区分「谁在动」；对**静止的宠物**天然无输出（这是 v1 已量化、v2 再次确认的结构性盲点）。
- **标签侧的重要限制**：`absent` 只有 2.5%，且来自教师（GDINO）；人工抽检显示绝大多数帧都有猫，
  因此「absent」类里混有教师漏检的猫——这会让任何运动判据看起来更差。**该限制只影响数值，不改变结论方向**：
  即使把标签全修正，运动量与「是否有宠物」之间也不存在单调关系（静止宠物 = 零运动）。
- **结论与其上界**：**运动统计不能作为在场判定**（AUC ≤ 0.75、误检 80%）；只能用作**免费触发器**
  （「画面有大变化」→ 立刻补一次模型判定）。
- **下一步**：两种情形分开覆盖——静止宠物靠**周期 T 模型确认**，出现/离开靠**运动触发**即时确认；
  做「模型调用次数 vs 静止漏判率」曲线定 T 与触发阈值（任务 3.11）。
