# Evidence: presence-gate-model

> 结论载体。每条实验：做了什么 + 数据 + 结论/下一步（≤120 字），附上「这个指标不测量什么」。

## 2026-10-29：运动能量能否替代模型？（motion-probe-20261029a）

- **skill 闸门**：已加载 `experiment` skill（移植自 CyberVerse）。
- **类型**：正确性 / 判别力（不是性能）。
- **baseline**：模型（GDINO native, tiles=3, 阈值 0.15）在 15,139 帧上的帧级标签：present 97.6% / absent 2.4%。
- **可辨识性**：运动能量在 present/absent 两组的中位数分别为 **2.85 / 1.91**（灰度平均绝对差，1 s 间隔）——
  两组分布几乎重叠，说明该判据对「有没有宠物」的可辨识性很弱；这本身就是结论的一半。
- **对照**：同一批帧、同一时间间隔（1 fps 抽样，帧差跨 1 s），唯一变量是「用运动能量还是用模型」。
- **结果表**（motion ≥ 阈值即判 present）：

| 阈值 | 召回 | 漏检帧 | 误检率（absent 被误触发） |
|---|---|---|---|
| 0.5 | 0.997 | 44 | **0.994** |
| 2.0 | 0.719 | 3,994 | 0.477 |
| 5.0 | 0.245 | 10,720 | 0.111 |
| 15.0 | 0.064 | 13,286 | 0.028 |

- **关键盲点**：**28.1%** 的「有宠物」帧运动能量 < 2.0（静止/趴卧的猫）。而 `prolonged_stationary`
  是本项目标注量第二大的类（538 条）——纯运动检测会系统性丢掉最常见的行为。
- **反向误触发**：11.1% 的「无宠物」帧运动能量 ≥ 5（红外切换 / 曝光变化 / 窗帘）。
- **这个指标不测量什么**：运动能量不区分「谁在动」（人 / 宠物 / 家电），也不测量「静止但在场」。
- **样本量**：14,544 帧（present 14,192 / absent 352），跨 124 天、8+ 户码，达标。
- **结论与其上界**：**纯运动能量不能替代模型**（要 99.7% 召回得把误检率推到 99.4%，等于永远触发）。
  但可作为**免费触发器**：运动低时降低模型调用频率、运动高时立即调用。
- **下一步**：门控改为二态（present = 有猫或有其他宠物）；三态仅留作语料污染审计；
  评估「运动触发 + 模型定期确认」的双层调用策略能省多少次模型前向。

## 标签口径（用户裁定 2026-10-29）

- **门控输出二态**：`present`（画面里有宠物，不论猫狗）/ `absent`（没有宠物）。
- **三态仅用于审计**：`cat_present` / `other_animal_only` / `absent` 继续记录，用于量化「语料里混了多少狗」，
  不再作为门控输出。

## 2026-10-29：运动统计 v2（时间窗口 + 背景建模）（motion-windowed-20261029b）

用户指出 v1 的算法太弱：「看像素变动不能只看单帧」。v1 实际算法是**相邻两个 1 fps 抽样帧的灰度平均绝对差**
（间隔 1 s，每段视频首帧无前帧被剔除）——单次成对差，既看不到 1 s 内的动作，也分不清「慢慢走」与「静止 + 噪声」。
因此重做 v2：按**原生帧率**解码 `[t-2s, t]` 窗口，每 2 帧取一帧，算五种统计量。

- **类型**：正确性 / 判别力。
- **baseline**：同一份三态标签；`present = cat_present ∪ other_animal_only`。
- **可辨识性**：AUC 上限（见下表）——若 AUC 接近 0.5，说明该判据对「有没有宠物」无区分力。
- **对照**：同采样点、同窗口长度，唯一变量是统计量（5 种）。
- **结果表**（379 个采样点：present 194 / absent 185；阈值取「漏检 ≤ 2%」时的最高阈值）：

| 统计量 | 定义 | AUC | 该阈值下误检率 |
|---|---|---|---|
| `diff_adj_max` | 窗口内相邻帧差的最大值 | 0.661 | **0.946** |
| `diff_adj_mean` | 相邻帧差均值 | 0.703 | 0.854 |
| `diff_adj_p90` | 相邻帧差 90 分位 | 0.694 | 0.935 |
| `diff_span` | 窗首 vs 窗尾 | 0.712 | 0.957 |
| `mog2_max` | MOG2 前景占比最大值 | **0.747** | **0.800** |

- **改进幅度**：窗口 + 背景建模把 AUC 从「接近随机」抬到 0.747（最强指标 `mog2_max`），**但仍远不足以判定**：
  保住 98.5% 召回时，无宠物帧有 **80%** 会被误触发。
- **这个指标不测量什么**：不区分「谁在动」；对**静止的宠物**天然无输出（这是 v1 已量化、v2 再次确认的结构性盲点）。
- **标签侧的重要限制**：`absent` 只有 2.5%，且来自教师（GDINO）；人工抽检显示绝大多数帧都有猫，
  因此「absent」类里混有教师漏检的猫——这会让任何运动判据看起来更差。**该限制只影响数值，不改变结论方向**：
  即使把标签全修正，运动量与「是否有宠物」之间也不存在单调关系（静止宠物 = 零运动）。
- **结论与其上界**：**运动统计不能作为在场判定**（AUC ≤ 0.75、误检 80%）；只能用作**免费触发器**
  （「画面有大变化」→ 立刻补一次模型判定）。
- **下一步**：两种情形分开覆盖——静止宠物靠**周期 T 模型确认**，出现/离开靠**运动触发**即时确认；
  做「模型调用次数 vs 静止漏判率」曲线定 T 与触发阈值（任务 3.11）。

## 2026-10-30：首版门控模型训练 + 速度基准（gate-train-20261030a）

- **类型**：性能（延迟）+ 正确性（召回/误检）。
- **模型**：MobileNetV3-Small（**1.52M 参数**），输入 796×448（16:9 整帧不裁），二态标签（present 97.5% / absent 2.5%）。
- **训练**：train 10,367 帧（正 10,084 / 负 283），正负 1:2 加权采样，AdamW 3e-4，12 epoch 计划；
  在共享机守卫下跑到 **epoch 7**（val recall@0.5 = 0.997），被 780 s 墙钟上限终止 → 用 `--eval-only` 出指标。
- **阈值反解**：val 上按「漏检 ≤2%」取满足条件的**最高**阈值 → 0.869（val 漏检 1.96%）。

| 域 | n | recall | **FPR** |
|---|---|---|---|
| val/day | 1,889 | 0.976 | 0.955 |
| val/night | 381 | 1.000 | 1.000 |
| test/day | 1,969 | 0.971 | 0.842 |
| test/night | 533 | 0.981 | 1.000 |
| test/all | 2,502 | **0.973** | **0.871** |

- **速度（GPU，单帧 p50 / p90）**：455×256 **1.10 / 1.26 ms**；569×320 1.61 / 2.06 ms；
  796×448 1.78 / 1.98 ms；1138×640 1.17 / 1.30 ms（大输入反而更快是受同卡他人任务影响，需复测）。
  **CPU（2 线程）**：569×320 2.83 ms；796×448 9.44 / 11.33 ms。
- **标签口径（用户 2026-10-30 澄清）**：教师 GDINO 的检测**基本可信**——「几乎每帧都有宠物」说的是
  `present` 帧，不是质疑 `absent` 类。因此教师标签可直接作为监督信号，不需要人工重标全部数据。
- **这个指标不测量什么**：
  ① FPR 的**置信区间很宽**——训练集只有 283 个负样本（占 2.7%），val/test 各几百个；
     它是「在这么少负样本下」的估计，不是终值。要收紧区间得补负样本（164 段未标注视频 + 空场时段）。
  ② 延迟是在**他人任务共卡**时测的，且未做 TensorRT/ONNX 导出，不代表部署态。
- **结论与其上界**：**有模型了，且很快**（448 输入 GPU 约 1.8 ms/帧、CPU 约 9.4 ms/帧，均可实时）；
  但**「无宠物」判定的准确率现在无法定量**——瓶颈是负样本可信度，不是模型。
- **下一步**：先解决真负样本（人工核验 379 帧抽样 + 164 段未标注视频挖掘），再重训并重报 FPR；
  同时把 640/448 的异常延迟复测一次（安静机器上）。

## 模型结构（v1，2026-10-30）

```
输入：整帧 16:9 → 796×448（不裁剪、不缩放变形；部署时同样口径）
骨干：torchvision MobileNetV3-Small（ImageNet 预训练），13 个倒残差块 + SE
头：  Linear(576→1024) → Hardswish → Dropout(0.2) → Linear(1024→2)
参数：1.52 M
输出：present / absent 两 logits（softmax 后取 present 概率）
```

- **逐帧图像模型**：无时序模块、无帧间状态；时间逻辑只在调度与后处理（见 design D1a）。
- 训练增强：`RandomResizedCrop((448, 796), scale 0.6–1.0, ratio 1.4–2.0)` + 水平翻转 +
  亮度/对比度抖动 0.2（不做强颜色抖动，避免破坏红外与彩色域的边界）；
  评测：仅 `Resize((448, 796))`，不裁剪。
- 采样：`WeightedRandomSampler`，负样本权重 2.0（训练集正负比 10,084 : 283）。
- 未做（候选演进）：域条件（昼夜 dual-BN / 域 embedding）、运动图作为第 4 通道、ONNX/TensorRT 导出。

- 结论与限制：相较于单帧 MobileNetV3-Small（测试集 FPR 52.9%），4 帧 X3D-XS 在保持近 98% 召回的同时将测试集误报率降至 27.27%，前向速度极快。但测试集负样本绝对数量仅 11 条（误报 3 条），统计方差依然较大；验证集因仅 3 条负样本导致其自身 FPR 达 100%，不能认为门控已达到最终部署标准，后续仍需针对负样本扩增验证。

## 2026-11-07：候选方案备案——Grounded-SAM 与 SAM 3（用户要求写入）

由 `multi-pet-sort-tracking` 4.1 的结论延伸：既然 SAM 系本身没有类别语义，那"给概念让它判断"的方案是否可行？本节备案两条候选，均**未安装、未下载权重、未实验**。

### Grounded-SAM / Grounded-SAM-2

| 项 | 事实 |
|---|---|
| 仓库 | `IDEA-Research/Grounded-Segment-Anything`（17,791 stars，最后推送 2024-09-05）、`IDEA-Research/Grounded-SAM-2`（3,803 stars，2025-11-11） |
| 许可证 | **Apache-2.0**（与 `GroundingDINO`、`facebookresearch/sam2` 同为 Apache-2.0，无 GPL 传染） |
| 工作原理 | GroundingDINO 出「框 + 类别」→ 把框当 prompt 喂 SAM → 出精确掩码 |

**为什么它不解决我们的问题**：语义**全部继承自 GroundingDINO**。狗粮袋面印刷的金毛，DINO 判成 "dog"，SAM 就精确切出印刷图案，输出 `{label: "dog", mask: 印刷狗}`——看起来比现状更有说服力，但依然是误检。它提供的是「类别 + 掩码」，不是「这个类别对不对」。

**结论**：本项目已直接持有 GroundingDINO 与 SAM2，再引入 Grounded-SAM 的增量只有"掩码更准"，而对误检判定无帮助。不作为候选。

### SAM 3（`facebookresearch/sam3`）

| 项 | 事实 |
|---|---|
| 规模 | **848M 参数**（detector + tracker 共享 vision encoder）；对照 SAM2-small ≈46M、MobileSAM ≈10M |
| 关键能力 | **Promptable Concept Segmentation**——给概念/文本，分割该概念的所有实例 |
| 许可证 | 自定义 **SAM License**（Last Updated 2025-11-19）：非独占、全球、免版税，**允许商用与衍生作品**；限制为军事/ITAR、反向工程、发表需致谢、需遵守贸易管制。**无"非商用"条款** |
| 权重要求 | **gated**——需在 HF 申请访问（`facebook/sam3`，新版 3.1 在 `facebook/sam3.1`）并 `hf auth login` |
| 依赖要求 | PyTorch **≥2.7**（README 装 2.10.0+cu128）、CUDA **12.6+**、**flash-attn-3**、**cc_torch**（自定义 CUDA op，需编译） |
| 现有环境匹配度 | pet 上 `yolo`/`dlc` 为 torch 2.8.0+cu128（版本可行），但 flash-attn-3 与 cc_torch 均需新装与编译 |

**唯一值得单独验证的点**：给概念「a real living dog / cat」时，它是否**不再**检出印刷动物。它的 detector 是概念驱动的，理论上可能比 DINO 更挑。**但这是未知的**——印刷动物照片对任何视觉模型都是强负样本难题，本 change 没有证据支持任一结论。且其纯分割模式与 SAM2 一样无类别语义（我们已实测 SAM2 在印刷金毛上给出 mask 分数 0.977，高于真猫的 0.964）。

**成本与前置**：① 用户需先在 HF 申请权重访问；② 需在 pet 上编译 flash-attn-3 + cc_torch（共享机，且不得动 `plf` 主环境）；③ 848M 模型 × 逐框推理，离线全量成本远高于 SAM2-small。

**结论**：**暂不引入**。若将来要做，正确用途是「概念提示能否拒绝非活体负样本」这个独立实验，不是框细化（4.1 已证明外接框精修收益仅 1–3%）。
