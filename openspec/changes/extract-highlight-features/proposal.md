# 亮点抓取特征提取与云端上报载荷

日期：2026-11-02。状态：Apply（用户 2026-11-02 明确指示：“实现提取出画面亮度，
对比度，宠物活动幅度，宠物身体画面中面积占比和时长，面部暴露面积占比和时长，
及行为识别信息上报到云端进行判断。云端相关可以先不动，别的可以完成一下，
暂时不提交”）。

## Why

`项目要求.txt` 中期验收第 2 条要求“亮点抓取（提取出画面亮度，对比度，宠物活动
幅度，宠物身体画面中面积占比和时长，面部暴露面积占比和时长，及行为识别信息
上报到云端进行判断）”；端侧功能还要求“向云侧输出结构化事件”和“本地短时缓存”。
仓库目前只有动作分类（`cat-action-training-v1` / `cat-action-model-zoo-v1`）
和检测/跟踪脚本，没有画面质量、活动幅度、面积占比、面部暴露这些量，也没有
上报载荷格式。

## What Changes

- 新增 `petlib/highlights/`：
  - `metrics.py`：亮度、对比度、区域运动能量、面积占比等纯 numpy 计算；
  - `sources.py`：宠物身体来源（YOLO11-seg 懒加载 / `pet_detect_track.py`
    轨迹 JSON / 无）与猫脸来源（OpenCV `haarcascade_frontalcatface_extended`）
    的统一接口；
  - `actions.py`：行为识别时间轴（读取已有 JSON/JSONL，或用 v1 七类 MMAction2
    配置 + checkpoint 滑窗推理，懒加载）；
  - `aggregate.py`：逐采样帧 → 按窗口汇总 → 时长 / 连续段；
  - `report.py`：`pet.highlight.v1` 上报载荷与本地 outbox（原子写入，断网缓存）。
- 新增 `scripts/extract_highlight_features.py`：单视频 → 载荷 JSON（+ 可选 outbox）。
- 新增 `scripts/test_highlight_features.py`：合成数据单元测试。
- 新增 `docs/highlight_features.md`：字段定义、阈值、用法与限制。

## Non-goals

- 端侧不挑选、不裁剪亮点片段（用户 2026-11-02：具体裁剪哪些作为亮点是云端的工作）。
- 不实现云端接收、判断、存储或 HTTP 上传（用户：云端相关先不动）；载荷只写到
  本地文件和 outbox 目录，`cloud_judgement` 字段留空。
- 不训练新模型；猫脸检测先用 OpenCV 自带 Haar 级联，不下载新权重。
- 原计划不在本地跑模型推理（项目硬规则）。2026-11-02 服务器 GPU 被占，用户明确要求
  “看看我本机有可能快速跑一个示例出来吗”，故在本机 RTX 3060 上用隔离 venv
  （继承 `reid` 环境的 torch 2.4.1+cu121，只新装 ultralytics 8.3.40）跑了单猫示例；
  只做 YOLO11n-seg + Haar 推理，不训练、不跑行为模型。
- 暂不 git 提交（用户指示）。因“脚本先提交再在服务器执行”的硬规则，本轮
  **不在服务器上执行**，真实视频验证留到提交之后。
- 不改动现有训练/评测/Live 代码与 Web 页面。

## 验收

- 单元测试全部通过，覆盖：亮度/对比度数值、运动能量与全局变化补偿、面积占比
  （掩码与框两种来源）、时长与连续段合并、行为时间轴读取与合并、载荷字段完整性、
  outbox 原子写入，以及用假检测器跑通合成视频的端到端流程。
- CLI 在无模型依赖（`--pet-source none --face none`）时能对合成视频产出合法载荷。
- 文档写明每个字段的定义、单位、默认阈值“未经真实数据校准”这一限制，以及
  服务器验证待办。
