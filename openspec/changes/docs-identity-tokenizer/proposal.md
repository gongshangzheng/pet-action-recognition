# Proposal: docs-identity-tokenizer

## Why

8 号《身份-动作 Tokenizer》是单模型内部设计的唯一权威文档（职责见 `docs-system` 登记表）。当前结构是：

```
§1 设计目标与非目标 → §2 谱系 → §3 架构总图 → §4 逐组件设计（§4.0–§4.7 平铺）
→ §5 训练流程 → §6 评测矩阵 → §7 待决策项 → §8 许可 → §9 参考来源
```

三个问题：

1. **总图埋在中部**（§3）——读者要翻过目标与谱系才知道整体长什么样
2. **待决策在末尾**（§7）——与 6 号《系统架构》「总图在前、待决策紧随」不一致
3. **组件平铺**（§4.1 预处理 / §4.2 编码器 / §4.3 骨架 / §4.4 潜空间 / §4.5 动作 / §4.6 身份 / §4.7 解码）——没有按「框架的重要部分」分章，动作提取与身份提取淹没在编号里

## What Changes

对齐 6 号的**总-分**结构：

- **框架总图提到顶上（§1）**：完整结构图（两条支路 → 共享编码器 → register 聚合 / 正交基投影 → 解码 → 损失）+ 模块地图 + 设计目标与非目标
- **当前待决策上移到 §2**（与 6 号同位置）
- **框架拆成几个重要部分，各自成章**：
  - **共享基座**（3D patchify + 视频编码器——两条支路共用）
  - **动作提取**（正交运动基 → 行为素序列）
  - **身份提取**（参考输入 → register 融合 → `w_identity`）
  - **潜空间与解码**（两条支路汇合）
- 训练流程 / 评测矩阵 / 谱系与合规 / 参考来源 依次在后；符号速查降为附录

## Impact

- `management/docs/identity-tokenizer.md`：**结构重排**（内容是搬移，不重写；补齐章节引言使每章自洽）
- **引用级联**：6 号 / papers 笔记 / 各 change design 中指向 8 号节号的位置全部重映射，闭合核对后悬空必须为 0
- `docs-system` 登记表：8 号的单篇 Change 由「待开」→ `docs-identity-tokenizer`

## 不做

- 不改设计内容（方案本身的裁定走 `identity-action-tokenizer` change）
- 不动 6 号结构（6 号自己的单篇 change 是 `docs-architecture`）
