## 读者动线（为什么是这个顺序）

```
总图（整体是什么）
  → 待决策（哪里还没定）
    → 共享基座（两条支路共同依赖的底座）
      → 动作提取（支路一）
      → 身份提取（支路二）
        → 潜空间与解码（两条支路在这里汇合）
          → 训练流程（怎么训出来）
            → 评测矩阵（怎么验证）
              → 谱系与合规 / 参考来源（出处）
```

- 先给总图与模块地图，读者随时知道「现在读到整体里的哪一块」
- 待决策紧随总图（与 6 号一致）：先知道哪些点还悬着，读细节时心里有数
- **共享基座先行**：它是动作与身份两条支路的公共依赖，讲完再分叉可以避免重复
- 动作提取在前、身份提取在后：动作是主产品（行为素序列），身份是解耦机制的支点
- 汇合点（潜空间与解码）放在两条支路之后：读者此时才需要理解「两边怎么拼起来重建」
- 训练 / 评测在最后：属于「怎么得到、怎么验」，不是结构本身
- 谱系（借什么否什么）从原 §2 移到后段：它是出处说明，不是阅读正文的前提
