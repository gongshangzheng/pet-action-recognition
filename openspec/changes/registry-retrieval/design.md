## 自总管迁入的决策（ID 不变）

### D9: 登记-检索架构（用户确认方向 2026-09-14，实施待批准）

**用户需求（两条，确认为同一机制）**：① 框出猫 → embedding → 检索库中找最相似 → 确定是哪只猫（RAG 式检索）；② 用户拍几张碗的照片 → 模型识别出「这只是碗、其他不是碗」（解决 GroundingDINO 文本检测碗偏掉的问题）。

**统一架构（登记-检索 / Re-ID）**：
```
登记：用户框选/拍照 → DINOv2 embedding → 特征库（FAISS）
      猫登记照 3-5 张/只、物品照片 3-5 张/件
检索：候选区域（GroundingDINO 粗框 / SAM mask）→ DINOv2 embedding → 余弦最近邻
      文本检测管「类别级候选」，登记照管「实例级判定」——两者串联互补，主链不废弃
```

**关键判断**：家庭场景是极端封闭集（2-5 只猫、几件固定物品），DINOv2 零样本 embedding + 最近邻预计够用，**无需训练**；零样本不稳时的兜底 = embedding 上训 logistic 回归小分类器（分钟级）。猫 Re-ID（§8.2 register_cats.py）与物品识别共用同一套登记-检索代码。

**候选生成问题（用户追问：连碗都检测不到怎么办）**：检索必须有候选区域。文本检测失效时，候选来源按优先级：
1. **SAM/SAM2 自动分割**（segment everything）：无类别抠出画面所有物体 mask，彻底绕开词表；**固定机位只需跑一次**，静态物体 mask 缓存复用——碗/摄像头这类不动的东西成本近乎零
2. **OWLv2 图像引导**：照片直接当 query，不经过文字，能检出文本漏检
3. **帧差/背景减除**：固定机位找「新出现/被移动」的物体，触发局部重分割
4. **GroundingDINO LoRA 室内微调**（用户提出的最后手段）：需标注数据 + 训练成本 + 损伤开放词汇能力，仅在 1–3 全失败时启动

**分工架构**：每帧 GroundingDINO 只管**会动的**（猫）；静态物体走「**一次 SAM 分割 + 登记检索 + 帧差变更触发**」。

**实施时机**：调研结论备档；待 §4 验收后用户决定启动。

## 附录：算法原理（自总管附录 A 迁入）

### A2 分割

**HQ-SAM（可选，mask 清洗消融 8.5）**
- 是什么：Segment Anything Model 的高质量变体。SAM = ViT 图像编码器（SA-1B：1100 万图 11 亿 mask 训练）+ 提示编码器 + mask 解码器，给框/点就输出像素级 mask；HQ-SAM 加一个**高质量输出 token**，融合图像编码器的早期浅层特征（边缘细节）与晚期语义特征，专修 SAM 在细结构上糊边的问题
- 为什么是可选：关键点隐空间不消费 mask（D2b）；消融实验（8.5）决定 mask 清洗背景是否提升下游

## 增补决策（2026-09-14 讨论）

### R1: 场景常驻物体清单——SAM 的"背景理解"角色

SAM 不只当分割工具，当**背景的物体级描述**用：固定机位跑一次全图分割 → 连续观察期间位置与 embedding 稳定的 mask = 「场景常驻物体清单」（沙发/桌/碗/爬架…各有 mask + DINOv2 embedding + 坐标）。与 MOG2（像素级差异）分工：MOG2 管"哪里变了"，清单管"那里本来有什么"。

### R2: 变更触发重分割的修正（用户指出猫动误触发问题）

原设计「帧差发现变动 → 重分割」有漏洞：猫是最常动的东西，会持续误触发。修正为三重过滤：

1. **猫框剔除**：前景 mask 先减去当前猫框（膨胀边缘）——猫的动是已知的、被跟踪的，不算背景变动
2. **持续性迟滞**：非猫变动需稳定存在 ≥X 秒才触发（人走过/光影瞬态不触发；杯子被碰落地静止后才触发）
3. **局部重分割**：触发时只对该物体 mask 邻域重分割，非全图——SAM 成本趋近零

变更分类：剩余前景 ∩ 清单物体 → 该物体被挪动（更新其 mask/坐标）；剩余前景 ∉ 清单 → 新物体 → 分割 + 登记新条目（走登记-检索流程）。

### R2b: 局部重分割流程（补充细节，2026-09-14 讨论）

**SAM 的执行范围**：只处理变动邻域——变动前景的 bounding box 向外扩 20% 的裁剪区域，交给 SAM 分割；其余画面沿用缓存 mask。全图分割只在两种情况发生：① 首次建库；② 累计局部修正过多/摄像头被移动（由整体帧差比例超阈值判定）→ 全图重建清单。

**状态机**（静态物体子系统的三种状态）：

```
[稳定态] 前景(剔除猫框后)为空或瞬态
   │  非猫前景持续 ≥X 秒（X 待定，初值 10s）
   ▼
[变更态] 定位变动区域 → 与常驻清单求交
   │  ├─ 落在清单物体 O 的 mask ∪ O 的旧位置附近 → 「O 被挪动」
   │  └─ 不与任何清单条目相交 → 「新物体出现」
   ▼
[更新态] 对变动邻域局部 SAM 分割 → 新 mask
   ├─ 被挪动：DINOv2 新 mask embedding vs 登记库确认仍是 O → 更新 O 的坐标/mask
   ├─ 新物体：embedding 入登记库 → 新条目（"未知物体 #N"，待用户赋予语义）
   └─ 更新完成 → 回 [稳定态]
```

**常驻清单数据结构**（初稿，启动时细化）：每条目 = `{object_id, mask_rle, bbox, embedding(512d), first_seen, last_moved, semantic_label(用户标注,可空)}`；存储为 per-camera JSON/npz，gitignore。

**边界情况备忘**（启动时验证）：猫趴在沙发上一小时（猫框剔除已处理）；物体被猫叼走（变动区域起点在猫框边缘——需允许"从猫框生长出来的变动"不立即触发）；镜头自动曝光缓变（MOG2 学习率压制）。
