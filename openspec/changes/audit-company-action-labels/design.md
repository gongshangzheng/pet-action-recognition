# 只读审计设计

输入是服务器 `/home/work/analysis_code/datasets/company_video_paths/` 下的
`merged_annotations.local.csv` 与 `merged_annotations.local.json`。
CSV 读取 behavior，JSON 只读取非取消 annotations.result，不把 predictions 当人工真值。
不同导出各自统计并比较 `(视频, 类别, 起帧, 止帧)` 的去重集合。

脚本 stdout 输出原始区间-标签对数、去重区间数、涉及的不同视频数、
同视频同类范围合并后的覆盖帧数，以及同时出现不同类别的覆盖帧数。
按 1 起始且两端包含计算帧数，仅为既有区间格式的审计口径；
正式转换前仍须核对模板，不假定所有视频为 15fps，不以帧数冒充真实秒数。
同视频中的多区间和相邻视频仍可能同源，因此“不同文件”不是独立场景保证。

统计 JSON result type 和 value 字段名作为标签结构依据；
结果 id 不自动解释为猫身份，时间共现不能自动解释为多猫。
不作语义标签合并、不选一个标签替换重叠，不推定缺失标签是负例。
比较计数发生差异时先记录，不能自行选择或删改导出记录。

脚本先在本地只做 AST 语法解析并提交，然后通过 SSH 输入送入远程
Python 内存；校验传入源码 SHA256，禁用字节码，只使用标准库。
两份输入在读取前后 SHA256 比较，不解码视频、不运行模型、不建立缓存或输出文件。
汇总只显示类别名称、数量与结构字段名，不显示任务内容和视频文件名。

类别建议以零观测、不同视频覆盖和可分组验证为依据，不设普遍适用的最小样本阈值。
有足够片段只代表可尝试训练；还需视觉复核、个体关联、独立分组划分及真实场景评测。
