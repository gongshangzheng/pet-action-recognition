# 裁剪训练实验设计

## 1. Context

本设计供实验执行者实现和用户验收。用户已批准三臂实验，远程资产核验和小批媒体准备已完成；批准记录与运行证据见 [evidence.md](evidence.md)。小批裁剪质量及参数仍待用户确认，全量生成和训练尚未启动。

### 1.1 已核对的入口

- `scripts/pet_detect_track.py`：GroundingDINO-tiny 抽样检测，最高置信猫框、插值和平滑，输出 `track.json`。`--motion-correct` 默认关闭；像素辅助使用 MOG2 前景与检测框交集外扩，不是存在性判定。
- 该检测脚本把全部解码帧保存在列表中；无猫检测时没有合法的空轨迹分支，插值也未限制长缺失区间。当前最高置信框方案没有多猫身份保证。
- 该脚本只在启用运动校正、非抽样帧且达到预热帧号后调用背景模型，需修正连续更新与预热过程后验证。静止宠物不能因前景消失被判无猫。
- `scripts/make_followcam.py`：按 `camera_box` 裁剪，外扩系数 1.2，默认输出 512×512；会把 `state` 文字画进 `followcam.mp4`。空裁剪写黑帧，短轨迹复用末项，均不能静默用于本实验。
- `scripts/pet_batch_run.py`：旧批次驱动未传入 `--motion-correct`，因此不能把旧批次一概视为启用了像素辅助。
- `configs/cat_action_videomaev2_b_v1.py`、`configs/cat_action_v1_base.py` 与 `petlib/datasets/cat_intervals.py`：七类分类配置，直接读取原始视频并在人工标注区间内采样。
- `scripts/run_cat_action_batch.py`：固定了旧索引和旧结果目录，需要独立实验入口，避免写回旧排名和模型结果。

### 1.2 历史参照与证据边界

`docs/cat_action_training_v1.md` 记录训练目录为 `pet-final-v1`，数据和产物链接到 `pet-final`。它记录七类 train/val/test 为 1664/604/442，VideoMAEv2-B 验证 top-1 85.93%、macro-F1 70.97%，测试 top-1 81.90%、macro-F1 67.66%。

这些数字是历史报告，不是本次复测。报告还提示本地曾有不同 seed 的索引副本，实施时必须核对远程索引 SHA-256，不能按本地行数猜测一致性。旧测试结果已公开，本轮重复使用该测试集只能作为既有基准复验，不能称全新独立留出验证。

## 2. Goals / Non-Goals

产出可追溯的空间裁剪语料和配对分类结果，分别回答裁剪是否有帮助、像素辅助是否带来额外收益。接受负结果，实验完成不以提高到某一分数为条件。

此次沿用七类人工时间标签，目标宠物未明确、多猫歧义和漏检均须可见。不引入新身份关联器，也不把分类准确率解释为事件检测效果。

## 3. Decisions

### 3.1 固定数据与三个实验臂

> **方案：** A 为原视频重训，B 为 GroundingDINO 裁剪，C 为相同检测缓存加像素运动校正的裁剪。三臂使用相同 sample_id、类别、日期划分和共同可用样本。
>
> **理由：** B 对 A 检验裁剪，C 对 B 检验像素辅助。只比较 C 与旧报告会混入运行环境、样本和配方差异。
>
> **替代：** 仅训练 C 成本更低，但无法归因；旧 checkpoint 复评可用于核验历史锚点，不能替代 A 的配对重训。

先冻结原七类清单，再生成裁剪。样本筛选只能依据可解码性、检测和裁剪有效性及身份歧义，不能依据分类预测或测试类别调整规则。共同可用清单在训练前冻结，A/B/C 均使用它；另列原清单总数、每类每 split 的损失和失败原因。

在原始评测清单上同时报告成功分类数除以全部区间数，裁剪失败计为未成功分类；并单独报告成功裁剪子集的分类指标。前者是“含预处理失败的区间成功率”，不能称事件级准确率。不同臂的可用率另列，避免用丢失难例换取高分。

### 3.2 复用检测缓存与干净裁剪

> **方案：** 对冻结清单引用的源视频生成检测缓存，B/C 共享完全相同的检测结果，随后分别计算相机路径并编码派生视频。逐个源视频处理，使用顺序解码和有界窗口，避免保留全片像素。
>
> **理由：** 源视频全长空间裁剪可保持原标注帧号，避免片段重编号错误，也避免重复检测。
>
> **替代：** 只编码标注时间段可节省磁盘，但需要额外帧号重映射，本轮不采用。

提议首轮复用现有起点：抽样间隔 10、检测阈值 0.3、外扩 1.2、输出 512×512，训练输入再取 224×224。这些数值不是已验证的最优值，须经训练集小批质检并冻结。任何后续参数改动先记录原因，并重新生成受影响缓存及清单。

训练有效帧只含裁剪画面，不新增文字、框、置信度或标签；源视频已有水印仍可能保留。展示叠加写入独立诊断视频。保留原帧数、顺序、FPS 与时间戳映射，核验编码无掉帧、重复帧或截断；若源视频为可变帧率且无法保持映射，明确拒绝，不能猜测帧号。当前媒体审计尚未覆盖逐帧时间戳，此项仍待完成。

每个源视频记录源路径及哈希、尺寸和帧数、检测权重哈希、代码提交、参数、裁剪视频哈希、轨迹、逐帧来源及有效性。重复运行验证缓存元数据后才能复用；参数或源哈希不符时拒绝混用，已有产物不得覆盖。

### 3.3 缺失检测、多猫与狗处理

> **方案：** 检测 prompt 同时包含猫和狗，并保留每个抽样帧的全部去重候选。只在有合法锚点的短缺口内插值；提议首轮最大锚点间隔为两个检测步长。端部、长缺失、空检测和目标歧义标记为无效；人工标注区间内任一帧无效，该区间进入失败清单，确保随机采样不会改变入选集合。
>
> **理由：** 长插值或复用最后框会制造没有观测依据的目标轨迹。
>
> **替代：** 退回整帧能提高可用率，但会混淆裁剪实验，本轮不自动回退。新增跟踪器另行讨论。

缓存保留全部猫和狗候选；不能只保存 argmax 后再声称已核实单猫。人工核对训练集抽样及自动标出的多候选视频；验证/测试只按冻结规则判断有效性，不按结果逐例修框。多猫且无法由既有标注确定目标的区间单列，不将其识别为单猫连续轨迹。单猫同时出现狗时，首个七类裁剪实验也保守排除，并在失败统计中单列 `dog_present_target_ambiguous`；该规则不声称狗一定干扰了动作，只表示现有标注不足以证明动作属于猫。

无猫帧不能由像素低运动直接判定。检测无猫只记为 `no_reliable_cat_detection`，可能是真正无猫，也可能是小目标、遮挡、红外或探测器失败；当前缺少人工确认时不得声称“已确认无猫”。像素变化继续只用于扩展已有检测框。

审阅显示与训练资格分开：无效帧有猫框时使用最高置信度猫框，无猫框时显示完整原画并保留无效原因。显示回退不改变 `valid` 或共同索引，也不保证多猫身份连续；不能将可见画面视为训练合格证据。

### 3.4 像素辅助先验证再扩量

修正背景模型顺序更新与预热，保持静止宠物原检测依据。C 仅在非锚点帧使用像素前景辅助外扩，不因低运动删除样本，不改变检测缓存和空间标签。

先用合成框和已知平移验证坐标恢复、边缘裁剪和锚点一致性。再从训练 split 固定抽取至少 20 个区间，覆盖静止、快动、小目标、遮挡与夜间；不足的场景如实记缺。用户查看原图与裁剪的随机顺序对照，检查身体切断、跳猫、抖动和文字污染。单段只算管道验证。

若像素辅助无效或劣化，保留结果并报告，不能默默切换成 B 却仍称 C。质量验收通过后才批量准备数据，失败则修正并重审受影响参数。

### 3.5 训练与测试冻结

提议沿用现有 VideoMAEv2-B 配方：16 帧、间隔 4、224 输入，AdamW lr=5e-5、weight decay=0.05，20 epoch，warmup 2 epoch 后 cosine，AMP，micro-batch 4、累积 4，原七类权重。A/B/C 从相同 K710 蒸馏预训练骨干开始，不从旧七类 best checkpoint 续训。

首轮三臂使用同一训练 seed 0，保持优化器、增强、采样和有效 batch 相同。数据划分 seed 与训练 seed 分别记录。显存不足时只能对三臂统一调整 micro-batch 和累积并记录，不独改一个臂；多个 seed 的确认实验另行申请，首轮不宣称统计显著。

每臂按 val macro-F1 保存最佳 epoch。验证集选择预处理方案，使用 macro-F1 为主，top-1 与分类别召回作诊断；并列时优先较简单方案。先写入冻结记录，再统一测试三臂一次，不按测试集重新选参或挑模型。

保存 top-1、macro-F1、balanced accuracy、混淆矩阵、各类 precision/recall/F1/support，以及逐 sample_id 概率和配对正确/错误变化。置信区间按源视频分组重采样，注明仅反映评测样本波动，不覆盖训练随机性。历史测试已使用的限制必须出现在报告中。

## 4. Risks / Trade-offs

裁剪可能丢失食碗、饮水机和如厕环境，导致类别性能下降。按类别检查失败，不能只报整体平均。

像素变化可能来自阴影、红外噪声或相机移动；固定机位适用性在训练小批审查中核实。未验证场景不能推广。

全长视频双变体编码会增加磁盘、CPU 和 GPU 成本。先估算源时长和存储，容量不足则停止并向用户报告，不能未经审核缩小样本后仍与旧全量成绩比较。

共享 GPU 有进程实际占显存或主机资源紧张时不得开跑；长任务通过 `remote-ops` 预检、静态审计、降规模冒烟及资源守卫。训练吞吐受共享资源干扰的结果不能用作性能结论。

## 5. Migration Plan

实现使用独立 `exp/gdino-crop-videomaev2-evaluation` 分支，先提交可复用脚本、配置和测试，再通过 Git 同步远程并校验 HEAD。不得覆盖现有脏工作树或旧训练结果。

派生视频放 `results/cat_crop_classification/assets/<dataset-id>/`，索引放 `datasets/cat_crop_classification/<dataset-id>/`，运行记录放 `results/cat_crop_classification/<run-id>/{raw,gdino,gdino_motion}/`。各臂保存解析后的完整配置、环境、日志、状态、指标和权重哈希，禁止写回旧 model-zoo 排名。

代码以独立提交回退，原始数据和权重始终只读。失败产物保留状态，不自动清理用户数据；结论与失败原因写入本 change 的 `evidence.md`。

## 6. Open Questions

资产核验已确认：远程不存在 `pet-final-1`；`pet-final-v1` 是独立 worktree，`pet-final` 是主工作树，二者共享的数据、索引、权重和结果可读。原七类索引哈希与历史记录一致。后续仍须在任何训练前重新做资源预检与 Git HEAD 校验。

用户在 Review 时审核本设计提出的三臂成本、小批裁剪规则和训练预算。任何改变样本定义、实验臂或评测协议的后续决定必须先回写计划。
