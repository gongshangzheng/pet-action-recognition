# Design: background-object-memory

> 机制主体迁自 `registry-retrieval` design R1 / R2 / R2b（2026-09-14 讨论稿）+ 架构 §4「背景对象层」。本文件把它整理为可实施的契约；参数值仍是实验测定项。

## D1 分工：谁负责什么

| 层 | 负责 | 频率 | 模型 |
|---|---|---|---|
| ① 在场门控 | 画面里有没有猫 | 高频 / 逐帧 | 轻量单类「猫」检测（候选 YOLO-nano 级） |
| ① 主检测跟踪 | 猫框 + 家具框 + 轨迹 id | 每 10 帧抽样 | GroundingDINO（多 prompt） |
| **本层：背景对象记忆** | 场景常驻物体清单（mask + embedding + 坐标） | 关键帧触发 | SAM（关键帧），可选 HQ-SAM |
| ③ 抠像 | 猫本体 | 逐帧 | `rembg` 小模型（`pet-background-removal`） |

与 MOG2（像素级「哪里变了」）的分工：MOG2 回答**哪里变了**，清单回答**那里本来有什么**。

## D2 触发：关键帧而不是逐帧

```
触发条件（满足其一）：
  ① 看到的区域变化超阈值（裁剪模拟的窗口移动 / 相机真实转动）
  ② 距上次分割超时
→ SAM 在关键帧上分割（自动网格 prompt / 已有检测框 prompt）
→ 更新「场景常驻物体清单」
```

**两次关键帧之间**：真实机位不动 → 物体在**原帧坐标系**里静止 → 裁剪帧内位置 = 全局坐标 − 裁剪偏移（免费换算，无需重新分割）。

## D3 变更检测三重过滤（修正猫动误触发）

原设计「帧差发现变动 → 重分割」有漏洞：猫是最常动的东西，会持续误触发。修正：

1. **猫框剔除**：前景 mask 先减去当前猫框（膨胀边缘）——猫的动是已知的、被跟踪的，不算背景变动。
2. **持续性迟滞**：非猫变动需稳定存在 ≥ X 秒才触发（人走过 / 光影瞬态不触发；杯子被碰落地静止后才触发）。初值 X = 10 s。
3. **局部重分割**：触发时只对该物体 mask 邻域重分割，非全图——SAM 成本趋近零。

**变更分类**：剩余前景 ∩ 清单物体 → 该物体被挪动（更新 mask/坐标）；剩余前景 ∉ 清单 → 新物体 → 分割 + 登记新条目。

## D4 局部重分割与状态机

```
[稳定态] 前景(剔除猫框后)为空或瞬态
   │  非猫前景持续 ≥X 秒（X 待定，初值 10s）
   ▼
[变更态] 定位变动区域 → 与常驻清单求交
   │  ├─ 落在清单物体 O 的 mask ∪ O 的旧位置附近 → 「O 被挪动」
   │  └─ 不与任何清单条目相交 → 「新物体出现」
   ▼
[更新态] 对变动邻域局部 SAM 分割 → 新 mask
   ├─ 被挪动：新 mask embedding vs 登记库确认仍是 O → 更新 O 的坐标/mask
   ├─ 新物体：embedding 入登记库 → 新条目（"未知物体 #N"，待用户赋予语义）
   └─ 更新完成 → 回 [稳定态]
```

**全图重建只在两种情况下发生**：① 首次建库；② 累计局部修正过多 / 摄像头被移动（整体帧差比例超阈值判定）。

## D5 常驻清单数据结构

每条目 = `{object_id, mask_rle, bbox, embedding(512d), first_seen, last_moved, semantic_label(用户标注，可空)}`；
存储为 per-camera JSON/NPZ（gitignore）。embedding 模型与向量库**选型未定**（见 `registry-retrieval` D9b），本层先用可替换槽位。

## D6 三项职责

1. **背景对象记忆**——"一直知道有哪些背景物体"，含被猫遮挡期间（SAM 记忆注意力保住掩码，半 amodal；这是单靠检测器做不到的）。
2. **纠正** GroundingDINO 识别错误。
3. **补** GroundingDINO 盲区（无 prompt 的物体）。

## D7 四项实验测定项（实施时定值，本 change 只定机制）

| # | 待定 | 方向已定 | 候选 |
|---|---|---|---|
| 1 | 重分割触发参数 | 区域变化超阈值 + 超时兜底 | 阈值数值、兜底间隔、迟滞 X（初值 10 s） |
| 2 | 自动发现物体的二次分类 | 检测框 prompt 的类别免费（GDINO 框自带类别，Grounded-SAM 同思路） | CLIP 零样本 / DINOv2 近邻查登记库 / GDINO 二次推理 |
| 3 | 过分割过滤 | 碎片掩码要能过滤 | 面积 / 稳定性（帧间一致）/ 出现时长阈值 |
| 4 | 与 GDINO 家具框的合并去重 | 合并——重叠大（IoU 超阈值）判同一物体 | 低重叠情况的判定阈值 |

## D8 边界情况备忘（启动时验证）

- 猫趴在沙发上一小时（猫框剔除已覆盖）。
- 物体被猫叼走（变动区域起点在猫框边缘 → **允许"从猫框生长出来的变动"不立即触发**）。
- 镜头自动曝光缓变（MOG2 学习率压制）。
- 多摄像头：每摄像头一份清单，不共享 object_id 命名空间。

## D9 与 `registry-retrieval` 的边界

- 本 change 负责**清单的建立与维护**（分割 + 触发 + 状态机 + 纠正/补全检测输出）。
- `registry-retrieval` 负责**实例识别**（embedding 模型选型、向量库、登记 CLI、猫 Re-ID 与物品识别共用抽象）。
- 两者共用同一份 embedding 槽位与清单结构；`registry-retrieval` design R1/R2/R2b 的机制段已迁入本文件，R 段保留指针。
