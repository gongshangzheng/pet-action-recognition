# Design: docs-architecture —— 架构文档的结构（唯一依据）

> **v2（2026-09-17 用户裁定三条结构原则）**：
> ① **无术语表**——§0 取消，术语在**首次使用处就地说明**；
> ② **总-分结构**——**端到端设计总图放开头**，随后对总图的**每一个部分逐一讲解**；
> ③ **概念不独立成章**——原 §1 概念补充**拆散归位**到所属环节的讲解里。

> **v3（2026-09-17 用户确认管线与两处修正）**：
> ④ **环节顺序确认**：第一步是**定位与跟踪（含确保画面里有猫）**——在场判断是定位跟踪的第一步，不是独立环节；之后跟随视角（猫居中视频流）→ **背景移除（optional 组件）** → 动作表征 → 分割 → 识别 → 身份 → 出口；
> ⑤ **「时间窗口契约」不设独立小节**——它就是④动作表征的输入/输出说明（输入窗口 64 帧、λ 每 4 帧一份），并入④的讲解，总图层面不出现。

## 整体逻辑（读者动线，v3）

```
先看整张图（§1 总图：① 跟踪（含在场判断）→ ② 跟随视角 → ③ 抠像（可选）→ ④ 表征 → ⑤ 分割 → ⑥ 识别 → ⑦ 身份 → ⑧ 出口）
→ 再按图索骥，逐环节讲解（§2–§9），每个环节自带它需要的概念（总-分）
   每个环节的讲解自带它需要的概念（总-分）：
     ④ 带 符号速查 / 变长输入 / 训练两阶段 / 解耦 vs 直接监督
     ⑤ 带 能力分层 A0–A5 / 行为素→动作（TAS / 静止分隔符 / 行业模式）
     ⑧ 带 实时形态（C18）
→ 看还剩什么没定（§10 登记）→ 横切与索引（§11–§13）→ 历史 / 进度 / 出口（§14–§16）
```

**两条边界（不变）**：① 模型内部设计（聚合粒度 / 离散化 / 对称架构）不在本文——归 8 号；② 概念不进登记表——登记表只收「必须决策」项。

## 不变式（v2，写正文时必须维持）

1. **总-分**：总图永远第一；任何新环节先上总图、再在对应章讲解
2. **无术语表**：术语首次出现处就地说明（一句话即可，不展开成节）
3. **无独立概念章**：概念随所属环节走；确属跨环节的概念（如时间窗口契约）放总图章
4. 编号与物理顺序一致；跨文档引用指向真实标题（悬空 = 0）
5. 每章只放「跨模型」内容；单模型细节 → 8 号
6. 总图节点只带 I/O 契约（含时间尺度），不带实现细节（分辨率 / 编码 / 方法名）
7. 演进记录只追加；正文不放「术语修正」警示语
8. 背景移除在总图与章节标题中 MUST 标注 optional；在场判断 MUST 写为定位跟踪的第一步，不作为独立环节
9. 不设「时间窗口契约」类横切小节——环节的输入 / 输出时间尺度写在该环节讲解内
8. L1–L8 是管线层编号，与各 change design 内部 L 编号不是同一命名空间
