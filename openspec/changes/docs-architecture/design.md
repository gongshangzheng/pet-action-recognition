# Design: docs-architecture —— 架构文档的结构（唯一依据）

> **v2（2026-09-17 用户裁定三条结构原则）**：
> ① **无术语表**——§0 取消，术语在**首次使用处就地说明**；
> ② **总-分结构**——**端到端设计总图放开头**，随后对总图的**每一个部分逐一讲解**；
> ③ **概念不独立成章**——原 §1 概念补充**拆散归位**到所属环节的讲解里。

> **v3（2026-09-17 用户确认管线与两处修正）**：
> ④ **环节顺序确认**：第一步是**定位与跟踪（含确保画面里有猫）**——在场判断是定位跟踪的第一步，不是独立环节；之后跟随视角（猫居中视频流）→ **背景移除（optional 组件）** → 动作表征 → 分割 → 识别 → 身份 → 出口；
> ⑤ **「时间窗口契约」不设独立小节**——它就是④动作表征的输入/输出说明（输入窗口 64 帧、λ 每 4 帧一份），并入④的讲解，总图层面不出现。
> ⑥ **总图之后紧跟「当前待决策问题」速览章**——不展开、不分子章节，一个章下分点列完所有未决项（🔴+🟡）；**速览即登记，不再有展开版登记表章**；需要展开说明的个别决策进附录或对应 change。
> ⑦ **尾章收敛（2026-09-17）**：跨切面 / 决策索引 / 约定等杂章**并入一个附录**；进度**精简**（不写细）。
> **v8（2026-09-17 用户裁定三则，待实施）**：
> ⑨ **④⑤⑥ 在总图上合并为一个「动作理解」大框**——动作识别这一块不一定采用自研方案，可能直接用现成动作识别模型（如 VideoMAE V2）。总图只画一个完整大框（表征 · 分割 · 识别三步**通用节点**，不出现 λ 等自研专属词）；§6 按方案**直接拆成两个小节**分别讲：**自研部分**（现设计全文归此）/ **现成模型部分**（VideoMAE V2 等 + 滑窗后处理成段，即能力分层「A1 模拟 A3/A4 输出」）——不设「方案路线」元小节。
> ⑩ **行为素聚合粒度不要固定死**（2026-09-17 用户裁定）：粒度 = 每 t 帧一份，t 是 **patch 时间跨度配置参数**。当前值 t=4, p=8（≈0.27 s/份 @15fps）；文档表述「每 t 帧一份（当前 t=4）」。后续消融（C05：t ∈ {2,4,8}）可能改变该值，届时文档与配置随之更新。
> **管线表述（用户澄清，权威）**：行为素粒度 = **每 t 帧提取一份特征**（`z_j`，编码器直接输出）→ **从特征中提取 Motion Latents**（正交运动基投影，`λ_j` = 运动潜变量的系数表示，与特征一一对应）。粒度讨论以特征为准；λ 是特征的系数表示。
> ⑪ **④ 表征与 ⑤ 分割的先后顺序可互换**——登记为新决策 **C36**（🟡）：先分割 = 帧级运动能量/变化点前置（抠像后画面运动 ≈ 猫运动，零模型依赖）；先表征 = 特征序列上分段（更准，依赖表征模型）。总图大框内用**双向连线**表达顺序未定。
> **v9（2026-09-17 用户指出编号混乱）**：⑫ **决策编号体系**——保留 C-ID（跨文档引用已遍布 8 号 / papers 笔记 / 各 change design，约 35 处），但：① **§2 速览列表按号升序**（修复此前按文档出现顺序提取导致的 27/28/30/31/32/23 乱序）；② 每条**名字自解释**（不写「触发信号取哪个」这类需要上下文的简称）；③ 明确「**跳号 = 该项已决**，编号不复用」。备选方案（若用户要求取消编号）：迁移 8 个文件 ~35 处引用为名称引用，工作量中等。
> **§2 速览格式**：`- **Cxx 自解释名字**——（可选一句话补充）`；不写状态 emoji（分组标题已表状态）。
> ⑧ **元数据全部 sidecar 化**（2026-09-17 用户裁定）：演进记录 / 进度 / 附录 / 相关文档**一律不占正文章节**——每篇 md 配**同名 sidecar json**（`architecture.md` ↔ `architecture.json`），字段：`changelog` / `progress` / `appendix` / `related`。
> 渲染布局：**文章顶部按钮**展示演进记录与进度；**底部独立块**渲染相关文档与附录（功能需求登记在总 Change `docs-system`）。

## 整体逻辑（读者动线，v3）

```
先看整张图（§1 总图：① 跟踪（含在场判断）→ ② 跟随视角 → ③ 抠像（可选）→ ④ 表征 → ⑤ 分割 → ⑥ 识别 → ⑦ 身份 → ⑧ 出口）
→ 再按图索骥，逐环节讲解（§2–§9），每个环节自带它需要的概念（总-分）
   每个环节的讲解自带它需要的概念（总-分）：
     ④ 带 符号速查 / 变长输入 / 训练两阶段 / 解耦 vs 直接监督
     ⑤ 带 能力分层 A0–A5 / 行为素→动作（TAS / 静止分隔符 / 行业模式）
     ⑧ 带 实时形态（C18）
→ 速览还剩什么没定（§2 待决策速览，即登记）→ 逐环节讲解（§3–§10）
→ 附录（§11：环境隔离 / 部署拓扑 / 许可分档 / 选型状态 / 重点决策说明）→ 演进（§12，粗）→ 进度（§13，简）→ 相关文档（§14）
```

**两条边界（不变）**：① 模型内部设计（聚合粒度 / 离散化 / 对称架构）不在本文——归 8 号；② 概念不进登记表——登记表只收「必须决策」项。

## 不变式（v2，写正文时必须维持）

1. **总-分**：总图永远第一；任何新环节先上总图、再在对应章讲解
2. **无术语表**：术语首次出现处就地说明（一句话即可，不展开成节）
3. **无独立概念章**：概念随所属环节走；确属跨环节的概念（如时间窗口契约）放总图章
4. 编号与物理顺序一致；跨文档引用指向真实标题（悬空 = 0）
5. 每章只放「跨模型」内容；单模型细节 → 8 号
6. 总图节点只带 I/O 契约（含时间尺度），不带实现细节（分辨率 / 编码 / 方法名）
7. 演进记录只追加、粗粒度（日期 + 一句话 + commit），存放于同名 sidecar json 的 `changelog`，不占正文章节、不出现在章节列表；正文不放「术语修正」警示语
8. 背景移除在总图与章节标题中 MUST 标注 optional；在场判断 MUST 写为定位跟踪的第一步，不作为独立环节
9. 不设「时间窗口契约」类横切小节——环节的输入 / 输出时间尺度写在该环节讲解内
10. 「当前待决策问题」速览章（§2）**即登记**：只列 ID + 名字 + 一句话 + 落点，不展开、无子章节，已决即移出；需要展开的个别决策进附录 §11.E 或对应 change
11. **尾部零杂章**：正文到环节讲解为止；不设登记表、跨切面、决策索引、约定、演进、进度、附录、相关文档等任何独立尾章
12. 元数据（changelog / progress / appendix / related）存**同名 sidecar json**；渲染：顶部按钮（演进、进度）+ 底部块（相关文档、附录）；更新 json 不触发正文章节重排
13. 行为素聚合粒度表述为「每 t 帧一份（当前 t=4）」——**不要固定死**，t 是配置参数，消融（C05）可能改变它，文档数值随实验更新
14. 总图④⑤⑥为**通用大框**：节点不出现 λ / 动作系数等自研专属词；内部顺序未定用双向连线 + C36
15. L1–L8 是管线层编号，与各 change design 内部 L 编号不是同一命名空间
