# Design: docs-architecture —— 架构文档的结构（唯一依据）

## 整体逻辑（读者动线）

```
先给语言（§0 术语）→ 再给判断框架（§1 概念）→ 看整体怎么跑（§2 流程）
→ 看八个环节（§3 总图）→ 看还剩什么没定（§4 登记）→ 进每层细节（§5 分层）
→ 横切关注（§6）→ 查索引与约定（§7/§8）→ 追历史与进度（§9/§10）→ 出口（§11）
```

**两条边界**：① 模型内部设计（聚合粒度 / 离散化 / 对称架构）**不在本文**——归 8 号；② 概念不进登记表——登记表只收「必须决策」项。

## 不变式（写正文时必须维持）

1. 编号与物理顺序一致；跨文档引用指向真实标题（悬空 = 0）
2. 每章只放「跨模型」内容；单模型细节 → 8 号
3. 总图节点只带 I/O 契约（含时间尺度），不带实现细节（分辨率 / 编码 / 方法名）
4. 演进记录只追加；正文不放「术语修正」警示语
5. L1–L8 是管线层编号，与各 change design 内部 L 编号不是同一命名空间（§1 开头有提醒）
