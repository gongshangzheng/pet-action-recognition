# Proposal: docs-action-model-design

## Why

《动作识别模型设计》是单模型内部设计的唯一权威文档（职责见 `docs-system` 登记表）。当前结构是：

```
§1 设计目标与非目标 → §2 谱系 → §3 架构总图 → §4 逐组件设计（§4.0–§4.7 平铺）
→ §5 训练流程 → §6 评测矩阵 → §7 待决策项 → §8 许可 → §9 参考来源
```

三个问题：

1. **总图埋在中部**（§3）——读者要翻过目标与谱系才知道整体长什么样
2. **待决策在末尾**（§7）——与《系统架构》「总图在前、待决策紧随」不一致
3. **组件平铺、方案不分明**——编码器 / 骨架 / 潜空间 / 动作 / 身份 / 解码依次排开；而实际设计里有**两个候选方案**（单模型 TIV+TV / 双模型外挂身份），读者无法对照；编码器之后的**下游（行为素序列 → 动作段 → 类别）**也没有位置

## What Changes

- **框架总图提到顶上（§1）**：整体 = 两方案 + 共同下游（编码 → 行为素序列 → 分段 → 动作识别分类）
- **当前待决策上移到 §2**（与《系统架构》同位置）
- **两个方案各占一章**：§3 方案一（单模型 TIV+TV）/ §4 方案二（双模型：外挂身份 + 动作编码器）
- **共有的机制单独一章（§5）**：正交约束 / 聚合粒度 / patchify 或逐帧 2D / 变长 / 解码与重建 proxy
- **下游单独成章（§8）**：行为素序列 → 动作段 → 类别（实现落在 `video-action-segmentation` / `video-feature-latent`）
- 训练与对比实验（§6）、评测矩阵（§7）、谱系与合规（§9）、参考来源（§10）；符号速查降为附录

## Impact

- `management/docs/action-model-design.md`：**结构重排**（内容是搬移，不重写；每章补引言）
- **引用级联**：《系统架构》/ papers 笔记 / 各 change design 中指向本文档的节引用全部重映射，闭合核对后悬空必须为 0
- `docs-system` 登记表：本文档单篇 Change → `docs-action-model-design`

## 不做

- 不改设计内容（方案裁定与开口项走 `identity-action-tokenizer` change）
- 不动《系统架构》结构（它的单篇 change 是 `docs-architecture`）
