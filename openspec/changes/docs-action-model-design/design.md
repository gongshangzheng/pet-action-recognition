# Design: docs-action-model-design

> 本 design 是《动作识别模型设计》**结构**的唯一依据（与 `docs-architecture` design 之于《系统架构》同理）。
> 结构级变更：**本文件先经用户审核，之后才能动正文**。

## 目标结构

```
§1  框架总图        ← 整体：两方案 + 下游（编码 → 行为素序列 → 分段 → 动作识别分类）
§2  当前待决策
§3  方案一：单模型同时提取身份与动作（TIV + TV）
§4  方案二：双模型分别提取（外挂身份编码器 + 动作编码器）
§5  共有机制        ← 正交约束 / 聚合粒度 / 变长 / 解码与重建 proxy
§6  训练流程与对比实验
§7  评测矩阵
§8  下游：行为素序列 → 动作识别
§9  谱系与合规
§10 参考来源
附录 符号速查
```

**为什么是「两方案各一章」**：两个方案从**输入形态到训练目标都不同**（单模型 TIV/TV 分工 vs 双模型分工），共有部分只有「正交约束 / 粒度 / 重建 proxy」——所以按方案分章最省重复、也最贴近对比阅读的需要。

**为什么下游单独成章**：编码器（两方案）只产出**行为素序列**，重建只是 proxy；真正交付的是「动作段 + 类别」。这一段由《动作识别模型设计》的下游章承接（实现落在 `video-action-segmentation` / `video-feature-latent`）。

## 读者动线

```
总图（整体：编码 → 行为素 → 分段 → 识别）
  → 待决策（哪里还没定）
    → 方案一（单模型）           ┐ 两个方案并列，读者可对照
    → 方案二（双模型）           ┘
      → 共有机制（正交约束 / 粒度 / patchify / 变长 / 重建 proxy）
        → 训练与对比实验（怎么训、怎么比）
          → 评测矩阵（怎么验收）
            → 下游：行为素序列 → 动作识别（编码器的产物怎么变成动作类别）
              → 谱系与合规 / 参考来源
```

- **方案先于共有机制**：读者先看到两个候选长什么样（这是最需要决策的部分），再看它们共用的零件
- **下游放最后**：`行为素序列 → 动作段 → 类别` 是编码器的消费方，读完编码器才有意义
