## 两方案对结构的影响

身份侧现有**两个待裁定方案**（见 `identity-action-tokenizer` design T-A5d）：

| | 方案一：共享对称编码器 | 方案二：外挂编码器（DINOv2 / DINOv3 或 VAE）|
|---|---|---|
| 对 §1 总图 | 两条支路共用同一个编码器框 | 两条支路各一个编码器框（身份侧外挂）|
| 对 §3 | 视频编码器与身份**共享参数**（对称）| 视频编码器是**动作专属**底库 |
| 对 §5 | 唯一路径：register 融合 + 隔离约束 | 分两方案叙述（§5.2 共享对称 / §5.3 外挂）|

**结构原则**：§1 总图必须给**两方案通用**的骨架（编码器框标「共享 / 外挂」两种情形），使方案落定后不必重排章节；章名用「视频编码器」而非「共享基座」，因后者隐含方案一。

## 读者动线（为什么是这个顺序）

```
总图（整体是什么）
  → 待决策（哪里还没定）
    → 视频编码器（动作提取的底座）
      → 动作提取（支路一）
      → 身份提取（支路二）
        → 潜空间与解码（两条支路在这里汇合）
          → 训练流程（怎么训出来）
            → 评测矩阵（怎么验证）
              → 谱系与合规 / 参考来源（出处）
```

- 先给总图与模块地图，读者随时知道「现在读到整体里的哪一块」
- 待决策紧随总图（与 《系统架构》一致）：先知道哪些点还悬着，读细节时心里有数
- **视频编码器先行**：它是动作与身份两条支路的公共依赖，讲完再分叉可以避免重复
- 动作提取在前、身份提取在后：动作是主产品（行为素序列），身份是解耦机制的支点
- 汇合点（潜空间与解码）放在两条支路之后：读者此时才需要理解「两边怎么拼起来重建」
- 训练 / 评测在最后：属于「怎么得到、怎么验」，不是结构本身
- 谱系（借什么否什么）从原 §2 移到后段：它是出处说明，不是阅读正文的前提
