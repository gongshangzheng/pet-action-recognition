# Design: docs-action-model-design

> 本 design 是《动作识别模型设计》**结构**的唯一依据（与 `docs-architecture` design 之于《系统架构》同理）。
> 结构级变更：**本文件先经用户审核，之后才能动正文**。

## 目标结构

```
§1  框架总图        ← 整体：身份编码 + 动作编码 + 解码重建 → 行为素序列 → 分段 → 动作识别分类
§2  当前待决策
§3  身份编码        ← 两种方案并列（方案一 模型内 register/TIV · 方案二 外挂预训练编码器）
§4  动作编码        ← 正交约束 / 粒度 / patchify 或逐帧 2D / 变长
§5  解码与重建      ← 两条通路如何汇合、重建 proxy 怎么做
§6  训练流程与对比实验
§7  评测矩阵
§8  下游：行为素序列 → 动作识别
§9  谱系与合规
§10 参考来源
附录 符号速查
```

**为什么这样切**：两个待比较的方案**只在「身份从哪来」上分叉**（模型内 register/TIV 聚合 vs 外挂预训练编码器）；**动作编码与解码重建是两个方案共用的**。所以按「身份编码 / 动作编码 / 解码重建」三章切，方案对比集中在一章内，动作与解码不用写两遍。

**为什么下游单独成章**：编码器只产出**行为素序列**，重建只是 proxy；真正交付的是「动作段 + 类别」。这段由 §8 承接（实现落在 `video-action-segmentation` / `video-feature-latent`）。

## 读者动线

```
总图（整体：身份编码 + 动作编码 + 解码重建 → 行为素序列 → 分段 → 识别）
  → 待决策（哪里还没定）
    → 身份编码（两种方案并列，集中对比）
      → 动作编码（两方案共用）
        → 解码与重建（两条通路汇合）
          → 训练与对比实验
            → 评测矩阵
              → 下游：行为素序列 → 动作识别
                → 谱系与合规 / 参考来源
```

- **身份编码在前**：这是唯一分叉点，先让读者看清两个候选
- **动作编码随后**：两方案共用，读者不必重复阅读
- **解码重建第三**：身份与动作在此汇合，重建是 proxy
- **下游最后**：行为素序列的消费方，读完编码器才有意义
