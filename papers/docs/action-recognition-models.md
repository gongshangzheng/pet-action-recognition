# 现有动作识别模型综述（方法与输入细节）

> **本文定位**：**外部领域知识**——现有视频动作识别/分割模型"用了什么方法、输入输出到底是什么"。
> **不涉及本项目设计**；我们据此得出的判断见 [《系统架构》《系统架构》§1.1](../management/docs/architecture.md)（能力分层 A0–A5）与 §1.8（行为素 → 动作）。
>
> **为什么需要这篇**：反复出现的误解——
> ① "现有模型都能处理变长视频"；② "它们能识别多个动作/给时间戳"；③ 把"定长片段分类"当成缺陷。
> **第 ③ 点要特别澄清：主流做法不是错，它是**另一个任务**的正确解。** 本文把任务定义与输入契约讲清楚。

## §1 先分清任务：能力分层 A0–A5

| 层 | 名称 | 输入 → 输出 | 新增能力 | 多动作 | 时间戳 | 全程覆盖 | 在线 |
|---|---|---|---|---|---|---|---|
| **A0** | 单帧分类 | 一张图 → 1 类别 | 基础识别 | ❌ | ❌ | — | ✅ |
| **A1** | **片段分类**（主流）| 定长片段 → **1 类别** | + 时间（多帧）| ❌ | ❌ | ❌ | ❌ |
| **A2** | 多标签片段分类 | 定长片段 → 多类别 | + 一段可多动作 | ✅ | ❌ | ❌ | ❌ |
| **A3** | 时序动作检测 TAD | 长视频 → 多个变长段 + 起止秒 | + 定位 | ✅ | ✅ | ❌ | ❌ |
| **A4** | 时序动作分割 TAS | 长视频 → 逐帧标签 → 覆盖全程的段 | + 全程覆盖 | ✅ | ✅ | ✅ | ❌ |
| **A5** | 在线动作检测 OAD | 流 → 当前时刻动作 | + 因果 / 在线 | ✅ | ✅ | ✅ | ✅ |

**绝大多数叫"动作识别"的模型都在 A1**，例如 VideoMAE / UniformerV2 / SlowFast / TSM / TSN / TimeSformer / MViT / X3D。

## §2 ⭐ 输入契约（最容易被误解的部分）

### 2.1 「吃进去」永远是一个**固定长度**张量

```
输入视频（任意长度）
   ↓ 采样器（在 dataset.__getitem__ 里）
[T 帧, H, W, 3]         ← T 是超参，固定（16 / 32 / 48 / 64）
   ↓ 模型
[1 个类别]（shape: [num_classes]）
```

**A1 的"能处理变长视频"= 采样器把任意长度压成固定 T**。这是**设计意图**，不是妥协：
该任务的规定就是"给一个已裁剪好的、只含一个动作的片段，输出它的类别"。在那个任务定义下，固定 T 是正确且高效的。

### 2.2 采样器语义**必须分清**（两种做法后果完全不同）

| 采样器 | 语义 | 长视频后果 | 短视频后果 |
|---|---|---|---|
| **`SampleFrames(clip_len, frame_interval)`** | **固定时间跨度** `clip_len × frame_interval`；长视频**随机（训练）/居中（测试）取一段** | ⚠️ 只看到跨度内的帧，**其余部分不进模型** | `np.mod` **循环重复采样**补足 |
| **`UniformSampleFrames(clip_len)`** | *"divide the video into n segments of equal length and randomly sample one frame from each segment"* → **铺满整段** | 铺满全片，但每采样点间隔 = `时长/T` → **快动作被稀释** | 铺满（大量重复） |
| `DenseSampleFrames` | 滑窗密集采样（多 clip）| 覆盖更全，成本线性上升 | — |
| `UntrimmedSampleFrames` | **给 TAD/TAS 用**（名字里的 "untrimmed"）| 覆盖长视频 | — |

**由此得到一个根本矛盾**：

```
窗口覆盖长 → 时间分辨率低（快动作丢失）
窗口覆盖短 → 长动作看不全
→ 单一时间尺度无法两头兼顾
```

### 2.3 测试期的 clip / crop 协议

| 项 | 常见取值 | 含义 |
|---|---|---|
| `num_clips` | 1 / 4 / 10 | 从视频里采**多段**各自前向 → **概率平均** |
| `num_crops` | 1 / 3 | 空间多裁剪（左上/中/右上）平均 |
| 典型协议 | `10 clips × 3 crops` | 最终仍输出 **1 个标签** |

> ⚠️ **`num_clips > 1` 不是"多动作"**——是把**同一个**视频采多段做平均，输出仍只有 1 个标签。

### 2.4 其他输入细节

| 项 | 典型值 | 备注 |
|---|---|---|
| 分辨率 | 224×224（短边 resize 到 256 再 crop）| 少数用 256 / 320 |
| `frame_interval`（时间步长）| 1 / 2 / 4 | 与 T 共同决定时间跨度 |
| 帧率假设 | 固定 CFR | 变帧率需先重采样 |
| 空间增强 | RandomCrop / Flip / 色彩抖动 | 训练期 |
| 时序增强 | 随机起点、随机间隔、分段采样 | 训练期 |

**本仓实例**（`configs/pet_*.py`）：

| config | 采样器 | T | `frame_interval` |
|---|---|---|---|
| videomae / videomaev2 / aim / videomae_v1 | `SampleFrames` | 16 | **4** → 跨度 64 帧 ≈ 4.3 s @15fps |
| posec3d | `UniformSampleFrames` | 48 | 铺满整段 |
| tsn | `SampleFrames` | 1 | 1（取 3 帧，`num_clips=3`）|
| uniformerv2 | `UniformSample` | `num_frames` | — |

## §3 模型族与代表方法

| 族 | 代表 | 核心思想 |
|---|---|---|
| **2D CNN + 时序聚合** | TSN、TSM、TRN、TAM | 逐帧 2D 特征 + 时序上的 pooling / 移位 / 注意力 |
| **3D CNN** | C3D、I3D、R(2+1)D、**SlowFast**、X3D、TPN | 直接在时空体上卷积（时间维下采样）|
| **Transformer / ViT** | **TimeSformer**、**ViViT**、VideoSwin、MViTv2、**UniformerV2**、AIM | **tubelet embedding** + 时空注意力（ViViT/TimeSformer 分解时空注意力以省算力）|
| **掩码自监督预训练** | **VideoMAE**、**VideoMAEv2**、MVD、MaskFeat、BEVT | 遮绝大部分 tubelet → 重建像素；下游微调 |
| **双流 / 双路径** | Two-Stream、SlowFast | 外观流（RGB）+ 运动流（光流）或快慢两路 |
| **骨架** | ST-GCN、**PoseC3D**、CTR-GCN | 关键点热图/图 → 时空图卷积（对人/动物都适用）|

**与本项目相关的两条观察**：
1. **ViT 族的 tubelet embedding** 正是我们编码器借用的 patchify 思路（见 [《系统架构》 §5.4](../management/docs/architecture.md)）。
2. **VideoMAE 用 sin-cos 3D 位置编码**（`use_learnable_pos_emb=False`）⇒ **换 T 不必重训位置编码**（需重建模型 + 重微调），这对"多时间尺度"很有用。

## §4 训练数据与标注形态

| 数据集 | 规模 | 标注形态 | 任务 |
|---|---|---|---|
| Kinetics-400/600/700 | 数十万–百万片段 | **一片段一类别** | A1 |
| UCF101 / HMDB51 | 13k / 6.8k | 一片段一类别 | A1 |
| Something-Something V2 | 22 万 | 一片段一类别（**重运动语义**）| A1 |
| **ActivityNet / THUMOS** | 数万长视频 | **边界标注**（每段起止+类别）| A3 |
| **50Salads / GTEA / Breakfast** | 数十段长视频 | **逐帧标注** | A4 |

**关键事实**：**标注形态决定了任务范式**。Kinetics/UCF101 的"一片段一类别"逼出了 A1；要给时间戳就必须有边界/逐帧标注。

## §5 输出与评测协议

```
A1 输出：[num_classes]                       ← 全程只输出这个
评测：top-1 / top-5（视频级，单标签）
```

**A1 的输出里没有"时间"这个维度**——它不告诉你动作从第几秒到第几秒，因为它连"有几个动作"都不知道。

## §6 三个常见问题，直接回答

| 问题 | A1（主流）| A3 TAD | A4 TAS | A5 OAD |
|---|---|---|---|---|
| **输入能变长吗** | ✅ 能（但**压成定长 T 帧**）| ✅ 真变长 | ✅ 真变长 | ✅ 流式 |
| **输出是变长吗** | ❌ 永远 1 个标签 | ✅ 变长列表 | ✅ 变长段 | ✅ 逐帧 |
| **能识别多个动作吗** | ❌ 不能（假设"一片段一动作"）| ✅ | ✅ | ✅ |
| **能给时间戳吗** | ❌ **完全不能** | ✅ 主要输出 | ✅ 段的边界 | ✅ 实时时刻 |

**一个例子最直观**（10 秒视频：0-3s 舔毛 → 3-7s 走动 → 7-10s 睡觉）：

```
用 A1：你必须【自己先裁成 3 段】再分别喂进去 → 每段出 1 个标签
       它不会说「0-3s 是舔毛」——那个 0 和 3 是你裁的时候自己定的

用 A3（如 ActionFormer）：直接喂 10 秒 → [{"0-3s": grooming}, ...]
       时间戳是它给的
```

## §7 长视频 / 多动作 / 时间戳的处理路径

| 路径 | 做法 | 需要什么 |
|---|---|---|
| **滑窗 + 后处理** | 定长 T 窗口铺满长视频 → 每窗一个标签 → 后处理合并成段 | 无需新标注（但边界精度受限）|
| **TAD**（ActionFormer / TriDet / TadTR）| 直接输出变长 proposal | **边界标注** |
| **TAS 有监督**（MS-TCN / ASFormer / DiffAct）| 逐帧分类 → 段 | **逐帧标注** |
| **TAS 无监督**（CTE / TW-Hierarchical Clustering / TAEC / ASAL）| 连续嵌入 + 变化点 + 聚类，**同时得边界与段类型** | **无需标注** |
| **OAD**（LSTR / OadTR）| 因果逐帧预测 | 在线标注 |
| **音频范式迁移** | pause/VAD 预分段（"静音当标点"）+ 联合分割与词表发现（arXiv 1603.02845）| 无需标注 |

> **无监督 TAS 与本项目需求最贴**：输入长未裁剪视频 → 输出段边界 + 学到的类别，不需标注。详见 [《系统架构》 §1.5](../management/docs/architecture.md)。

## §8 与本项目的关系

| 本项目的需求 | 对应层 | 做法 |
|---|---|---|
| 只判断"这段是不是某动作" | A1 | 现成模型可直接用（但需先裁片段）|
| **从监控长视频里切出多段 + 时间戳** | **A4 级输出** | **不能直接用 A1**——需要「片段表征 + 分割/分词层」 |
| 逐窗标签 + 时序后处理 | 滑窗路径 | 无需标注，但边界精度靠后处理 |
| 无监督发现动作类型 | 无监督 TAS | 无需标注，成熟且直接可借鉴 |

**核心结论**：本项目要的是 **A4 级输出**，而主流模型停在 **A1**——两者不是"谁更好"，是**任务不同**。
主流的"定长片段分类"是 A1 的正确解；我们额外需要的是**分割/分词层**（见 [《系统架构》 §1.5](../management/docs/architecture.md)、change `video-action-segmentation`）。
