# 身份-动作 Tokenizer（专篇）

> **一句话**：把一段视频拆成两组 token——"这是哪只猫"（身份，全段时间共享）+ "这帧在动什么"（动作，每帧一份）。能重建原视频说明解耦成立。
>
> 这是项目里最复杂、也是最有野心的结构。围绕对比学习目标设计。

## §1 问题与定位

### §1.1 为什么需要身份-动作解耦

理想的宠物视频表征应该满足两个性质：

1. **可控**：给定"猫 A + 动作 X"能生成对应的视频片段
2. **可分解**：能单独抽出"身份"用于 Re-ID、能单独抽出"动作"用于行为识别

现有动作识别模型（TSN/SlowOnly/VideoMAE 等）只能输出"这是什么动作"的类别，**没办法**回答"这只猫是谁"——身份和动作被混在一起。

**FLOAT×TiTok 杂交架构**就是把"身份"和"动作"在表征层面分开：身份 tokens 是一组跨时间共享的小集合（K_id=32 个），动作 latent 是每帧一份（z_t 32d），解码器把两者组合起来重建视频。如果重建质量够好，说明这种分解是合理的。

### §1.2 为什么先在 UCF101 上验证

猫语料太少（34 段白天视频 = 14.7 分钟 + 3k clips），训不动一个视频生成模型。**解法**：

- **阶段 A 在 UCF101 上**（NAS，13320 段 101 类，量级大两个数量级）验证架构可行性
- **阶段 B 再迁移到猫语料**（mammal_v0 + cats v1 + followcam），规模小但贴近实际

UCF101 上的"身份"是"这是哪个人"——同一段视频里同一人的各帧应该共享身份 tokens，不同人应该区分。这与猫 Re-ID 完全同构。

## §2 架构设计（用户定义 2026-09-16，FLOAT×TiTok 杂交）

### §2.1 三要点

```
视频帧序列 x_1, x_2, ..., x_T
        ↓
   编码器（待定：ViT/VideoMAE/V-JEPA 2）
        ↓
   拆分为两组 token：
   ├── 身份 tokens e_id（K_id=32 个，整段时间共享）
   └── 每帧动作 latent z_t（32 维，每帧一个）
        ↓
   轻量解码器 f(e_id, z_t) → 重建视频
```

### §2.2 三要点逐条解释

1. **身份 tokens e_id（K_id=32 个，跨时间共享）**
   - "几十个跨时间共享的身份 tokens"——比如 32 个 32 维向量，整段视频共用同一组
   - **对比学习视角**：这就是把"同猫跨时间"的 positive invariance **直接写进模型结构里**——同一只猫的任何一帧，e_id 都一样；不同猫的 e_id 必须互不相同（在损失函数里强制）
   - 借鉴 TiTok：视觉 tokenizer 用几十个 token 表达一张图，本项目把这种思路借到"用几十个 token 表达一只猫的身份"
2. **每帧动作 latent z_t（32 维）**
   - "这一帧在动什么"——每帧单独算一个
   - 与身份正交：动作换身份不换时（如 A 猫吃饭 / A 猫跑），z_t 变化、e_id 不变
3. **解码器 f(e_id, z_t) → 重建视频**
   - "轻量解码器用（身份 tokens + 逐帧动作 latents）重建原始视频"
   - 重建成立 → 身份与动作的分解在数学上自洽
   - 借鉴 FLOAT：FLOAT 是身份-动作解耦的视频生成方法，本项目借其思想做表征学习而非纯生成

### §2.3 为什么 K_id=32、z_t=32d

K_id 大小（8 / 16 / 32）做缩放实验，阶段 A 验收时定。直觉：猫的视觉差异远小于人脸（猫种类多但个体外观变化相对小），K_id=32 应该够；过大会过拟合。z_t 32d 类似。

## §3 两阶段路线

### §3.1 阶段 A：UCF101 验证（架构可行性）

**目标**：证明"FLOAT×TiTok 杂交 + 解码器重建"这套架构能跑通、解耦成立。

- 数据：NAS UCF101 → 窗口清单（16 帧/窗）+ 缓存 patch tokens（冻结骨干，一次性 ~半天）
- 训练目标：重建损失 + 动作 CE（101 类弱监督）+ 类别损失
- 实验组：token 数缩放（8 / 16 / 32）
- **中期检查点**：
  - z_t 线性探针 top1@101 类——z_t 应该足够好用作动作分类
  - 身份 dropout/交换消融——把身份 tokens drop 一些、或换成另一段的，看重建是否崩坏
- **验收**：架构可行性判定通过 → 进入阶段 B；否则改架构

**对比学习视角**：阶段 A 没有显式 InfoNCE（用 101 类监督代替），但**身份 tokens 跨时间共享**这一步本身就是在把 positive invariance 写进结构。

### §3.2 阶段 B：猫语料迁移（落地）

**目标**：把在 UCF101 上验证过的架构搬到猫语料上，做我们的真目标。

- 数据：mammal_v0 + cats v1 + followcam 视频
- 训练目标：重建损失 + 动作 CE（5 类）+ **track 级 InfoNCE 对比损失**（核心新增）
- **track 级 InfoNCE**：
  - **Positive pair** = 同一只猫的两段视频帧 / 同一只猫相邻帧
  - **Negative pair** = 不同猫的同帧 / 不同猫跨帧
  - 优化"正对相似度最大化、负对相似度最小化"——**对比学习视角落进损失函数**
  - 温度/负样本数等超参需要调
- **跨猫交换重建**（消融）：把 A 猫的帧用 B 猫的 e_id 重建，看是否被识别为非 A——若重建出来明显是 B 的身份，说明身份 tokens 真起作用了

### §3.3 阶段 B 的对比学习设计

| 项 | 设计 |
|---|---|
| 正样本构造 | 同一只猫的相邻 N 帧 + 同一只猫的远距离 N 帧（采样自同一 track_id） |
| 负样本构造 | 同 batch 内所有"非此猫"的 e_id（in-batch negatives） |
| 损失函数 | InfoNCE（NT-Xent）——最大化正对相似度、最小化负对相似度 |
| 温度 τ | 待调（典型值 0.07–0.1） |
| 嵌入空间 | 身份 tokens e_id 经 projection head 后做相似度计算（与 SimCLR 一致） |

## §4 评测矩阵（design T-A4 全表）

围绕"对比学习视角下的同/异身份分辨力"设计五个评测维度：

| 维度 | 指标 | 意义 |
|---|---|---|
| 重建质量 | LPIPS / PSNR / SSIM | 解码器能否还原原视频（基础能力） |
| **动作探针**（5 类） | 线性探针 top1 | z_t 是否足够用作行为分类（动作维度好） |
| **身份检索** | 同猫 vs 不同猫的检索精度（rank-1/5） | e_id 是否能区分个体（身份维度好） |
| **身份泄漏** | 动作探针是否被身份信号污染 | e_id 与 z_t 是否真的解耦（关键） |
| **交换重建** | 跨身份重建是否被识别为非 A | e_id 真起作用 vs 仅靠 z_t 重建 |

**验收硬指标**：
- 重建：PSNR > 25 dB（可接受画质）
- 动作探针：top1 > 80%（5 类上）
- 身份检索：rank-1 > 90%
- 身份泄漏：z_t 探针在不同猫上准确率差距 < 5%（说明没被身份污染）
