# 研究结论与踩坑

> **怎么看**：§1 关键点提取五大问题（来自 `keypoint-extraction-pitfalls.md` 全文）；§2 K400 经验共性；§3 复活条件分析；§4 用户裁定时间线（决策历史）；§5 教训提炼。

## §1 关键点提取五大问题

> 全文来自原 `keypoint-extraction-pitfalls.md`，整合到本节。原文件在本 change 中被吸收删除。

### §1.1 检测器是整个管线的第一瓶颈

关键点模型的精度上限由**前置检测器**决定——检测框位置偏差 5px，关键点也会跟着偏。要做好关键点，得先把检测器调到准确。

本项目当前检测器是 **GroundingDINO**（详 [3 号《模型》§4](../wiki/models)），34 段白天视频检出率 0.939——已经够用，但仍有提升空间。

### §1.2 动物身体截断（未完整入画）即崩溃

人体姿态模型对人体截断有较强鲁棒性（训练时见过大量 partial body）。**动物姿态模型对截断几乎崩溃**——四肢只要缺一个，整只动物的关键点估计就乱了。

这在监控视频里几乎必然发生（猫会走出画面、被家具遮一半）。

### §1.3 关键点语义体系不统一，结果无法互通

不同数据集/模型用不同的关键点定义：

- AP-10K：17 个关键点
- SuperAnimal：20+
- HRNet（不同 checkpoint）：数量不同

不同模型的输出无法直接对齐——必须做关键点映射（`scripts/keypoint_mapping_quadruped.json`），这是个持续维护成本。

### §1.4 多动物与身份切换无解

即使单人关键点做得完美，多动物场景（家里两只猫同时出现）下：

- 检测框可能互换（A 猫和 B 猫的框变了）
- 关键点也跟着换——同一个 id 下会出现"瞬间跳到另一只"

**这是身份识别问题的副作用**——没解决 Re-ID 之前，关键点无法稳定追踪。

### §1.5 零样本输出不能当 GT，也不能当弱监督

直觉上"模型在没见过的动物上也能跑出关键点"似乎可以当伪标签（pseudo-GT）训练下游任务。但实测：

- **置信度太低**：MC 跟随视角 mean_conf 0.367 / conf>0.5 帧仅 0.2%（2026-09-15）
- **四肢点几乎不可用**：<0.25 置信度
- **抖动不可叠加**：瞬时偏移让动作信号被噪声淹没

**结论**：零样本关键点不能当 GT，也不能当弱监督。详见 [3 号《模型》§3.1](../wiki/models)。

## §2 K400 经验共性：标注体系不对齐

Kinetics-400 上的教训与猫语料惊人相似：

- K400 有 400 类，**部分类之间边界模糊**（如"clapping hands" 与 "applauding"）
- 不同标注员对同一动作会标不同类
- 模型 top5 准确率（92.5%）远高于 top1（77%）——说明类间混淆严重

**类比到猫语料**：cats v1 的"activity 伞类"问题就是同一性质——人也不知道猫到底分几类活动（详 [2 号《数据集全景》§2.2](../wiki/datasets)）。

**应对**：与其让人定类别，不如让数据自己聚——这是 `video-feature-latent` 选 UMAP+HDBSCAN 无监督发现的核心理由。

## §3 复活条件分析：t13 检测/跟踪落地之后（2026-08-15）

> 关键点能否"复活"（重回管线）？取决于前置条件。

| 条件 | 当前状态 | 复活需要 |
|---|---|---|
| 检测器稳定 | ✅ GroundingDINO 检出率 0.939 | — |
| 单猫白天场景稳定 | ✅ 抽样+插值+运动校正 v5 | — |
| 多猫身份切换 | ❌ tracker-selection 0/4 延后 | 多猫数据 + 跟踪器选型完成 |
| 高质量关键点估计 | ❌ 0.367 mean_conf 不足 | 或换 backbone（HRNet-pretrained on mammals / SuperAnimal 优化版） / 或加专用微调 |

**结论**：短期内关键点不进管线；多猫场景出现时再评估。

### §4.1 运动校正 v5 参数详解（重要数据）

来源：`batch-followcam-extraction` 1.2 用户验收纪要 + `scripts/pet_compare_followcam3.py`

```
参数名        | 值        | 含义
-------------|-----------|----------------------------------
off-alpha    | 0.6       | 偏移更新步长（越大跟得越紧）
off-max-v    | 5% 帧宽   | 速度上限（防止校正发散）
覆盖门槛     | 0.2       | 与新检测 IoU 超过此值才接受校正
```

**三轮迭代历史**：v1（缩框 bug）→ v2（只扩不缩+覆盖门槛）→ v3（EMA 相机路径，滞后否决）→ v4（锚点精确+半余弦窗偏移）→ v5（参数定稿）

**验收实测**：34 段批处理 0.939 检出率，校正触发 12.0%，偏移 max 108px，锚点帧像素级一致。三联对比视频（原片/interp-only/motion-corrected）脚本：`scripts/pet_compare_followcam3.py`。

## §5 教训提炼

| 教训 | 来自 | 应用 |
|---|---|---|
| **零样本视觉输出别当真** | 关键点 0.367 mean_conf | 在 mmaction2 推理结果上别盲目信任 top1，看 top5 |
| **人定的活动类目不可靠** | cats v1 activity 伞类 50% | 用无监督发现行为，不预定义 |
| **全帧率未必比抽样好** | ByteTrack 否决 | 评估算法前先想"够用即可" |
| **门控治标不治本** | GatedTracker 否决 / 沙发漂移走渲染层 | 算法问题优先解在源头（数据/渲染），少叠补丁层 |
| **计划体例容易过期** | live 两篇 plan 已落地 | 文档只保留"决策与落地"，丢弃"阶段拆分/执行顺序" |
| **重要信息要可追溯到证据** | k400 指标 / 34 段三率 / 0.367 / 4/1859 等 | D6 四要素（日期/来源/数字/证据路径）——任何重要结论必带证据路径 |
