## 背景与目标

闭集行为识别的输入必须是长度可比的片段，而人工标注的区间长度从 4 秒到 110 秒不等。模型的固定输入是 16 帧、间隔 4，只覆盖区间正中约 4 秒——长区间因此只贡献一个样本，短区间则凑不满窗口。数据准备这一层的任务，就是把这些区间整理成等长片段，同时让每一步损失都说得清。

这条线走过三代，每代解决上一代暴露的问题：

1. **4 秒切段数据集（2026-09）**：79 段素材按 2 秒步长均匀切成 4 秒片段，五类。它让训练、评测、推理第一次跑通，但素材只覆盖单机位单日、总时长有限，没法承接后来的 2,573 段带标注视频。
2. **区间索引（2026-10）**：改用人工标注的动作区间，按拍摄日隔离划分，七类。区间是「动作发生过」的证据，比均匀切段更贴近任务；但沿用区间原长，且检测只覆盖了「过滤后索引」引用的 2,144 段视频。
3. **区间切片（2026-11）**：补齐 429 段未检测视频、修正多宠物计数、把区间切成 60 帧片段，十类。本文主体是这一代。

术语：**锚点**是抽样检测帧（`frame % 5 == 0`）；**多宠物**指同一锚点上 `cat_count + dog_count ≥ 2`；**外延**指把不足 60 帧的短区间向两侧借帧到 60 帧。

## 当前问题

按区间切片要回答三件事：能救回多少区间（可用率）；每一次丢弃能否归因（损失可追溯）；划分会不会把同一段视频的片段分到不同 split（隔离）。

旧数据集的基线是 207 个可用区间 / 2,710 个标注区间（7.6%）。这个数字低得可疑，但低的原因当时并不清楚——是语料里真的多宠物太多，还是测量本身有问题？在把可用率抬起来之前，必须先分清这两者。

## 实验设计

处理顺序固定，每一步都计数并写入逐区间清单：

1. 剔除非闭集类别（7 类之外）；
2. 剔除短于 1 秒的区间；
3. 按锚点宠物数判定多宠物：先按面积取主框、丢弃 IoU ≥ 0.8 的重复框、丢弃面积比 < 0.15 或 > 3 的退化框，再要求覆盖率 ≥ 0.5 且连续 ≥ 3 个锚点；
4. 按事件日期分配 split（沿用既有 day map）；
5. 同一视频内的重叠按「具体动作 > activity > prolonged_stationary」仲裁，被压制者记 `suppressed_by`；
6. 短区间以自身为中心向两侧外延到 60 帧，不越相邻区间与视频边界；
7. 分层随机切片：区间按可容纳片段数切成 k 段（k = min(4, 可容纳数)），每段内随机取起点，seed=0；
8. activity 片段数封顶为第二大类的 3 倍。

三条规定动作是判据，不是修辞：逐区间清单的原因计数之和必须等于 3,927；同一种子重跑 `clips.jsonl` 哈希一致；任何源视频的片段不跨 split。

## 结果与分析

**可用率从 7.6% 升到 85.0%，其中一半靠补检测、一半靠纠正测量。** 补检测把 429 段从未检测过的视频纳入（rc=0，4,532 秒），让此前因「无可靠检测」被整段丢弃的区间重新可判。更大的跃升来自多宠物计数的修正：967 条被判多宠物的区间里有大量是同一只猫被检出两个框（抽查 20 条里 5 条两框 IoU = 1.00、面积比 1.00）。改为先做几何规整再计数后，多宠物降到 482 条，回收 485 个区间、1,269 个片段。

这个修正并非凭空而来：先做多宠物稳定性实测（3,109 个区间里覆盖率 ≥ 0.3 的为 0、最长连续 ≥2 只的为 0，605 条旧判「多猫」全是孤立单帧），才敢判定这批计数里混着重复框。方法上的教训是：**同一个判据在两种实现下给出相反的结论时，先怀疑测量，不要先改结论。**

**外延失败的数字变了三次，每次都是修掉上一版的测量错误。** 18 → 106 → 143：第一次是 `sample_id` 取 `annotation_id`，同一标注任务的多行共用 id，导致相邻区间边界互相覆盖（改成「视频:起帧-止帧:类别」后真实值暴露为 106）；第二次是可用区间变多、邻接冲突随之增加。这个数只有和当时的规则一起读才有意义，单独引用会误导。

**活动类占比是这套数据的主要失衡。** activity 片段 3,784 个、占 50.1%，未触发 3 倍上限（第二大类比它小得多）。实测 activity 的性质支持这一处理：2,352 个 activity 区间时长中位 7.2 秒，47% 的带标注视频整段只标 activity，按帧计它独占约 89% 的活动帧——它是「猫在活动」的粗粒度状态，不是具体动作，若不封顶会淹没其他类。

**稀有类不可训练。** seizure 0 片段、fall 2、gnawing 17。seizure 的唯一区间被判多宠物整段排除；这只区间我先后给出过两个互相矛盾的解释（「看到两只猫」→「第二框是毛绒玩具」→ 用户复核确认**确实是两只空间分离的真猫**），正确结论是排除理由成立、SORT 落地后可回收。这个反复本身是证据：检测误判不能靠一次目视定案。

**隔离与可复现已验证。** 2,150 个源视频的片段全部落在单一 split，跨 split 视频 0 个；可用区间 3,339 × 4 = 13,356 是片段上限，实际产出 7,554，差额来自区间长度不足与 activity 封顶。同一 seed 重跑清单哈希一致。

## 结论与下一步

- 区间可用率 7.6% → 85.0%（3,339/3,927），片段 207 → 7,554（训练 4,506），划分隔离与确定性均有核对。
- 已确认的是数据可用性与可追溯性；未确认的是标注质量、类间平衡是否足够支撑十类训练——那是训练报告的问题，不是本报告的结论。
- 482 条多宠物排除仍是上限估计：规整规则只能压「多报」，补不了「漏检第二只动物」。
- 下一步：个体跟踪落地后回收多宠物区间（预计可再加约 480 个区间）；稀有类（seizure/fall/gnawing）需补数据，当前模型侧无解。
