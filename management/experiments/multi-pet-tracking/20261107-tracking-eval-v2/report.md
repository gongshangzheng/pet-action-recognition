## 背景与目标

多宠物视频占已检测区间 18%（565 个稳定多宠物区间，另 1,541 个「1 猫+1 狗」）。现有预处理脚本 scripts/pet_detect_track.py 只取置信度最高的框再插值平滑：两只动物同框时最高分框会在两者之间静默跳变，插值把跳变铺成一条平滑但错误的路径——不报错，只产出垃圾。结果多宠物区间只能整段排除。

本轮目标是给每只动物建立稳定的、可核对的轨迹。跟踪只消费既有检测缓存，不解码视频帧，因此技术不确定性不在算力，而在观测密度：锚点间隔 stride=5，15 fps 下约 3 Hz，帧间 333 ms。

术语：锚点 = 抽样检测帧（frame % sample_stride == 0）；轨迹碎片 = 同一只动物的轨迹因漏检断成多段；身份交换 = 两条轨迹中途互换了各自的动物；嵌套重复 = 同一只动物在同一帧被检出两个框，一紧一松。

## 当前问题

这条线一直搁置，原因很具体：管线里没有任何关联逻辑，两动物同框时的跳变不报错、只产出错误数据。更麻烦的是标注没有身份字段——即使轨迹做对了，也无法确定标注指的是哪只动物。

本轮要回答：① 在 stride=5 的稀疏锚点和「框不完美」的检测质量下，SORT 系跟踪能否给出可用轨迹；② OC-SORT 相对原版 SORT 是否有增益；③ 物种抖动、幻影轨迹各自该由哪一层修。

本轮不回答：动作标注该归属哪只动物；检测模型或阈值要不要改；以及任何训练侧效果。

## 实验设计

检测侧完全固定，用既有 GroundingDINO 缓存（box_threshold 0.3、猫狗双 prompt），不重跑检测、不改阈值。

四臂递进，每臂只改一个变量：A 硬分实例（猫/狗各一个 tracker，OC-SORT use_byte）→ B 单流（所有检测进一个流，物种改为轨迹元数据多数投票）→ C 单流 + IoS 嵌套去重（交集/较小框面积 ≥0.8 判重，跨物种也去重，每次删除记日志）→ D 在 C 基础上把锚点加密到 stride=2。

评估集从既有缓存按判据抽：coverage≥0.5 且连续锚点 ≥3，按视频去重后种子 20261107 随机取 10 段。指标在跑之前写死：碎片 ≤2 段/个体、交换 ≤2 次/视频、3 段抽样轨迹数与人工个体数一致。

指标能力边界必须写明：标注没有身份 GT，「交换」只能用代理信号（同物种两条轨迹在共享帧上 IoU>0.5 的次数），真值靠人工核对；碎片按时间近邻（gap≤24 锚点）把同物种轨迹聚成个体再数段数。

## 结果与分析

最强的一条结论是「OC-SORT 与关断版 SORT 逐帧等价」：10 段上帧级框差异为 0，轨迹结构完全相同，唯一差异是记录参数的字段。这不是实现没生效（参数确实不同、输出哈希确实不同），而是说明在这批 3 Hz 锚点上匹配歧义小到不足以让方向代价或低分二次关联改变任何一次分配。use_byte 不触发还有结构性原因：缓存检测置信度下限就是 0.30，不存在低分池可捞。

四臂指标：碎片/个体最大 A=4 → B=3 → C=3 → D=4（阈值 2，均不达标）；一致性中位 0.8182 → 0.8889 → 1.0000 → 1.0000；交换代理信号 A=0 → B=16 → C=0 → D=0。

人工核对给出三个决定性事实。第一，最差段的三条「狗」轨迹是狗粮包装上印刷的狗，而画面里那只真猫完全没被检出——pet_count 的噪声是误检与漏检叠加。第二，中位段那只猫进狭窄通道时有 2 个锚点被判成 dog，硬分实例下无法并回猫流，只能另起 id10000，人眼可见的硬断裂；改单流后假狗轨迹消失，猫的轨迹从 36 个锚点增到 40。第三，最好段活动的猫在前 6 个锚点后就没有框了——我起初判为「跟踪丢失」，用户复核后确认那只猫是真的离开了画面，属正确行为。这条更正很关键：本 change 因此没有任何「漏检后无法重生」的实证，ReID 的原始动机随之消失。

B 臂交换信号从 0 跳到 16 曾被当作退化，逐条追查后确认全部集中在一段、来自两条被正确标记为「物种存疑」的垃圾轨迹（一致性 0.5/0.55）——硬分实例下它们分处两流永不比较，单流后才相遇暴露。指标本身没错，但读它必须叠加 species_flagged 一起看。

C 臂之后仍有碎片，于是做了两件事。一是加密锚点（D 臂）：成本 2.5 倍（267 秒），碎片反而 3→4，一段上凭空多出两个估计个体——说明剩余碎片不来自观测密度，而来自低置信静态误检的闪烁，加密只是增加了它出现/消失的次数。二是在 3.7 试做轨迹级「疑似误检」标记，用人眼确认的 8 条轨迹做判别力检验，四个候选信号全部失效：假目标置信度 0.616 高于真猫的 0.533，物种一致性 0.93 与真猫的 0.93 完全相同，假杂物位移 2 px 与睡觉真猫的 7 px 无法区分，面积上误检与远景真猫重叠。这不是调参问题，是信息不足——材料已移交 presence-gate-model，由它提供框级活体判定。

框细化（4.1）只做到探针：5 个手挑用例 × 2 个模型，输出原框与精修框的并排对比图。三条结论。第一，**用外接框做精修收益很小**：原框与 mask 外接框的 IoU 普遍 0.88–0.97，尺寸只差 1–3%（真猫 262×224 → 259×223），说明 GroundingDINO 的框本来就和 SAM 认定的边界接近，只有明显松的框才收得动。第二，还要区分「掩码」与「掩码外接框」：真猫案例里掩码紧贴身体轮廓，但尾巴伸到框角、撑满外接框，导致 bbox 几乎不变——所以用外接框替代原框收益小，掩码本身的价值在别处（如抠背景）。第三，**SAM 不能过滤误检**：狗粮袋面印刷的金毛，框 180×212 → 精修 178×210 几乎不动，mask 分数 0.977 反而高于真猫的 0.964——SAM 无类别语义，把印刷图案当成一个完美物体确认了。第四，**MobileSAM 不可用于精修**：夜间松框上给出 126×79、IoU 0.095、分数 0.461 的失败结果（SAM2 同例 464×196 / 0.877）。

这里有一处必须记录的更正：首版探针我把「狗粮包装误检」的用例框取成了 id3 [1290,543,1552,767]，那实际是**趴在狗粮袋上的真猫**；真正的误检是袋面印刷金毛（id1 f0 180×212、id4 f80 189×211）。用户指出后逐轨迹裁图核对确认，已换用正确框重跑，并同步更正两份 change 的 evidence。

最后一步是用户裁定的「不能稳定存在的一律放弃」：轨迹需满足锚点 ≥5 且跨度内覆盖率 ≥60%，否则丢弃不合并。实测丢弃 3 条，全部集中在狗粮袋那段——两条静止的印刷/杂物轨迹，以及一条覆盖率只有 54% 的真猫（用户裁定该猫确实检测不到、可以丢）。旁证支持这个判据：被丢的三条中心坐标首末几乎不变，而真实离场的那只猫是向画面右边缘移动、边距 2px、覆盖率 100%，被正确保留。加上这一步后碎片/个体最大从 3 降到 **2，达到事先阈值**；但一致性最小值从 0.6286 掉到 0.2571——因为丢弃后部分锚点的活跃轨迹数少于检测宠物数，这是精度优先的必然代价，读指标时必须与「稳定过滤已启用」一起看。

## 结论与下一步

最终结论：**当前数据条件下不适用于训练裁剪，不接入**。四臂对照把问题彻底分了层，也让后续不该在哪里继续折腾变得明确。

关联层的问题确实可修，而且已经修掉了：物种抖动导致的身份断裂，由「单流 + 物种作元数据」消除——中位段那条假狗轨迹不再生成，猫的轨迹从 36 个锚点增到 40；嵌套重复框由 IoS 去重消除，中位段一闪而过的 id2 消失，交换代理信号从 16 归零。锚点一致性中位从 0.8182 提到 **1.0000**。

但两个"加资源就能解决"的假设都被否掉了。加密锚点：成本 2.5 倍（267 秒），碎片反而从 3 变成 4，一段上凭空多出两个估计个体。换更强关联算法：OC-SORT 与关断全部 OC 机制的 SORT 基线逐帧等价，10 段 0 帧差异——匹配歧义小到没有发挥空间。ReID 也因此失去原始动机（一个被单流解决，一个被用户复核推翻——那只猫是真的离开了画面），判定不启用，重启条件已写死。

剩下的失败不在跟踪层：碎片/个体仍是 3 > 阈值 2；持久误检（狗粮袋面印刷的金毛）与框不贴合都属于检测侧。我们试过在轨迹层做误检标记，用人眼确认的 8 条轨迹做判别力检验，四个信号全部失效，而且更正后更糟——那只真猫的置信度 0.331，比三条误检的 0.502/0.536/0.616 都低，任何阈值组合都会先杀掉真猫。框细化同样不成立：把掩码外接框当收紧手段，收益只有 1–3%（真猫 262×224 → 259×223），因为尾巴这类细长部位会撑满外接框。

**明确移交的两条**：误检抑制交给 presence-gate-model 做框级活体判定（需要先补非活物负样本，现有 11 条不够）；掩码级观测（身体面积占比等）交给观测指标线——框面积相对掩码高估 1.47–2.67 倍，这个指标只能用掩码算。

**本报告不能宣称的**：不能宣称多宠物轨迹可用于训练裁剪；不能宣称框细化提高裁剪质量；不能把聚类估计的个体数当作真实动物数。本轮未产出区间级轨迹结论，也未接入任何裁剪或训练侧切换。
